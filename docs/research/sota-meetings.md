## Meetings: recording, transcription, diarization and notes

### Where we are

Verified in code (docs/meetings.md is accurate; docs/research/roadmap.md L16 "meeting recap" has shipped; `native_audio.py` does not exist, capture is ffmpeg/avfoundation only via `audiocap.py`).

- **Capture** (`meeting_recorder.py`): `ChannelCapture` = one long-lived ffmpeg per channel (`mic`, `output`) using the segment muxer, closes a 16 kHz mono wav every `segmentSeconds` (20). `RecordingSession._segment` stamps `t_start = seq*segment_seconds` (recording clock) and queues it; `TranscribeWorker._transcribe_one` validates (`audiocap.validate_wav`, ffprobe + remux), calls `stt.transcribe`, retries with backoff, deletes the wav unless `keepAudio` or error. Fixed-length cuts: segments are sliced at arbitrary 20 s boundaries with no VAD, so words are cut mid-utterance (mitigated only by a 180-char `TAIL_CHARS` whisper `prompt`).
- **STT** (`stt.py`): `proxy` (POST `/v1/audio/transcriptions`, `verbose_json`, prompt tail) or `local` (`whisper-cli -otxt -nt -l auto`, **returns empty `detail`: no timestamps, no segments, no VAD flags**). Every non-paused segment is sent, including pure silence. There is no silence gate, no `no_speech_prob`/`avg_logprob`/`compression_ratio` filtering, no hallucination-phrase filter (grep for silence/vad/hallucin in these modules finds only the selftest's `silence_wav`). Whisper on silent or noisy-room mic segments is known to emit "Thank you." / "Thanks for watching" / repeated loops, which then get rolled into `transcript`, FTS and the enhance prompt, and each one costs a billed call.
- **Data model** (`meetings.py` SCHEMA): `meetings` (notes / enhanced / transcript / summary / sources / audio_dir / keep_audio / conversation_id ...), `meeting_segments` (channel mic|output|import, seq, t_start/t_end, text, `detail` JSON of verbose_json, **`speaker` column exists and is always empty**, state, attempts, wav_path), `meeting_revisions` (proposal/accept, mirrors doc_revisions), `meeting_action_items`, `meetings_fts`. Post-release columns go through `ADDED_COLUMNS` (empty today) applied in `Meetings.__init__`.
- **Transcript**: `Meetings.build_transcript` merges segments by `t_start`, one line per run on the same channel, labels from `CHANNEL_LABELS` (`[you]` / `[them]`). A four-person call is `[them]` throughout. `meeting_notes.ENHANCE_PROMPT` explicitly forbids naming speakers.
- **Enhance** (`meeting_notes.enhance`): one LLM call, user notes as outline, 6 templates, JSON out (markdown, decisions, action_items, topics, headline), head+tail cap at 48k chars, degraded mechanical fallback, accept/reject revision (never overwrites user edits). This already matches Granola/Hyprnote's core UX.
- **UI**: `MeetingsView.tsx` / `MeetingRecorderBar.tsx` poll `/meetings/{id}/segments?since=`; `lib/transcript.ts speakerLabel` already honours a non-empty `speaker`. The per-meeting SSE ships idle.
- **Weak spots**: (1) no VAD/silence/hallucination gate; (2) local whisper loses timestamps; (3) no diarization, no speaker naming; (4) no audio-file import (docs/meetings.md: "later slice"; the `import` channel is already in the schema) so a machine with no loopback device or an existing recording has no path in; (5) literal FTS only; (6) no live streaming partials (20 s lag by design); (7) no ASR custom vocabulary (attendee names / calendar title are not fed to whisper `prompt`); (8) macOS-only capture, loopback is a manual BlackHole setup.

### What the best open-source systems do

- **Silero VAD** ([snakers4/silero-vad](https://github.com/snakers4/silero-vad)): ~2 MB model, <1 ms per 30+ ms chunk on one CPU thread, 8/16 kHz, ONNX available, `VADIterator` for streaming. Tunables: `threshold` (default 0.5), `min_speech_duration_ms` (250), `min_silence_duration_ms` (100), `speech_pad_ms` (30). Used as the front gate by faster-whisper, whisper.cpp and WhisperX.
- **whisper.cpp** ([ggml-org/whisper.cpp](https://github.com/ggml-org/whisper.cpp)): built-in `--vad` with `-vm ggml-silero-v6.2.0.bin` (`models/download-vad-model.sh`); flags `--vad-threshold`, `--vad-min-speech-duration-ms`, `--vad-min-silence-duration-ms`, `--vad-max-speech-duration-s`, `--vad-speech-pad-ms`, `--vad-samples-overlap`. Also `-oj`/`-ojf` JSON output with segment (and word) offsets, `-tdrz` tinydiarize speaker-turn markers (needs a tdrz model), and `whisper-stream` (`--step`/`--length` sliding window) for live partials. Our `_local` uses none of this.
- **faster-whisper** ([SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper), [transcribe.py](https://raw.githubusercontent.com/SYSTRAN/faster-whisper/master/faster_whisper/transcribe.py)): `vad_filter` with Silero options; hallucination guards `no_speech_threshold=0.6`, `log_prob_threshold=-1.0`, `compression_ratio_threshold=2.4`, `hallucination_silence_threshold` (skips segments around long silences when word timestamps on); `condition_on_previous_text` defaults True but `BatchedInferencePipeline` forces it False plus `prompt_reset_on_temperature=0.5` because carried context is the main cause of repetition loops; beam 5; `BatchedInferencePipeline` batches VAD chunks. The three thresholds are exactly the fields a `verbose_json` response already gives us per segment (`no_speech_prob`, `avg_logprob`, `compression_ratio`), so the same filter can be applied to the proxy path with no new dependency.
- **WhisperX** ([m-bain/whisperX](https://github.com/m-bain/whisperX)): VAD pre-segmentation then "cut and merge" chunks to ~30 s so cuts land in silence, batched faster-whisper, wav2vec2 forced alignment for word timestamps, pyannote diarization, then `assign_word_speakers`: each word/segment gets the speaker whose diarization turn overlaps it most (max-overlap, fall back to nearest turn). Claimed 70x realtime; VAD preprocessing "reduces hallucination".
- **pyannote / sherpa-onnx diarization** ([k2-fsa sherpa-onnx](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/index.html)): two-stage: a segmentation model (`sherpa-onnx-pyannote-segmentation-3-0` or `reverb-diarization-v1`, small ONNX) finds speech/overlap regions, an embedding extractor (3D-Speaker or NeMo ONNX) embeds each, then clustering with `threshold` or fixed `num_clusters` and `min_duration_on/off` merging. Runs on CPU via `onnxruntime` with a Python API, no torch. Output: list of (start, end, speaker id). This is the realistic local diarizer for an Electron app; pyannote proper needs torch.
- **Scriberr** ([rishikanthc/Scriberr](https://github.com/rishikanthc/Scriberr)): self-hosted, engines Parakeet / Canary / Whisper, automatic diarization with speaker labels, playback follow-along and click-text-to-seek, built-in recorder, folder watcher, Ollama/OpenAI-compatible summaries and chat over the transcript, audio file import as the primary input.
- **Meetily** ([Zackriya-Solutions/meeting-minutes](https://github.com/Zackriya-Solutions/meeting-minutes)): Whisper or NVIDIA Parakeet (advertised "4x faster" live transcription), Metal/CoreML on macOS, Ollama-first summaries with Claude/Groq/OpenRouter/custom endpoints; community edition has no diarization (planned in the paid tier), so diarization is the gap even leaders have not closed in OSS desktop apps.
- **Hyprnote / Char / anarlog** ([fastrepl/hyprnote](https://github.com/fastrepl/hyprnote), now anarlog): local-first Tauri notepad, captures mic + system audio as separate streams, on-device Whisper, user's raw notes are the skeleton the summary is built around (the enhance UX we already copy), BYO LLM (Ollama/LM Studio), template-driven summaries, extension system. I could not pull its source in this session, so mechanism-level claims here are limited to its README/third-party descriptions.
- **NVIDIA Parakeet** (v2/v3 TDT 0.6B; run via onnx/sherpa-onnx or MLX): far faster than whisper-large on CPU/ANE with competitive English WER; Meetily and Scriberr both ship it. A pluggable-backend item for us, but a multi-hundred-MB model so it stays an optional extra.

### Build next

**meetings-1 (VAD gate + hallucination filter + local verbose JSON).** A new stdlib-only `meeting_vad.py` does an adaptive energy VAD on each wav (30 ms frames, noise floor from the 10th-percentile RMS, speech threshold floor+margin, minimum speech duration), returning a speech ratio and speech spans. `TranscribeWorker._transcribe_one` skips the STT call when a segment has no speech (state `empty`, wav deleted, no billed call), and a new `stt.filter_hallucinations` applies faster-whisper's `no_speech_threshold 0.6 / log_prob -1.0 / compression_ratio 2.4` rules per verbose_json segment, a short known-phrase list for low-speech-ratio segments, and repetition-loop collapse. `_local` switches to `-oj` so `detail.segments` exists, and passes `--vad` when a Silero ggml model is present. Optional `onnxruntime` Silero is a documented graceful upgrade, never required.

**meetings-2 (audio import).** `POST /meetings/{id}/import-audio` (multipart) writes the upload under `recordings/<id>/import/`, ffmpeg-resegments it into the same 20 s wav scheme, and feeds the existing `TranscribeWorker`/`finalize`/enhance path with `channel='import'` and offsets from the file clock. New module `meeting_import.py` keeps app.py edits to one route. It is the only way to use Meetings on non-macOS or loopback-less machines and the natural input for diarization.

**meetings-3 (speaker turns + naming).** `diarize.py` defines a backend seam (`none` default, optional `sherpa-onnx` loaded lazily when installed with model paths in settings) and a pure `assign_speakers(utterances, turns)` implementing WhisperX's max-overlap assignment. It runs at finalize only on retained audio (import, or `keepAudio`), writes `detail.turns` and per-utterance speakers, and a new `meetings.speaker_names` JSON column (via `ADDED_COLUMNS`) maps `S1` to a display name; `build_transcript` renders per-utterance `[Dana]` lines, `PUT /meetings/{id}/speakers` renames, and the enhance prompt is relaxed to allow naming speakers only from that map. Without a backend nothing changes, so behaviour degrades to today's channel labels.

### Specs

#### meetings-1: Segment VAD gate, Whisper hallucination filter, local whisper JSON detail (M)

**Why.** Whisper hallucinates on silence and room noise ('Thank you.', loops). faster-whisper (no_speech_threshold 0.6, log_prob_threshold -1.0, compression_ratio_threshold 2.4, hallucination_silence_threshold), whisper.cpp (--vad Silero) and WhisperX (VAD pre-segmentation) all gate before or filter after decoding. We send every 20 s segment, including silence, to a billed endpoint and roll whatever returns into transcript, FTS and the enhance prompt; the local backend also discards timestamps entirely (stt._local uses -otxt -nt). Verified: no silence/VAD/hallucination code in stt.py, meeting_recorder.py or audiocap.py.

**Files.** `backend/personal_os/meeting_vad.py (new)`, `backend/personal_os/stt.py`, `backend/personal_os/meeting_recorder.py`, `backend/personal_os/meetings.py (DEFAULT_CONFIG only)`, `backend/personal_os/app.py (MeetingConfigIn fields only, if the model is explicit)`, `backend/tests/test_meeting_vad.py (new)`, `backend/tests/test_stt.py`, `docs/meetings.md`

**Design.** 1) meeting_vad.py (stdlib: wave, array, math; no numpy). `analyze(path, frame_ms=30, min_speech_ms=250, margin=2.5, abs_floor=60) -> dict(speech_ratio: float, speech_seconds: float, spans: list[[start_s,end_s]], noise_floor: float, peak: float, ok: bool)`. Read 16-bit mono PCM via wave+array('h'); per-frame RMS; noise_floor = 10th percentile of frame RMS; threshold = max(abs_floor, noise_floor*margin); a frame is speech if rms>threshold; merge runs with <=300 ms gaps; drop spans < min_speech_ms; speech_ratio = speech_s/total_s. Non-16-bit or unreadable wav -> return ok=False and the caller treats it as 'unknown, transcribe anyway' (never drop audio on a parse failure). 2) stt.py: add `filter_hallucinations(text, detail, speech_ratio=None, cfg) -> (text, detail, dropped:list[str])`. For each entry of detail['segments']: drop if (no_speech_prob>0.6 and avg_logprob<-1.0) [faster-whisper's joint rule], or compression_ratio>2.4, or (speech_ratio is not None and speech_ratio<0.15 and normalized text in HALLUCINATIONS). HALLUCINATIONS = frozenset of normalized phrases: 'thank you','thanks for watching','thank you for watching','you','bye','subtitles by the amara.org community', 'please subscribe' etc. Collapse any phrase repeated >=4 consecutive times to one. Rebuild `text` from kept segments (join stripped); if detail has no segments (plain text reply) only apply the phrase rule to the whole text when speech_ratio<0.15. Record dropped phrases in detail['filtered']. 3) stt._local: add '-oj' (and `-of <tmp base>`), parse <wav>.json 'transcription' list into detail {'segments':[{'start': offsets.from/1000,'end':offsets.to/1000,'text':...}]}; keep -otxt fallback if JSON missing; unlink both files in finally. If cfg whisperVadModelPath (or <data_dir>/models/ggml-silero*.bin) exists, append ['--vad','-vm',path]. 4) meeting_recorder.TranscribeWorker._transcribe_one: after validate_wav and before the retry loop, if cfg.get('vadGate', True): v = meeting_vad.analyze(path); if v['ok'] and v['speech_ratio'] < cfg.get('vadMinSpeechRatio', 0.03) -> self._report(... self._result(state='empty', detail={'vad': v}, keep=False)) and return (no STT call). After a successful transcribe, if cfg.get('hallucinationFilter', True): run filter_hallucinations with v['speech_ratio']; if text becomes '' state='empty'. Do not update self._tail from filtered text. 5) Settings: add to meetings.DEFAULT_CONFIG: 'vadGate': True, 'vadMinSpeechRatio': 0.03, 'hallucinationFilter': True, 'whisperVadModelPath': ''. (config lives under settings['meetings'], DEFAULT_CONFIG is deep-merged in meetings.config_for; llm.DEFAULT_SETTINGS already has 'meetings': {'enabled': False}, which is a read-only block in PUT /settings, so keys only need to be in meetings.DEFAULT_CONFIG and accepted by MeetingConfigIn / PUT /meetings/config; verify MeetingConfigIn in app.py around line 4064 and add the four fields if it enumerates them.) No schema migration.

**Tests.** backend/tests/test_meeting_vad.py (plain script, style of test_stt.py): generate wavs with stdlib wave+math (silence, 440 Hz sine at amplitude 8000 for 3 s inside 10 s of near-silence with low noise, pure low noise, 8-bit file, corrupt file). Assert analyze: silence -> speech_ratio<0.03; tone burst -> ratio ~0.3 within tolerance and one span near [3,6]; noise-only -> below ratio threshold; corrupt/8-bit -> ok False. filter_hallucinations unit tests with hand-built verbose_json dicts: segment with no_speech_prob .9/avg_logprob -1.5 dropped; compression_ratio 3.0 dropped; 'Thank you.' dropped only when speech_ratio=.05 and kept at .6; 'a a a a a a' repetition collapsed; empty detail path. test_stt.py additions: _local with a stubbed subprocess.run that writes a whisper -oj JSON file (use monkeypatch of stt.subprocess.run and stt.whisper_cli_path) -> detail['segments'] populated and temp files removed. test_meeting_recorder.py addition using audiocap.synthetic_input: a segment of pure silence (anullsrc via a lavfi input spec) with a stubbed stt.transcribe that records calls -> zero calls, state 'empty'; sine segment -> one call. No network, no real model.

**Done when.** With vadGate on, a silent segment never reaches stt.transcribe and is stored as state empty with its wav deleted; a segment whose only output is 'Thank you.' at speech_ratio<0.15 yields no transcript text; verbose_json segments failing faster-whisper thresholds are removed and listed in detail.filtered; local whisper segments now carry start/end in detail; setting vadGate false and hallucinationFilter false restores current behaviour byte-for-byte; all new and existing meeting/stt tests pass offline with backend/.venv/bin/python.

#### meetings-2: Import an audio file into a meeting (import channel) (M)

**Why.** Scriberr and WhisperX are file-first; for us an existing recording, a phone memo, or any non-macOS / no-loopback machine has no way in, and docs/meetings.md names import-audio as the deferred slice. The schema (`meeting_segments.channel` allows 'import', CHANNEL_LABELS has 'import', `transcript.ts` handles channels) and the whole transcribe->finalize->enhance->accept pipeline already exist, so this unlocks it cheaply. It is also the clean input for whole-file diarization (meetings-3).

**Files.** `backend/personal_os/meeting_import.py (new)`, `backend/personal_os/audiocap.py (one helper: resegment_argv)`, `backend/personal_os/meetings.py (MeetingService.import_audio method, small)`, `backend/personal_os/app.py (one route, registered above /meetings/{id})`, `src/renderer/src/components/MeetingsView.tsx (Import button)`, `src/renderer/src/lib/api.ts (client call)`, `backend/tests/test_meeting_import.py (new)`, `docs/meetings.md`

**Design.** 1) audiocap.resegment_argv(ff, src, out_pattern, segment_seconds) -> argv: `ffmpeg -hide_banner -loglevel error -i src -vn -ac 1 -ar 16000 -f segment -segment_time N -reset_timestamps 1 -c:a pcm_s16le out_pattern` (out_pattern `import-%05d.wav`). 2) meeting_import.py: `async def run(svc, meeting_id, src_path, *, segment_seconds, ...)`: validate src with audiocap probe (_probe_duration) and reject > cfg.maxImportSeconds (default 14400) with a 400-style ValueError; create out dir via meeting_recorder.recording_dir(data_dir, id)/'import'; run ffmpeg in a thread; for each produced wav k: svc.meetings.add_segment(meeting_id,'import',k,k*N,k*N+secs,started_at+k*N,str(wav),size,duration_ms=...,state='recorded'); then transcribe sequentially in a thread pool of 1 reusing the same code path as TranscribeWorker (factor `_transcribe_one` core into a module-level function `transcribe_segment(path, cfg_fn, settings_fn, data_dir, tail)` OR instantiate TranscribeWorker with a queue; prefer minimal change: construct a RecordingSession-less TranscribeWorker and call its public methods; if impractical call stt.transcribe directly with the prior segment's tail as prompt and write through svc._on_result with the same res dict shape from TranscribeWorker._result). Honour keep_audio (delete wavs on success unless kept; failed ones stay for retranscribe). When all done: svc.meetings.mark_started-like patch (started_at = now - duration if empty, sources=['import'], duration_ms) then transcript=build_transcript, finalize(status='ready'), enqueue enhance if cfg.enhanceOnStop (reuse MeetingService._enhance_quietly). Refuse (409) if the meeting is currently recording or already has segments on mic/output. Consent gate: same `consentedAt` requirement as start() because it processes third-party speech, and the proxy backend uploads audio exactly as live recording does (reuse the same acknowledgement text/blocker). 3) Route: `POST /meetings/{id}/import-audio` with `UploadFile = File(...)`, python-multipart is installed; stream the upload to a temp file under data_dir/tmp (no full read into memory, cap 1 GiB), then `asyncio.ensure_future(meeting_import.run(...))`; return 202 with the meeting row (status 'transcribing'). Progress is the existing `/meetings/{id}/segments?since=` poll, no new bus. 4) UI: an 'Import audio' button in the meeting header when status is scheduled/notes_only/ready with no live session, `<input type=file accept=audio/*,video/*>`, posts multipart, then the existing polling view shows segments. 5) Settings key: add 'maxImportSeconds': 14400 to meetings.DEFAULT_CONFIG (and MeetingConfigIn if enumerated). No migration (channel 'import' already valid; the `sources` JSON gets ['import']).

**Tests.** backend/tests/test_meeting_import.py: skip with a clear message if ffmpeg is missing (other recorder tests assume it). Generate a 50 s sine wav with ffmpeg lavfi (audiocap.synthetic_input style), stub stt.transcribe to return f'seg {n}' deterministically, call meeting_import.run against a real in-memory Database + Meetings + MeetingService with a stub complete_fn for enhance. Assert: 3 segments (20+20+10 s) with channel 'import', t_start 0/20/40, state done, transcript has lines in order with the [them] label, status 'ready', wavs deleted when keep_audio is false and retained when true, a stt error on segment 2 leaves that wav and sets state failed while others finish, oversize duration rejected, import refused on a meeting that has mic segments, consent missing -> MeetingBlocked. Route test is optional; keep it at the service layer to avoid app.py import side effects.

**Done when.** Uploading a wav/mp3/m4a/mp4 to a meeting yields import-channel segments, a finalized transcript and a pending enhance revision, using the same stub-able STT path; failures behave like live segments (kept wav, Retranscribe works); a recording meeting or one with live segments rejects import; consent is enforced; the new test passes offline.

#### meetings-3: Speaker turns: diarization seam, WhisperX-style assignment, speaker naming (L)

**Why.** WhisperX (pyannote turns + max-overlap word/segment assignment), sherpa-onnx (ONNX segmentation + embedding + clustering, no torch), and Scriberr (auto speaker labels, rename) all attribute speech to people; Meetily's community edition has none. Ours collapses a four-person call into [them] and the schema seam (`meeting_segments.speaker`, `detail`, `speakerLabel()` in transcript.ts, CHANNEL_LABELS) is explicitly reserved for this. Because wavs are normally deleted per segment, diarization can only run on retained audio (imports from meetings-2, or keepAudio), which is honest and avoids a model dependency for the default path.

**Files.** `backend/personal_os/diarize.py (new)`, `backend/personal_os/meetings.py (ADDED_COLUMNS speaker_names, build_transcript, finalize hook, MeetingService.diarize)`, `backend/personal_os/meeting_notes.py (prompt + payload)`, `backend/personal_os/app.py (two small routes above /meetings/{id})`, `src/renderer/src/components/MeetingsView.tsx (rename speakers UI)`, `src/renderer/src/lib/transcript.ts`, `backend/tests/test_diarize.py (new)`, `docs/meetings.md`

**Design.** 1) diarize.py: `Turn = tuple[float,float,str]` (start,end,speaker id like 'S1'). `class Backend(Protocol): def diarize(self, wav: Path, cfg) -> list[Turn]`. `NullBackend` returns []. `SherpaBackend` imports sherpa_onnx lazily inside diarize(), builds OfflineSpeakerDiarizationConfig from cfg keys diarizeSegmentationModel and diarizeEmbeddingModel (paths under data_dir/models, user-downloaded; capabilities row `diarize` reports missing pieces with the exact download hint, non-blocking like stt_local), threshold from diarizeThreshold (default 0.5), min_duration_on 0.3 / off 0.5, num_clusters from diarizeSpeakers (0=auto); converts result.sort_by_start_time() to Turns; returns [] on ImportError. `resolve_backend(cfg)` -> 'none'|'sherpa' (setting diarizeBackend: auto|none|sherpa; auto = sherpa only if importable and both model files exist). 2) PURE `assign_speakers(utterances: list[dict{start,end,text}], turns: list[Turn], min_overlap=0.0) -> list[dict + 'speaker']`: for each utterance pick the speaker with the greatest summed overlap; if none overlaps, nearest turn by boundary distance within 1.0 s else ''; stable ordering. `merge_adjacent(utts, gap=1.5)` joins consecutive same-speaker utterances. Turn ids are renamed to S1,S2,... in order of first appearance. 3) Whole-file run: for a meeting with retained wavs on one channel (channel 'import', or 'output' with keepAudio), concatenate that channel's wavs in seq order into one temp 16 kHz wav via ffmpeg concat demuxer, call backend.diarize once (so clustering is consistent across the whole call; never per-segment), then offset turns are already global; map each segment's `detail.segments[]` (needs verbose segments from proxy or meetings-1 local JSON; if absent use the whole segment as one utterance at [t_start,t_end]) to speakers via assign_speakers using times relative to meeting start (segment t_start + utterance start). Persist per-utterance speakers into the segment's `detail['utterances']=[{start,end,text,speaker}]` and set `meeting_segments.speaker` to the dominant speaker; keep the 'mic' channel as 'me' (do not diarize the user's own mic). 4) meetings.py: ADDED_COLUMNS = {'speaker_names': "TEXT NOT NULL DEFAULT '{}'"} (JSON map {'S1':'Dana'}; add 'speaker_names' to JSON_FIELDS and PATCH via a dedicated method, not PATCH_FIELDS free-for-all). `build_transcript` change: when a segment's detail has utterances with speakers, emit one line per speaker run using `[Name]` (speaker_names.get(id, id), channel 'mic' stays [you]); when no utterance speakers exist, behaviour is byte-identical to today. Add `MeetingService.diarize(meeting_id)` (async via to_thread) that runs step 3, rebuilds transcript through `_settle_transcript`, and is called from stop()/import completion when cfg.diarize is true and audio is retained; a missing backend is a no-op with an info note, never an error banner.
