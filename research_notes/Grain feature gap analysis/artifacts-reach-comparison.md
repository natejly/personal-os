# Artifacts, dashboards, canvas, charts, web reach, and the Python sandbox

Comparison for a builder. Grain is a local desktop app. Synthesized 2026-10-02 from only these two notes:

- [App inventory](artifacts-reach-app.md), working tree that day. Code on disk wins over docs.
- [Market note](artifacts-reach-market.md), primary help and developer docs that day. No Grain code was reviewed there.

No new research. The two notes do not contradict each other: one inventories this tree, the other never opens it. They use "canvas" for different things, called out in section 3. Where the app note conflicts with older Grain docs, that is internal to the app note and is cited there.

Constraints on every close below: provider and source API keys stay on the server, out of widget and artifact HTML. Container network stays off unless the user turns `sandboxNetwork` on. This note does not describe sandbox escapes.

## 1. What Grain ships now

From the app note only.

**Dashboards.** Shipped. Tables `data_sources`, `dashboards`, `widgets`, and `recaps`. Source kinds `http`, `rss`, and `internal` (`todos`, `calendar`, `gmail`, `memories`, `projects`, `boards`). Widget kinds `html`, `summary`, `markdown`, `chart`, `stat`, and `table`, width 1–3 columns. Secrets stay on the server (`has_secret` in list responses; `fetch_source` injects the secret into a header or query param). HTTP and RSS go through `guarded_request` with redirects off. The Dashboards screen exposes those source and widget types. Chart, stat, and table render in `DeclarativeWidget` with no iframe. HTML renders in a CSP iframe. Summary and markdown render as markdown. There is no agent tool that creates a dashboard, a widget, or a data source (`tools.py`).

HTML widgets: the model writes one HTML document. The iframe is not given the app token. `render_widget` appends an HMAC query token (`widget:{wid}:{exp}`, 12-hour TTL) scoped to that widget's `source_ids`. CSP is `default-src 'none'` with inline script and style, `connect-src 'self'`, and `form-action 'none'`. The model prompt says credentials stay server-side and the iframe is `allow-scripts` only. Summary widgets call the model on every refresh (data blob capped at 24,000 characters). Recaps are one row per calendar day, skipped when `apiKey` is empty.

Declarative widgets: the model writes a JSON spec once (`path`, `select`, `sort` / `limit` / `filter` / `group`, plus a chart, stat, or table block). `generate_spec` validates, runs `autofix`, and makes at most one repair call. A later refresh re-binds and does not call the model. `GET /widgets/{wid}/data` serves cache inside `refresh_minutes` (minimum window 60 seconds). Rows cap at 500, series at 8. A declarative widget binds only the first id in `source_ids`. HTML widgets can be told about several sources. `revise_widget` regenerates the spec or, for HTML, the code.

**Spaces.** Shipped. A space is a persisted canvas (`canvases`, `canvas_windows`): snap, grid, zoom, pan, wallpaper, lock, and window geometry. Fifteen kinds on both sides, including `artifact`: chat, todos, calendar, board, note, dashboard-widget, memory, graph, documents, recap, project, usage, activity, web, artifact. The agent has no tool that opens or arranges a space. Presets keep windows whose referent still exists for chat, board, note, dashboard-widget, project, and artifact. They store refs and geometry, not a copy of artifact HTML or widget specs. `EAGER = true`, so every non-minimized, non-popped window renders. The six-window heavy cap and the 60% zoom gate are in code and are not applied. Heavy kinds: artifact, calendar, dashboard-widget, graph, usage, web.

**Artifacts.** Shipped and wired. `Artifacts(db)`, routes (list, create, get, update, delete, versions, restore, edit, revise, set code, render), and tools `artifact_create`, `artifact_update`, `artifact_edit`, `artifact_read`, `artifact_list`. Stored kind is `html` only. Versions are append-only, max 50. Render URLs are HMAC capabilities, TTL 24 hours. Render CSP is `default-src 'none'`, `connect-src 'none'`, `sandbox allow-scripts`. `blocked_capabilities` flags `fetch(`, XHR, WebSocket, remote script/link/iframe src, storage, forms, and `window.open`. The canvas window loads the artifact, offers history, revise, download, and copy, and accepts resize and title messages after a source check. Deleting an artifact or a dashboard widget also deletes matching canvas windows.

**Charts and interactive fences.** Shipped. Chat and doc markdown share `MarkdownPreview`. Fences `chart`, `interactive`, `mermaid`, and HTML/SVG become live blocks. Charts are Recharts from a JSON spec: `bar`, `line`, `area`, `pie`, `scatter`, 500 rows, views chart / table / source. Colors are `var(--chart-1)` through `--chart-8`. No brush component is imported. No time-axis type. Parse failure renders "Couldn't render chart" with no model repair in that component. Interactive fences add `slider`, `number`, `select`, and `toggle` (caps 12 controls, 8 series, 6 readouts, 400 sweep points, 500 rows). Formulas go through `lib/expr` `tryCompile`. The README says this is not `eval`; `expr.ts` itself was not re-read. Mermaid is lazy-loaded. The same chart components draw declarative dashboard widgets. Transforms exist on dashboard specs, not inside chart-fence `parseSpec`. A chart fence is JSON in the message. Live data belongs on a declarative widget, which can sit in a `dashboard-widget` window.

**Web search and fetch.** Shipped. `web_search` takes `time_range` (`day|week|month|year`) and `site`, pages rows, and allowlists every result URL so a tainted run can fetch them. Provider order: Brave alone if `braveApiKey` is set; otherwise Tavily alone if `tavilyApiKey` is set; otherwise concurrent SearXNG (only when `searxngUrl` is http(s)) and keyless Exa, merged with reciprocal rank when both return rows; if both fail or are empty, DuckDuckGo. A week range on SearXNG is rewritten and reported as month. `fetch_url` checks the URL, follows up to 5 redirects, then reads a cache (default TTL 3600 seconds; `fresh` bypasses). Bodies over 2 MB are not cached. `classify` routes pdf, json, html, text, or binary. HTML can be numbered (`LINK_CAP` 40) and focused with BM25 before paging. `max_chars` is clamped to 1,000–40,000 (default 12,000). Link URLs inside a page are not added to the allowlist. HTML that is 401/403/429/503 or under 300 characters can fall back to a Jina reader when `readerFallback` is true. Also registered: `youtube_video`, `youtube_search`, `github_search`, `github_read`. No site-map or crawl tool was found next to `web_search`. `open_page` was not re-read.

**Python sandbox.** Two sandboxes, both shipped.

`run_python` is a throwaway macOS seatbelt run: temp dir deleted afterward, `python -I`, network denied, app data, `.env`, ssh/aws/gnupg/kube, keychains, and browser profiles denied. A cowork desk `workspace` can be added as a readable and writable folder. A tool-bridge socket exists only when `tools` is set. Default timeout 30 seconds. CPU rlimit 20 seconds. The file states macOS refuses the address-space rlimits, so wall clock is the memory bound there. Matplotlib figures return as data URIs (at most 6 images, 3 MB each). Packages live in one shared venv (`<data_dir>/envs/work`): pandas, openpyxl, xlsxwriter, python-docx, python-pptx, pypdf, pdfplumber, reportlab, matplotlib, pillow. `python_install` allows at most 10 plain PyPI names, wheels only, and asks first (`danger` `external`). The `run_python` tool text says numpy is installed; numpy is not in `BASE_PACKAGES`. Whether matplotlib already pulls it in was not checked. This tool does not keep a kernel or the temp dir between calls.

The per-chat container is separate and persistent: name prefix `pos-sbx-`, default image `python:3.12-slim`, runtime default docker, `--network none` unless `sandboxNetwork`, `--memory 1g`, `--cpus 2`, `--pids-limit 256`, at most 5 sandboxes. `shutdown` stops labeled containers and does not `rm` them. `sandboxKeepDays` defaults to 14. `sandbox_checkpoint` is `docker commit --pause=true`, at most 3 images per conversation. `sandbox_restore` recreates from that image using the current network setting. `sandbox_reset` also removes checkpoint images. Tools: `sandbox_exec`, `sandbox_write_file`, `sandbox_read_file`, `sandbox_list_files`, `sandbox_put_document`, `sandbox_reset`, `sandbox_checkpoint`, `sandbox_restore`, present when the runtime is reachable. Idle stop is described in the README as five minutes; this inventory confirmed shutdown and checkpoint code, not the idle-timer function body.

**Desktop reach in this scope.** Shipped: first-run setup wizard (Fireworks, OpenAI API key, Anthropic, OpenRouter, Ollama, LiteLLM proxy, custom), a menu-bar tray that gathers canvas pop-outs, one global shortcut for that gather (`Control+Alt+Command+Space`, rebindable), in-app New Chat, and OS notifications for unattended jobs. A global quick-capture window is absent.

**Confirmed absent.** All three README items marked planned are absent as specified. Sign in with ChatGPT (browser OAuth, token in the local database, calls billed to that account). Private inference (sensitive jobs go to a local model and fail closed if it is down). Cloud worker (a second process for scheduled tasks, morning brief, and watches). What exists instead: an OpenAI API-key preset at `https://api.openai.com/v1`, an optional Ollama base URL for the whole app, and a job scheduler that runs only while this process is up. `extractionModel` is cleared on setup and is not a local-only path. Nothing in the summary, recap, learn, meetings, activity, or compaction call sites refuses a remote URL. Backend Python has no `chatgpt.com` / `auth.openai` sign-in, no `cloud_worker`, and no `llama.cpp` or `mlx` matches. On-device audio transcription is a different feature and was not re-audited.

**Docs that lag the tree.** `docs/research/sota-canvas.md` and `docs/research/sota-reach.md` describe an older tree. Artifacts, declarative widgets, `webread` / `websearch`, and checkpointed containers are in the code those notes say is missing. The README dashboard blurb omits chart, stat, table, specs, and TTL refresh. The README MicroVM section matches the code that was read. The short README Sandbox blurb says `run_python` denies reads of local files; the profile allowlists the interpreter, site-packages, and selected system directories, and macOS does not apply the address-space rlimit.

## 3. Where Grain is already ahead, or different on purpose

**A space is a real windowed desktop.** Grain keeps fifteen live window kinds on a saved canvas. ChatGPT removed Canvas from GPT-5.5 Instant and GPT-5.5 Thinking on 28 May 2026 and documents the desktop agent as a permissions control under the composer ([model release notes](https://help.openai.com/en/articles/9624314-model-release-notes/), [sandbox docs](https://learn.chatgpt.com/docs/sandboxing)). Claude's "canvas" in the current artifact help is the editable page inside a template artifact, not a desk of app windows ([artifact help](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)). Those are different products. Grain's fallback name `"Space"` is a canvas label.

**Live data is a spec, not a regenerated page.** Chart, stat, and table widgets store a JSON spec and refresh on a TTL without another model call, bound to HTTP, RSS, or Grain's own todos, calendar, mail, memories, projects, and boards. Secrets stay in `fetch_source`. Claude's documented dashboard is an artifact page, or a PNG from the code-execution container ([artifact help](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them), [file creation](https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude)). ChatGPT's documented in-answer charts are bar, line, pie, and scatter in the conversation ([8 June 2026 release notes](https://help.openai.com/en/articles/6825453-chatgpt-can-now-generate-images)). Grain's fence already has those four plus `area`, and the interactive fence adds local controls with a non-eval formula parser. ChatGPT Finances (Plaid, Pro, United States, from 15 May 2026) is a separate first-party product, not a generated widget ([same release notes](https://help.openai.com/en/articles/6825453-chatgpt-can-now-generate-images)).

**The widget and the artifact are stricter clients than Claude's published page.** Grain's artifact render sets `connect-src 'none'` and flags remote script, fetch, XHR, and WebSocket. The HTML widget CSP has no external script or CSS host. Claude's published artifact may load five CDNs and Google Fonts, and may `fetch` its own origin ([Claude Code artifacts](https://code.claude.com/docs/en/artifacts.md)). Grain's broker for dashboard data is the scoped HMAC token, and declarative widgets never see the secret because the backend fetches. That matches the market pattern the note says transfers to one user on one machine: untrusted UI, host-owned credential, keys out of the page ([market note, "Which of these matter"](artifacts-reach-market.md)). Per-viewer OAuth, public links, and shared artifact storage are called out there as multi-user hosting, and they fit a local single-user app poorly.

**Search already has a recency control and can run without a vendor key.** `time_range` is `day|week|month|year`. Claude's consumer research help and the ChatGPT pages that were read do not document a time-range control. Perplexity's API documents a finer set (hour, plus publication and last-updated bounds), so this is ahead of the Claude and ChatGPT consumer docs in that note, and behind Perplexity's API. With no Brave or Tavily key, Grain merges SearXNG and keyless Exa, then falls back to DuckDuckGo. A tainted run may fetch search-result URLs. URLs discovered inside a fetched page are not allowlisted.

**Two code runners, on purpose.** `run_python` is a stateless seatbelt one-shot with network denied, for a figure or a file conversion. The container keeps the conversation's files, checkpoints (max 3), and a 14-day stopped lifetime, with network off unless the user sets `sandboxNetwork`. The market note's split is the same shape: chat products use a remote container with no general internet; local agent shells use an OS sandbox; Cowork puts code in a VM and leaves ordinary file and web tools on the host. Grain already uses Seatbelt for the one-shot and a container for the persistent job. Replacing `run_python` with a second kernel would duplicate the container. Replacing Docker with Apple Virtualization.framework would copy Cowork's hypervisor and drop the checkpoint tools that are already shipped. The app note's remaining sandbox gap is the on-switch: `sandboxNetwork` is described as network on, with no registry allowlist and no deny-wins proxy.

**Jobs that stay on this machine.** Scheduled work runs in this process. Chat and both sandboxes stay local. The planned cloud worker would move scheduled tasks to a VPS with its own database. That item is absent. It is a product choice the market note does not score.

## 5. The top three builds

Order is what a person on this desktop hits first, using surfaces the tree already has. Sign-in, fail-closed inference, the cloud worker, and quick capture stay absent and stay out of these three: the market note does not cover them, and they do not unblock dashboards, charts, research, or the sandbox.

### 1. Agent tools for a bound widget on a space

The agent can already keep an HTML artifact. It cannot build the live dashboard Grain already renders, and it cannot put that widget on a space. Claude creates the side object from the conversation. This is the same job, aimed at `chart` / `stat` / `table` plus `add_window`.

Offline check: a test calls the tool with an internal source or a fixture HTTP source whose secret is a known string. It asserts a `chart` widget row, a spec that `generate_spec` accepts, a `dashboard-widget` window whose `ref_id` is that widget, and a refresh path that does not call `llm.complete`. The widget JSON, the spec, the data payload, and the iframe URL do not contain the secret.

### 2. Domain allow/deny, and a citation excerpt on fetch

Search, fetch, single-site, and `time_range` are shipped. The missing controls the market note treats as the research baseline are a domain list and a quote the user can check. Claude's API refuses when allow and block are both set. ChatGPT deep research is restrict or prioritize. Perplexity is allow or deny, up to 20, not both.

Offline check: fixture result rows, no network. Allow-list keeps only matching domains. Block-list drops them. Setting both returns an error and does not merge engines. A fixture HTML file through the `fetch_url` classifier returns `url`, `title`, and an excerpt under a fixed character cap. `time_range` still accepts only `day|week|month|year`. In-page links are still absent from the allowlist.

### 3. One repair pass for HTML widgets

Declarative widgets already validate and repair once. HTML widgets do not, and they are the path that can leak a secret into a page or pull a remote script if the model ignores `WIDGET_SYSTEM`.

Offline check: a fake `llm.complete` returns broken HTML on the first call and clean HTML on the repair call. The saved document is the repair, and `llm.complete` is invoked at most twice. A repair that still contains an external script URL, or the fixture source secret, is stored as an error and not rendered. CSP and the HMAC token helper are unchanged. Container create flags in the same test run still include `--network none` when `sandboxNetwork` is false.

Next after these three, when the user has turned network on: the registry allowlist in the gap table. It is L, and the default must stay off.
