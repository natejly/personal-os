# Life-OS comparison: Today, todos, calendar, mail, boards

As of 2026-10-02. Synthesized from `life-os-app.md` (working tree that day) and `life-os-market.md` (official docs fetched that day). No new web research. The notes do not contradict each other on Grain’s behavior or on the Tasks API. Two conflicts stay inside the market note and are labeled where they matter.

Products named here are only ones the market note checked: Gemini Apps, Claude, ChatGPT, Gmail, Google Calendar, Google Tasks, Superhuman Mail, Shortwave, Reclaim, and Motion.

Effort is a sizing judgment from the files the app note already names: **S** is one existing module and its UI, **M** crosses one backend module plus a view, **L** is a new subsystem or a multi-API triage surface. Nothing below was timed.

Sends and calendar writes stay propose-then-confirm. Recurrence stays in Grain’s todo store. The Tasks resource has no repeat field, and `due` keeps only the date. The time portion is discarded. ([Tasks resource](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks#resource:-task))

## 1. What Grain ships now

From the app note only.

**Today** (`HomeView`) is a greeting, the local long date, a quick-ask box, and toggleable cards. A missing `homeWidgets` key means the card is on. Defaults turn off only the cowork and meetings cards. Card order: Agent inbox, Cowork desks, Daily recap, Calendar (next 48 hours), Todos, Health, Inbox (unread, 14 days, first 8), Google Tasks (first 8), Drive (recently modified, first 8), Upcoming meetings, Projects, Recently learned (first memories), Recent chats. Google cards show Connect when `google.connected` is false. Drive also offers Reconnect when `missing_scopes` contains `drive`. `GET /dashboard` degrades per source into `errors`. Module `today()` must not call Google. ([HomeView.tsx](src/renderer/src/components/HomeView.tsx), [app.py `dashboard`](backend/personal_os/app.py))

**Brief me** opens a new chat and sends a fixed prompt: calendar today and tomorrow, unread mail for replies, open todos with overdue ones flagged, then the 3 things to do first. A seeded job, “Morning brief,” uses nearly the same prompt on cron `30 7 * * *`, with a read-only allowlist, and is created disabled. **Daily recap** is a separate cached markdown note per `YYYY-MM-DD` (`GET /recap`), sections “Since yesterday,” “Today,” and “Suggested focus,” under 180 words, empty if there is no API key. The card can regenerate or hide for the session. Quick-ask sends Enter as a new chat and ⌘/Ctrl-Enter as a one-line todo. Page context includes today’s events, later events, open todos, and the first 1500 characters of the recap. ([HomeView.tsx](src/renderer/src/components/HomeView.tsx), [jobs.py `SEED_JOBS`](backend/personal_os/jobs.py), [dashboards.py `RECAP_SYSTEM`](backend/personal_os/dashboards.py))

**Native todos** have title, notes, date-only `due`, priority 1–3, done, project, Google Tasks link, calendar mirror link, `repeat` JSON, `estimate_min`, and trash. Completing a row that still has `repeat` spawns the next instance and clears `repeat` on the completed row. The Todos page can set due, priority, project, and a repeat preset (every 1, from due: daily / weekly / monthly / yearly). Tools can set every-N and `from_completion`. Sort is Due or Urgency. Each row can complete, edit, trash, show a repeat badge and urgency, set an estimate, and schedule onto Google Calendar. `PlannerPanel` (“Plan my day”) is on this page. Todo writes default to on. Two-way Tasks sync defaults to on, about every 5 minutes, full `tasks_all` each pass. The next spawned todo syncs as a new task because recurrence is not sent to Google. A calendar mirror places each due todo on a configured calendar as a transparent event and adopts a dragged time back onto the todo. ([todos.py](backend/personal_os/todos.py), [TodosView.tsx](src/renderer/src/components/TodosView.tsx), [gtasks.py](backend/personal_os/gtasks.py), [todocal.py](backend/personal_os/todocal.py))

Today’s todo card is a different slice: open todos across projects, store order (done, null dues last, due, priority, `created_at DESC`), 12 fetched, 8 shown. Urgency sort is not used there. The Google Tasks card is a separate read of the default list, so with sync on the two cards can show the same work. ([modules/todos.py `today`](backend/personal_os/modules/todos.py), [HomeView.tsx](src/renderer/src/components/HomeView.tsx))

**Week calendar** is a Sunday-start 7-day grid of Google events plus due todos. Disconnected, it says it is showing todos only. Connected, calendars can be shown or hidden. `calendar_events` lists per calendar, `singleEvents=True`, and when ids are `["all"]` keeps the first 15 non-hidden calendars. There is no `syncToken`. Double-click creates a one-hour event. Drag moves start and end; events with attendees ask before emailing them. A recurring instance is edited as “this occurrence.” Dropping a todo sets `due` to that day and, if Google is connected, creates an event (all-day if the drop has no hour). The event editor covers all-day vs timed, RRULE presets plus custom RRULE/EXDATE/RDATE, series vs occurrence, guests and RSVP, guest permissions, Meet, reminders, color, location, description. **Plan my week** starts a chat. It is a prompt, not `schedule_suggest`. Calendar write tools are danger `external` (ask). `calendar_find_time` uses work hours 9–18 local, weekdays, and does not treat declined or transparent events as busy. `calendar_propose` reviews a batch on an overlay and writes nothing until approval, then read-back. ([CalendarView.tsx](src/renderer/src/components/CalendarView.tsx), [EventEditor.tsx](src/renderer/src/components/EventEditor.tsx), [tools.py](backend/personal_os/tools.py))

**Mail** searches Gmail (30 results) with folder, read filter, starred, attachments, `newer_than`, and a debounced query. Opening a message loads the body and marks it read. Toolbar actions in code: star, archive, compose, reply (quote up to 40 lines), save draft, send, review, and ask the assistant. Send toasts an immediate send, an unverified send, or an undo window. Tools: `gmail_search`, `gmail_read`, `gmail_draft` (never sends), `gmail_send` (outbox when wired; `as_draft` writes a draft), `gmail_outbox` (list or cancel this chat’s rows; cannot send early), `gmail_modify` (read/unread, archive, star). `Google.gmail_labels` exists and the view loads labels; the app note did not confirm a tool under another name. ([MailView.tsx](src/renderer/src/components/MailView.tsx), [tools.py](backend/personal_os/tools.py))

**Boards** are local kanban: boards, columns with a stored `wip_limit`, cards with title, description, float position, due, priority, JSON labels. Drag uses midpoint floats. The header shows `count` or `count/limit` when a limit is stored. Nothing in the renderer sets the limit. `add_card` and `move_card` do not read it. Cards have no todo id and do not appear on Today or the calendar. Default columns on create, from the tool text: Backlog, To do, In progress, Done. Tools can list, add a card, move a card, and create a board. No tool updates description, labels, due, or WIP, and no tool deletes a card. Board writes default to on. ([boards.py](backend/personal_os/boards.py), [BoardsView.tsx](src/renderer/src/components/BoardsView.tsx))

**Sign-in** is a desktop installed-app OAuth flow. A client pasted in Settings wins; otherwise env vars. Requested scopes: `openid`, `userinfo.email`, `calendar`, `gmail.modify`, `tasks`, `drive.readonly`, `drive.file`, `documents`, `spreadsheets`. No `include_granted_scopes`. Connected means a refresh token exists. `needs_reauth` is set when the token says so, scopes are missing, or the client id no longer matches. README still names only Calendar, Gmail, Tasks, and `email`. Every external write in `google.py` gets a read-back verdict: verified, unverified, or mismatch. Anything but verified becomes a tool error. Calendar list and Gmail headers refresh incrementally (`updatedMin`, Gmail `historyId`). Tasks sync does not. ([google.py](backend/personal_os/google.py), [verify.py](backend/personal_os/verify.py), [README.md](README.md))

**Watched vs unattended.** Interactive `gmail_send` sits in `pending_sends` for 60–120 seconds (default 90) unless the hold is disabled, in which case it sends immediately. A job never calls an external tool. Those calls become Agent-inbox proposals. Accept runs the call once. An accepted `gmail_send` then enters the outbox. Holds overdue by 15 minutes or more expire and are not sent. Jobs do not inherit a skip-permissions path. If nobody is watching and a call was not turned into a proposal, it is denied. ([outbox.py](backend/personal_os/outbox.py), [app.py](backend/personal_os/app.py))

The app note’s own “still absent” list, kept here so later sections do not treat them as shipped: mail snooze and send-later; todo subtasks, dependencies, tags, and a start time separate from `due`; board WIP enforcement; Tasks `updatedMin`; Calendar `syncToken`.

## 2. What leading apps ship that Grain does not

Named from the market note, with that note’s sources. Rows the app note already marks shipped are omitted here and listed in section 6.

**A sectioned daily brief with per-item complete, dismiss, and feedback.** Gemini Apps generates a Daily Brief from connected apps such as Gmail and Google Calendar, plus Gemini chats. Sections are “Top of mind” and “Looking ahead.” The user can chat about an item, mark it complete or incomplete, dismiss it, and mark it helpful or not. Eligibility on the help page fetched 2026-10-02: 18 or older, in the US, a personal Google Account, Personal Intelligence with Google Workspace connected and Memory on, English only. It can be turned off. A regional variant of the same article names a paid Google AI plan (Plus, Pro, or Ultra). ([Gemini Apps Help](https://support.google.com/gemini/answer/17077455?hl=en), [en-KE variant](https://support.google.com/gemini/answer/17077455?co=GENIE.Platform%3DDesktop&hl=en-KE))

Grain’s Brief me is an attended chat with a fixed prompt. The morning-brief job exists and is created disabled, and its allowlist cannot send or write the calendar. Daily recap is one cached markdown note, not items the user completes or dismisses. ([HomeView.tsx](src/renderer/src/components/HomeView.tsx), [jobs.py](backend/personal_os/jobs.py))

Conflict, unresolved, no new research: the Gemini marketing page says the brief scans inbox, calendar, and tasks, and that the user can set reminders, open emails, draft replies, and schedule events from the brief. The help article does not describe those controls. ([Gemini Daily Brief overview](https://gemini.google/overview/daily-brief/), contradicted in scope by [Gemini Apps Help](https://support.google.com/gemini/answer/17077455?hl=en))

**Scheduled and Gmail-triggered tasks that can stand in for a brief.** ChatGPT has no separate daily-brief object on the help page that was fetched. It has one-time and recurring scheduled tasks, plus monitoring tasks. Scheduled tasks can use connected apps including Gmail. Active-task caps: 3 on Free and Go, 5 on Plus, 10 on Business and Edu, 15 on Pro and Enterprise. Free is once per day in a flexible window. Paid plans can run hourly at an exact time. Event-triggered tasks in Work can fire on a new Gmail message, filtered by sender or subject, up to 30 times per hour and 720 times per day. If an action needs approval, the task pauses. The desktop app can show those tasks and cannot create or edit their trigger conditions. ([Scheduled tasks in ChatGPT](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt))

Grain’s morning brief is a disabled cron job with a read-only allowlist, not a sectioned brief. Mail watch has no background loop. Refresh is `POST /mail/watch/refresh` or the `mail_followups` tool. The market note did not fetch Gmail `users.watch` or Calendar push, so a push trigger is not a sourced close. ([mailwatch.py](backend/personal_os/mailwatch.py), market note gap on push)

**Inbox splits, natural-language labels, and snooze.** Shortwave’s triage loop is: clear non-actionable mail (done, delete, or snooze), do anything under about two minutes immediately, and turn larger work into stars or todos. Inbox Splits are tabs by importance, labels, senders, or search. AI filters label from natural-language rules and can feed those splits. “Organize my inbox” recommends bulk archive, label, delete, and todo actions while the user stays in control. Instant replies are inline suggestions. ([The Shortwave Method](https://www.shortwave.com/docs/guides/method/), [Customize your Shortwave](https://www.shortwave.com/docs/guides/customize-your-shortwave-settings/), [The Shortwave AI Assistant](https://www.shortwave.com/docs/guides/ai-assistant/))

Superhuman puts returned reminders in their own inbox section, with pending reminders in a Reminders folder. ([Remind Me](https://help.superhuman.com/hc/en-us/articles/46005666142733-Remind-Me))

Grain’s `MailView` has folder, read, starred, attachments, and `newer_than`. The app note records no snooze control. `gmail_modify` is read/unread, archive, and star. ([MailView.tsx](src/renderer/src/components/MailView.tsx))

**Label, filter, spam, and trash tools.** Claude’s Gmail connector (added March 2026) includes search, thread and message reads, create_draft, list_drafts, reply, forward, send_message, label and unlabel, create and delete labels, create and list filters, mark spam, and trash. Attachment content is metadata only. By default every action needs explicit approval. Team and Enterprise owners can let members allow send, reply, and forward without asking. ([Gmail connector](https://claude.com/connectors/gmail), [Use Google Workspace connectors](https://support.claude.com/en/articles/10166901-use-google-workspace-connectors))

**If-no-reply reminders that return the thread, and a draft waiting when they return.** Superhuman reminders default to “if no reply” (the thread returns only if nobody has responded; a reply cancels that reminder) or “Regardless.” Auto Reminders apply a default return time to mail the model judges needs a follow-up, to every external recipient, or to no messages. Auto Drafts write follow-ups and replies for the user to review, edit, and send. Follow-up drafts are added about an hour before a reminder returns. The follow-up and response toggles are documented on the Business and Enterprise Auto Drafts pages. When a mail needs a meeting, Auto Drafts can include the user’s available times. ([Remind Me](https://help.superhuman.com/hc/en-us/articles/46005666142733-Remind-Me), [Auto Reminders & Auto Drafts](https://help.superhuman.com/hc/en-us/articles/46005658551053-Auto-Reminders-Auto-Drafts), [Follow Up Faster](https://help.superhuman.com/hc/en-us/articles/46005792082445-Follow-Up-Faster))

Grain’s tracker stores `to_reply`, `awaiting_reply`, `fyi`, and `actioned`, classifies on demand, and can create a follow-up todo only after an explicit POST or panel button. The panel does not draft. Counts are on the dashboard payload and are not drawn on Today. That remaining thinness is in the gap table. The tracker itself is not a build. ([mailwatch.py](backend/personal_os/mailwatch.py), [MailWatchPanel.tsx](src/renderer/src/components/MailWatchPanel.tsx))

**Open tracking.** Superhuman Read Statuses show time, device, and who opened a message, only for mail sent with Superhuman Mail. There is no notification on open. Recent Opens is Business and Enterprise. ([Read Statuses and Recent Opens Feed](https://help.superhuman.com/hc/en-us/articles/46005603745293-Read-Statuses-and-Recent-Opens-Feed)) The market note’s inference is that this is not a Gmail API field, and section 3 leaves it aside on purpose.

**Offer a few real free/busy slots inside the message, then create the event when a person confirms.** For personal Gmail, “Propose times you’re free” lets the sender pick slots. The event is created when the recipient chooses. It is 1:1 only. On higher Google AI and Workspace plans, “Help me schedule” proposes times from availability. Default is 4 slots, maximum 20 guests. Green means all guests are free. Amber means the user must pick. Booking a slot creates the event and invites guests. Any Gmail user can also turn an existing thread into an invite. Appointment schedules are a booking page (buffers, a daily cap, calendars to check, co-hosts, Meet or in-person or phone, a form, up to five reminder emails whose text cannot be edited). The market note did not find an API for creating that booking-page object. ([Offer times to meet](https://support.google.com/mail/answer/16864784?hl=en), [Suggest times to meet with Gemini in Gmail](https://support.google.com/calendar/answer/16865189?hl=EN), [Schedule events in Gmail](https://support.google.com/mail/answer/16865706?hl=en), [Create an appointment schedule](https://support.google.com/calendar/answer/10729749))

Grain already has `calendar_free_busy` and `calendar_find_time`, and `gmail_draft` never sends. Nothing in the app note inserts proposed times into a draft. Plan my week is a chat prompt. Free/busy returns busy windows only, for at most 50 calendars, and the app computes open slots locally. ([tools.py](backend/personal_os/tools.py), [Freebusy: query](https://developers.google.com/calendar/api/v3/reference/freebusy/query))

**Defended time blocks that move when a meeting lands.** Reclaim places Habits, Tasks, and Focus Time and moves them unless locked. Priority runs Critical (P1) through Low (P4). Higher priority can overbook lower-priority Reclaim events. Users can auto-lock at the start of the day or week. A 12 June 2026 help article says task order can be weighted by due date, by work remaining, or by both. Reclaim also defends a no-meeting day and still lays Focus, Habits, and Tasks onto it. ([How Reclaim manages your schedule automatically](https://help.reclaim.ai/en/articles/6207587-how-reclaim-manages-your-schedule-automatically), [Priorities](https://help.reclaim.ai/en/articles/8291694-how-reclaim-uses-priorities-to-intelligently-plan-your-workweek), [Getting started with Reclaim](https://help.reclaim.ai/en/articles/5224992-getting-started-with-reclaim))

Motion’s public API creates a recurring task with frequency, duration, an ideal `HH:mm` used when that time is free, a schedule, and a deadline type of `HARD` or `SOFT`. The help center for how the product reshuffles a week was not fetched, so this note does not say whether Motion asks before each move. ([Motion API, create recurring task](https://docs.usemotion.com/api-reference/recurring-tasks/post))

Grain’s planner proposes blocks. The user applies selected ones. Applied blocks are ordinary events. Nothing in the app note moves them when a later event overlaps. Calendar will store a block. It will not defend it. ([planner.py](backend/personal_os/planner.py), market inference on the Calendar API)

**Task parent/child.** The Tasks resource has `parent`. `tasks.insert` takes parent and previous-sibling as position parameters, not as recurrence. Caps: 20,000 non-hidden tasks per list and 100,000 total. Title max 1024 characters. Notes max 8192. Status is only `needsAction` or `completed`. ([Tasks resource](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks#resource:-task), [tasks.insert](https://developers.google.com/tasks/reference/rest/v1/tasks/insert))

Grain’s `Todos.update` has no parent, subtask, dependency, or tag field. ([todos.py](backend/personal_os/todos.py))

**Citations back to the message or event.** Claude Help says Workspace answers include citations and links back to the emails, events, or documents used. ([Use Google Workspace connectors](https://support.claude.com/en/articles/10166901-use-google-workspace-connectors)) The app note does not describe source links on the recap or on Brief me. It does say the recap is forbidden from inventing facts.

**Testing-mode token lifetime for this OAuth shape.** An External consent screen left in Testing expires refresh tokens in 7 days when the scopes are outside name, email, and profile. Gmail, Calendar, and Tasks are outside that subset. The user can also lose the token by revoking the app, leaving it unused for six months, changing their password when the token includes Gmail scopes, or exceeding 100 refresh tokens per account per client (the next one drops the oldest). While Testing, verification is not required and only listed test users can connect. The app note does not record Grain’s publishing status. It records `needs_reauth` for a token flag, missing scopes, or a client-id mismatch, and it does not mention a 7-day expiry. ([Using OAuth 2.0 to Access Google APIs](https://developers.google.com/identity/protocols/oauth2), [Restricted scope verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification), [google.py `status`](backend/personal_os/google.py))

Publishing to remove that expiry is a different project. Gmail scopes including `gmail.modify` and `gmail.compose` are restricted. If the app stores restricted-scope data on servers, or transmits it, it also needs a security assessment. ([Choose Gmail API scopes](https://developers.google.com/workspace/gmail/api/auth/scopes)) Grain’s recap sends unread subjects and calendar facts to a model when an API key is set, and the brief’s tools include `gmail_read`. That is transmission off the machine once a cloud model is used. The app note does not say which host runs the model.

**Boards.** The market note did not review a kanban product (it names Todoist, Sunsama, Akiflow, and Fantastical as unchecked). No competitive board claim is available from these notes.

Conflict, unresolved, no new research: a Claude docs page, seen only in search snippets and not fetched in full, still says Claude cannot create, modify, or delete events and cannot send invitations, and that the integration is on Pro, Max, Team, and Enterprise. The Help Center article updated on the fetch date, and the connector tool list, describe create, update, delete, RSVP, and recurring meetings for every Claude user, including desktop. ([Claude docs, Google Calendar integration](https://claude.com/docs/connectors/google/calendar), contradicted by [Use Google Workspace connectors](https://support.claude.com/en/articles/10166901-use-google-workspace-connectors) and [Google Calendar connector](https://claude.com/connectors/google-calendar)) Grain’s own calendar write tools are already in the app note, so this conflict does not change the gap list.

The market note also did not confirm a 2025–2026 Gmail help page for nudges. Only the 14 May 2018 launch post was found. Nudges are not used as a current gap. ([Gmail will now remind you to respond](https://workspaceupdates.googleblog.com/2018/05/gmail-remind-respond.html))

ChatGPT’s Google Calendar tool list was not on the official pages fetched. This comparison does not claim ChatGPT can or cannot create events.

## 3. Where Grain is already ahead, or different on purpose

**Recurrence lives in Grain, which is the option the Tasks API allows.** Units are day, week, month, and year. Modes are `from_due` and `from_completion`. The UI presets are every-1 from due. Tools can set every-N and from completion. The completed row does not spawn twice. The next instance syncs as a new task. A Calendar RRULE is the other durable option in the market note, and Grain’s event editor already writes RRULE, EXDATE, and RDATE. Motion’s extra fields (ideal `HH:mm`, `HARD`/`SOFT`, a named schedule) are not on Grain’s todo. They are also not Tasks fields. ([todos.py](backend/personal_os/todos.py), [Tasks resource](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks#resource:-task), [Recurring events](https://developers.google.com/workspace/calendar/api/guides/recurringevents))

**A clock time for a task is a calendar event, because Tasks will not store one.** The mirror writes a transparent event and adopts a dragged time back onto the todo (`_adopt` / `_sig`). Dropping a todo on an hour creates a timed event. `calendar_find_time` ignores transparent events, so those due markers do not look busy. ([todocal.py](backend/personal_os/todocal.py), [Tasks resource](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks#resource:-task))

**Time blocks are proposed, then the user applies a subset.** The planner is a pure function: work window default 09:00–17:30, weekdays, 10-minute buffers, 15-minute steps, 15–120 minute blocks, 7-day lookahead, unknown estimate treated as 30. Weights are due 0.40, priority 0.25, energy 0.20, time 0.15. Energy is a length heuristic, not a stored field. Apply calls `calendar_create` for `Focus: {title}` with `send_updates=none` and keeps only verified creates. `schedule_suggest` tells the model not to call `calendar_create` unless the user confirms. That matches the market note’s reading of propose-then-confirm, and it is stricter than Reclaim’s automatic move. Silent moves are out of scope for the builds below. ([planner.py](backend/personal_os/planner.py), [modules/planner.py](backend/personal_os/modules/planner.py))

**Unattended mail and calendar writes cannot fire.** A job records a proposal. Accept is once (a second accept is 409). Accepted sends still wait out the 60–120 second hold. The morning-brief allowlist cannot propose those tools because they are not on the list. Claude’s default is also ask-before-send, with a Team and Enterprise option to stop asking. Grain’s job path has no equivalent of that option in the app note. Interactive undo is a different queue from the proposal inbox: the person who just composed can still cancel; a sleeping laptop does not emit a hold that is more than 15 minutes overdue. ([app.py](backend/personal_os/app.py), [outbox.py](backend/personal_os/outbox.py), [Use Google Workspace connectors](https://support.claude.com/en/articles/10166901-use-google-workspace-connectors))

**External writes are read back.** Verdicts are verified, unverified, or mismatch. The model is told not to claim success and not to retry. Planner apply treats a failed verification as a failed block. Mail compose treats sent-but-unverified as an error toast. None of the assistant help pages in the market note describe a read-back verdict. ([verify.py](backend/personal_os/verify.py), [google.py](backend/personal_os/google.py))

**The week grid, the todo list, and the boards are real local UI, not only chat tools.** Claude’s retrieved calendar examples are on-demand questions. Grain can double-click an hour, drag an event, RSVP, and edit a series. Todo and board writes default to on. Google writes default to ask. ([CalendarView.tsx](src/renderer/src/components/CalendarView.tsx), [tools.py `DEFAULT_MODE`](backend/personal_os/tools.py), [Google Calendar connector](https://claude.com/connectors/google-calendar))

**Mailbox data is fetched with the user’s own OAuth client into the local app.** Claude stores retrieved mail, calendar, and Drive data on Anthropic servers tied to the chat. A local app that never uploads those bodies does not take on that copy. Grain does send recap facts, and can send a brief that has read mail, to whatever model the API key points at. The system of record for todos, `thread_status`, boards, and the outbox is local. ([Use Google Workspace connectors](https://support.claude.com/en/articles/10166901-use-google-workspace-connectors), [mailwatch.py](backend/personal_os/mailwatch.py))

**Open tracking is a different product.** It works only for mail Superhuman itself sent. The market note found no Gmail field that provides it, and treats it as not table stakes. Grain’s tracker uses headers and snippets (who sent last, request phrases, age). Copying a tracking pixel is not a close for any gap below. ([Read Statuses](https://help.superhuman.com/hc/en-us/articles/46005603745293-Read-Statuses-and-Recent-Opens-Feed), [mailwatch.py](backend/personal_os/mailwatch.py))

**`gmail.modify` matches archive and star, which Grain already does.** The market note’s least-privilege example says an app that only sometimes sends should not request a scope that can read the whole mailbox. Grain also reads, archives, and stars, which is what `gmail.modify` is documented to cover (and not permanent delete). Splitting that scope is not required by the shipped mail toolbar. Adding Drive, Docs, and Sheets on the first consent is a separate choice: the market note recommends incremental scopes, and Grain’s `start_auth` does not set `include_granted_scopes`. ([Choose Gmail API scopes](https://developers.google.com/workspace/gmail/api/auth/scopes), [google.py `start_auth`](backend/personal_os/google.py), [Using OAuth 2.0 to Access Google APIs](https://developers.google.com/identity/protocols/oauth2))

**Manual “put this todo on the calendar now” is a user gesture, already verified.** `scheduleTodo` from a row button or a calendar drop creates one event through the normal create path. That is separate from the planner. The builds below do not replace it with an unattended create. ([TodoItem.tsx](src/renderer/src/components/TodoItem.tsx))

## 4. Gap table

Excluded on purpose: anything section 6 lists as shipped. ## 5. The top three builds

### 1. Put waiting mail and a confirmable day plan on Today

Ship the Today card and the urgency slice from the first two rows of the table together. Counts and blocks are already computed elsewhere. Today does not show them.

**Acceptance.** A fixture dashboard payload includes non-zero mail-watch counts for the shipped statuses and a planner result of two blocks with known titles. ## 6. Already shipped, so not a gap

The app note marks these as in the tree. They are not builds.

- **Recurring todos.** `repeat` is `{every, unit, mode}`. Completion spawns the next local row and clears `repeat` on the completed one. Google Tasks is not given a recurrence. That is the right split for the API in the market note. Do not add a repeat field to the Task body.
- **Reply tracking.** Statuses, the on-demand classifier, the Mail panel, dismiss-until-new-activity, and the explicit follow-up todo button are shipped. Automation is off on purpose: no background loop, `useLLM` hook left `None`, counts not drawn on Today. Section 4 keeps only the Today card, the draft button, and the optional polled job. It does not ask for a second tracker.
- **Proposal time-blocks.** `schedule_suggest`, `PlannerPanel`, and `POST /planner/apply` are shipped. Unpicked blocks are dropped. Blocks are not events until apply, and apply keeps only verified creates. Section 4’s “defended blocks” row is a later, confirmed move. It is not a second planner, and it does not auto-apply.
- **Outbox.** Hold 60–120 seconds, default 90, atomic claim, undo, send-now is not a tool, resume versus expire at 15 minutes, failed sends not retried, verification stored on the row.
- **Inbox proposals.** For `run.kind == "job"`, external and schedule tools are proposals. Accept runs once. Reject only while pending. An accepted `gmail_send` then enters the outbox. Calendar tools then hit `google.py` and the read-back. `calendar_propose` in a live chat is the overlay. From a job it is one proposal for the whole batch.

`docs/research/sota-pim.md`, as read by the app note, still describes recurrence, estimates, urgency, the planner, reply tracking, free/busy, thread reads, `updatedMin`, and Gmail history as missing. Those statements are stale against the working tree. A comparison that starts from that gap table will rebuild shipped work.
