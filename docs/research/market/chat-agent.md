# Chat and agent-loop market (as of 2026-10-02)

Scope: Claude (desktop / Cowork / Claude Code), ChatGPT (desktop, Projects, Work, Codex), Open WebUI, LibreChat, and Msty Studio. Mechanisms and user-visible behavior only. Claims dated before mid-2026 are marked possibly stale. This note does not audit Grain.

Products named below are comparison subjects. Example model names that appear inside vendor docs (for example GPT-6 Astra on ChatGPT’s Work page, or GPT-5.6 Sol in Open WebUI’s compare examples) are reported as what those pages say, not independently verified catalog facts.

## What do leading desktop and personal assistants ship for streaming chat, model choice, regenerate, branching, and multi-model compare?

### Takeaway

By October 2026 the hosted assistants have collapsed “chat” and “do the task” into one composer, while the local multi-model apps still treat the conversation as a tree you can fork and compare. Claude’s new unified experience explicitly does not offer branching from an earlier point. Open WebUI and Msty ship side-by-side multi-model compare; LibreChat ships a real fork with three copy modes; ChatGPT’s in-thread version switcher is contested in user reports.

### Cited Findings

**Claude desktop: one composer, model picker kept, in-chat branching removed**

- The unified Claude experience, rolling out gradually starting with Pro and Max on web, desktop, and mobile, merges Cowork and chat into one conversation. There is no mode to pick: a quick question and a longer task (research, files, code) happen in the same thread. Accounts that still see separate “Chat” and “Cowork” chips do not have it yet, and once an account moves over it cannot switch back. Chats, tasks, projects, and settings carry over. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)
- Several tasks can run at the same time. Cloud tasks keep running if the laptop is closed or the page is left; tasks that use local files, the browser, or the computer need Claude Desktop open. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)
- A message-box permission setting applies to the whole conversation: Auto (keeps working, with automated safety checks before actions) or Manual, the default (asks before each action). The user can stop or redirect while it works. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)
- After the merge, the model picker and the Code tab stay where they were. Web search is no longer a toggle; Claude searches when it helps. Research is `/deep-research` or “+” then “Research.” — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)
- Documented limitations of that new experience: “Branching a conversation from an earlier point isn’t available.” Incognito chats still open in the previous experience and cannot create files or run code. Search does not include older Cowork tasks. Add from GitHub is unsupported. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)
- Until the merge lands, desktop/web/mobile still start Cowork from a “Cowork” control in the message box and return to Chat the same way. Desktop is described as the full Cowork surface (local files and browser). — [Claude Help Center](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile)
- Indexed text of that same Cowork-surfaces article says that on 6 October 2026 new Cowork tasks on Pro and Max run in the cloud, and the “Only on your computer” option in Settings > General will be removed. This sentence was not re-read from a full page fetch. — [Claude Help Center](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile)
- Computer use is in beta for Pro and Max, in Cowork and Claude Code inside Claude Desktop on macOS and Windows. It clicks, types, and opens apps without taking the pointer or keyboard, generally waits if the user is typing, and asks before using an app. The desktop must be awake and the app open. Team and Enterprise do not have it. — [Claude Help Center](https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork)
- Claude Code’s `/model` lists models available to the account and switches mid-session without clearing the conversation. The help article refuses to pin exact model IDs and says `/model` is the source of truth. Rough guide on that page: Sonnet for most coding, Opus for harder reasoning (uses more quota), Haiku for fast cheap work. `/model opusplan` uses Opus while planning and Sonnet for execution. — [Claude Help Center](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code)

**ChatGPT: Chat vs Work, projects as parallel chats, regenerate UX in flux**

- ChatGPT’s own “use ChatGPT” doc splits surfaces: Chat for a question or back-and-forth; Work when the user wants a larger task carried through to a reviewable result; Codex for developer views. On the web, Work runs in a managed cloud environment. In the desktop app the user may choose Cloud (keeps going after the desktop app closes; continuable from web or mobile; uploaded files, connected tools, approved websites) or Work locally (files, apps, or the browser on the computer, when enabled). Progress is shown; it pauses for information or approval. — [ChatGPT Learn](https://learn.chatgpt.com/docs/use-chatgpt.md)
- Work getting-started (fetched 2026-10-02) tells the user to pick from the model selector and names GPT-6 Astra for demanding reasoning or polished files, GPT-6.1 Sol for complex work at lower cost than Astra, and Luna for simpler tasks. Longer tasks may use more credits. It also says to check plan usage before a large task. — [ChatGPT Learn](https://learn.chatgpt.com/docs/get-started-with-work)
- Projects in the desktop app hold both ChatGPT projects (uploaded files, instructions, connected sources shared across chats) and local projects (one or more folders the chats can read and change). Chat and ChatGPT Work both appear as chats in a project. The doc’s advice is one chat per outcome so messages stay focused while the project holds shared context, including parallel chats for research, drafting, review, and follow-up. — [ChatGPT Learn](https://learn.chatgpt.com/docs/projects)
- Local projects: multiple folders; one primary folder is the default working directory and the place Codex discovers `AGENTS.md`, skills, and `config.toml`. Secondary folders are searchable and editable but are not auto-discovered. Remote projects support one folder. Pinning a project or chat does not add context. Search chats can find a phrase or a branch name. — [ChatGPT Learn](https://learn.chatgpt.com/docs/projects)
- An OpenAI staff reply on the developer community (posted “Feb 27,” closed “Apr 20”; the fetched page does not show the year) says the current control is a “Try again” icon, and clicking it replaces the previous response rather than keeping multiple visible versions. There is no setting to restore the old multi-version regenerate. The suggested workaround is to send a new message that says “regenerate” so the earlier answer stays visible. — [OpenAI Developer Community](https://community.openai.com/t/where-are-options-for-choosing-better-answers-in-chatgpt/1375312)
- Later community reports contradict a clean “versions are gone” reading. A ChatGPT subreddit thread describes the inline `<1/n>` arrows disappearing while branches remained in exports, then a “Message Versions” menu. A developer-community follow-up says “See versions” shows historical edits, but continuing from one requires “Branch to a new chat,” which is not the same as switching versions inside the original thread. A separate Reddit post claims regenerate/edit erases other messages on desktop while arrows remained on the web for the same chat. These are user reports, not help-center spec, and their calendar dates were not confirmed in the fetched text. — [r/ChatGPT](https://www.reddit.com/r/ChatGPT/comments/1w19at5/new_message_selector/); [OpenAI Developer Community](https://community.openai.com/t/chatgpt-web-update-removed-message-version-arrows-cannot-access-edited-message-history/1374666/220); [r/OpenAI](https://www.reddit.com/r/OpenAI/comments/1sp6acy/psa_regenerating_a_response_or_editing_your/)
- OpenAI’s troubleshooting article still tells users who hit “There was an error generating a response” to click a “Regenerate” button, and if a reply hangs, to click “Stop generating” then “Regenerate.” That article may be older than the Try-again / See-versions threads; the page does not date the regenerate instruction. — [OpenAI Help Center](https://help.openai.com/en/articles/7996703-troubleshooting-chatgpt-error-messages)
- A long ChatGPT release-notes article describes a simplified model picker (Instant, Medium, High, Extra High, plus Pro Standard / Pro Extended) living in the composer on web and at the top of the conversation on iOS/Android, with an option for Instant to auto-switch to Medium. The fetched file is a multi-year changelog; the date of that specific picker change was not isolated, so treat the picker labels as possibly stale relative to the Work page’s GPT-6 Astra / Sol / Luna names. — [OpenAI Help Center](https://help.openai.com/en/articles/6825453-chatgpt-can-now-generate-images)

**Open WebUI: compare mode, per-model regenerate, merge**

- Official docs (live page fetched 2026-10-02): Compare mode is a Compare button in the model picker. The same prompt goes to two or more models at once. Responses render in parallel columns, or stacked on smaller screens. Admins can disable it per role/group (`Allow Multiple Models in Chat`) or with `USER_PERMISSIONS_CHAT_MULTIPLE_MODELS` (default true). If disabled, the Compare button is hidden. — [Open WebUI docs](https://docs.openwebui.com/features/chat-conversations/chat-features/multi-model-chats/)
- Merge (called Mixture of Agents in the docs) is a branch-shaped control whose tooltip is “Merge Responses.” It appears only on the last exchange, and only after every model has finished. The merge runs on the model whose response is being viewed, not on a separate Task Model, and uses a built-in prompt with no admin override. The merged answer is stored on the chat and can be created days later on a reopened conversation. The page marks merging experimental. Example models named on that page include GPT-5.6 Sol, Gemini 3.6 Flash, and Claude Sonnet 5. — [Open WebUI docs](https://docs.openwebui.com/features/chat-conversations/chat-features/multi-model-chats/)
- The docs site and the docs repo on GitHub disagree on the control: the live page says a Compare button; a `main` MDX snapshot in search results still described a “+” button in the model selector and, in one indexed copy, different example model names. Prefer the live docs page for current UI. — [Open WebUI docs](https://docs.openwebui.com/features/chat-conversations/chat-features/multi-model-chats/); [docs repo MDX](https://github.com/open-webui/docs/blob/main/docs/features/chat-conversations/chat-features/multi-model-chats.mdx)
- Client source (not a help article): `regenerateResponse` resends the parent user prompt. If that user message has a single model, it regenerates normally; if several models are selected, it passes `modelId` and `modelIdx` from the response being regenerated, so one column can be regenerated without rerunning the others. The multi-response UI also exposes previous/next message navigation per model. — [Chat.svelte](https://github.com/open-webui/open-webui/blob/53764fe6/src/lib/components/chat/Chat.svelte); [MultiResponseMessages.svelte](https://github.com/open-webui/open-webui/blob/ecd48e2f/src/lib/components/chat/Messages/MultiResponseMessages.svelte)

**LibreChat: edit, rerun as a sibling, fork with three copy modes**

- Message actions stay hidden while a response is still streaming and reveal on hover or keyboard focus. Edit offers Save (update in place, no new generation) or Update & rerun (new sibling response). Editing a user message and rerunning keeps its files, manually selected Skills, and quoted context. Structured assistant edits keep tool calls, errors, and artifacts visible but read-only; if more than one assistant part changes, the user must save without rerunning. Shortcuts: Ctrl/Cmd+S save, Ctrl/Cmd+Enter update and rerun, Escape cancel. — [LibreChat message actions](https://www.librechat.ai/docs/features/message_actions)
- Fork: hover a message, open its menu, fork icon. The message is the target. Options: “Visible messages only” (direct path, no side branches); “Include related branches” (direct path plus branches along that path); “Include all to/from here” (default: every message up to the target, including neighboring branches). “Start fork here” instead forks from the selected message forward to the latest message. “Remember” stores the choice; a settings default exists. The original chat is unchanged. — [LibreChat forking](https://www.librechat.ai/docs/features/fork)
- Shareable links publish a read-only view that keeps branches; signed-in viewers can continue the visible branch as a personal copy. Branch arrows on the shared view move between paths. — [LibreChat shareable links](https://www.librechat.ai/docs/features/shareable_links)
- Parameters for the current endpoint live in a side panel (Identity, Sampling, Limits, Reasoning, Context, Advanced, Misc). Headings show how many settings differ from default. Reset and Save As Preset are at the bottom. — [LibreChat settings](https://www.librechat.ai/docs/features/settings)

**Msty Studio: split panes, regenerate onto another model, edit-as-branch**

- Split Chat: “Add Split Chat” adds a pane. Splits turn on duplication mode so the typed message syncs across panes for side-by-side model comparison. A split can be deleted or hidden (history kept). Layouts save as named presets, including which prompts and attachments to keep. — [Msty Split Chat](https://docs.msty.ai/studio/conversations/split-chat)
- Per assistant message: Regenerate (new response; also the path when the user has changed the model and wants that model to answer the same prompt); Continue generation if the reply was cut off; Copy as Markdown, HTML, or formatted text. “Use as Prompt in New Split” opens an unsynced split whose first prompt is that message, without copying the whole path. “Edit as Branch” saves an alternative path without overwriting the original; Branch Explorer is the documented place to label, navigate, and compare branches. — [Msty responses](https://docs.msty.ai/studio/conversations/responses)
- Branch Explorer (docs page indexed, not fully re-fetched): branch dropdown on threads and the mini map; label a branch; side-by-side diff of two branches. — [Msty Branch Explorer](https://docs.msty.ai/studio/conversations/branch-explorer)
- Context controls that are not the same as delete: Context Shield drops prior conversation from what later turns can see, with an option to generate a summary one response at a time. Isolate Context excludes one response from later model context and is reversible. Hide removes a message from view but still includes it in context. Delete of the current message tries to reconnect the remaining path; “Delete Message and Descendants” removes the rest of that branch. — [Msty responses](https://docs.msty.ai/studio/conversations/responses)

**Streaming, narrowly**

- Claude Code’s Agent SDK emits live `StreamEvent` messages (text deltas, tool-input chunks) only when partial messages are enabled (`include_partial_messages` / `includePartialMessages`). Without that flag the loop still yields whole `AssistantMessage` objects after each model response. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- LibreChat’s context gauge updates from usage events during streaming. Copy is unavailable while a response is streaming so the clipboard is not filled with a partial. — [LibreChat token usage](https://www.librechat.ai/docs/configuration/token_usage); [LibreChat message actions](https://www.librechat.ai/docs/features/message_actions)
- OpenAI’s hang troubleshooting assumes a visible “Stop generating” control, which only makes sense if the reply is streaming or at least incrementally shown. It does not specify the transport. — [OpenAI Help Center](https://help.openai.com/en/articles/7996703-troubleshooting-chatgpt-error-messages)

### Inferences

- Hosted products are optimizing for “one thread, pick up on another device.” Local shells (Open WebUI, LibreChat, Msty) are optimizing for “many answers to the same prompt, and a tree you can walk.” A local Electron app that only has a linear transcript will look thin next to Msty and LibreChat even if its agent loop is strong, and thin next to Claude/ChatGPT if a run dies when the window closes.
- “Regenerate” is no longer one feature. It means replace-in-place (ChatGPT staff reply), sibling versions inside one thread (LibreChat rerun, Open WebUI per-model history, Msty regenerate), or “branch to a new chat” (ChatGPT community “See versions,” LibreChat fork, Claude Code `/branch`). Shipping only replace-in-place will match the ChatGPT staff description and miss what the local apps document as normal.
- Claude’s explicit “branching from an earlier point isn’t available” is a product choice in the new chat, not an oversight in the coding product. Claude Code still has `/branch` and `--fork-session`. Chat and code are not the same conversation model.

### Gaps

- No official 2026 help page was fetched that specifies Claude desktop or ChatGPT desktop token-streaming behavior (chunk protocol, reconnect, partial persistence). Stop/regenerate is documented; the stream itself is not.
- Open WebUI’s official docs fetched here cover compare and merge, not “clone this message into a new chat.” A third-party Mintlify mirror claims clone-at-message branching; that mirror was not treated as a primary source.
- ChatGPT in-thread version navigation is documented only by conflicting community threads plus one staff reply whose year is not on the page. There is no current help-center spec in this pass.
- Msty Branch Explorer was not fully fetched; the responses page confirms it exists and is for label, navigate, and compare.
- The ChatGPT release-notes model-picker section was not dated, so it should not be used as the October 2026 picker.

## How do their agent loops work: tool rounds, parallel calls, durable runs, resume after interruption, compaction, traces, and cost or token meters?

### Takeaway

The best-specified loop is Claude Code’s: a turn is “model response, then tool results, repeat until a response with no tool calls,” with read-only tools parallel, mutating tools serial, a hard turn cap and a USD cap, a compact-boundary event, and a session id that resumes with usage still attached on errors. LibreChat documents a similar step budget (default 25) plus mid-run steer at the next tool boundary. ChatGPT and Claude desktop document durability as “cloud keeps going, local needs the machine,” not as a transcript format. Token meters range from a plan usage screen (Claude chat) to a per-message tool inspector (Msty) to a context gauge that survives compaction (LibreChat).

### Cited Findings

**Claude Code loop (official SDK contract)**

- Cycle: receive prompt (plus system prompt, tool definitions, history) → model responds with text, tool calls, or both → SDK runs the tools and feeds results back → repeat until a response with no tool calls → `ResultMessage` with final text, token usage, cost, and session id. A “turn” is one of those round trips and does not yield control back to the caller. `max_turns` / `maxTurns` counts tool-use turns only. `max_budget_usd` / `maxBudgetUsd` stops on spend. Hitting either returns `error_max_turns` or `error_max_budget_usd`. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- Result subtypes also include `success`, `error_during_execution` (API failure or cancelled request), and `error_max_structured_output_retries`. All subtypes carry `total_cost_usd`, `usage`, `num_turns`, and `session_id` so cost and resume work after errors (Python types those cost fields as optional). `stop_reason` on the final turn includes `end_turn`, `max_tokens`, and `refusal`. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- Parallelism is by tool kind, not “all calls in the message.” Read-only tools (`Read`, `Glob`, `Grep`, and MCP tools marked read-only) may run concurrently. `Edit`, `Write`, and `Bash` run sequentially. Custom tools are sequential unless `readOnlyHint` is set. A denied tool comes back as a tool result and the model is expected to try another approach. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- Permission modes on the SDK: `default` (unlisted tools need an approval callback, otherwise deny), `acceptEdits`, `plan` (no source edits auto-approved), `dontAsk` (only pre-approved tools), `auto` (TypeScript only; a model classifier approves or denies), `bypassPermissions` (runs allowed tools unless an ask rule matches; not as root). — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- Context accumulates for the whole session (system prompt, tool schemas, history, tool inputs and outputs). Stable prefixes are prompt-cached. MCP tool schemas are deferred by default via tool search, except on Vertex or a non-first-party base URL. Subagents start a fresh conversation and only their final response returns to the parent, so the parent does not ingest the child transcript. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- Auto-compaction summarizes older history when the window is near its limit and emits `system` / `compact_boundary` (TypeScript: `SDKCompactBoundaryMessage`). Early instructions can be lost; persistent rules belong in CLAUDE.md because it is re-injected every request. Manual `/compact` is a prompt string. A `PreCompact` hook gets `trigger` `manual` or `auto` and can archive the full transcript before summarization. Compaction can be steered by a free-form CLAUDE.md section (preserve objective, paths, test results, decisions). — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- User-facing Claude Code commands: `/context` shows what is consuming context; `/compact [instructions]` replaces history with a summary; `/clear` starts empty context but saves the previous conversation for `/resume` or the rewind menu. Auto-compact is described as firing near the limit so users “rarely hit a hard wall.” `/cost` shows the session’s token and dollar usage for API-key billing. Enterprise-seat users see a limit-reached message with a reset time and no token meter until then. — [Claude Help Center](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code); [Manage sessions](https://code.claude.com/docs/en/sessions)
- What a turn actually sends, per the usage article: the conversation so far, project context (`CLAUDE.md` and files already read), and the new prompt. The conversation is what grows. Prompt caching makes later turns of a stable prefix cheaper, but the prefix still occupies the window. The article’s rule of thumb is `/clear` between tasks and `/compact` to continue a long task. `/clear` cannot be undone. — [Claude Help Center](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code)

**Claude Code sessions: resume, fork, what is not restored**

- Sessions are local transcripts. `claude --continue` resumes the latest interactive session in the directory; `claude --resume` opens a picker; `claude --resume <id-or-name>` resumes directly. `/resume` switches from inside a session. Sessions started with `claude -p` or the Agent SDK are omitted from the picker and from `--continue`, but can be resumed by session id. — [Manage sessions](https://code.claude.com/docs/en/sessions)
- A resumed session restores conversation history including tool calls and results, the model (unless retired, disallowed, overridden by flag/env, or a provider-specific deployment id), the agent definition if it can still be found, and permission mode only on some entry paths (plain terminal `--continue` / exact `--resume`, with exceptions for `bypassPermissions`, `plan`, and `auto`). Not restored unless passed again: `--mcp-config`, `--settings`, `--plugin-dir`, `--fallback-model`, and `--add-dir` directories. Background Bash and monitor tasks are not restored. An active goal carries over but its turn count, timer, and token-spend baseline reset. — [Manage sessions](https://code.claude.com/docs/en/sessions)
- Resume-from-summary dialog (Pro or Max): if the session has been inactive for more than about an hour and is over 100,000 tokens, the prompt cache has expired, so the next request processes the full history once no matter which option is chosen. Options: run `/compact` immediately (summary, most recent exchanges, and up to five recently read files); resume full history as-is; or don’t ask again. — [Manage sessions](https://code.claude.com/docs/en/sessions)
- `/branch [name]` copies the transcript and switches the process into the copy. In-flight background subagents and background Bash keep running, and their output lands in the new branch, not the original. “Allow for this session” grants carry over on `/branch` (same process) but not on `--fork-session` (new process). Remote Control follows the user into the branch. Resuming the same session in two terminals without forking interleaves both into one transcript. — [Manage sessions](https://code.claude.com/docs/en/sessions)
- `/export` writes a human-readable transcript. For scripts, `claude -p --output-format json` or `stream-json` returns result, session id, usage, and cost. Transcripts on disk are JSONL under `~/.claude/projects/`; the line format is internal and “changes between versions,” so the docs say not to parse it. Default retention is `cleanupPeriodDays` (described as the 30-day retention). `desktopSessionCleanupPeriodDays` is a separate age limit for Claude Desktop and Cowork transcripts. `--no-session-persistence` suppresses writes for one `claude -p` run. — [Manage sessions](https://code.claude.com/docs/en/sessions)
- Hooks that sit on the loop and do not themselves consume context: `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop`, `SubagentStart` / `SubagentStop`, `PreCompact`. A rejecting `PreToolUse` prevents execution and the model receives the rejection. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)

**Compaction and resume are not perfectly durable (user-reported bugs, not the contract)**

- GitHub issue: a multi-agent workflow resumed after auto-compaction restarted from phase 1 because compaction changed the session id, and the run journal lived under the old session directory. The consolidated journal is written only when the run completes; a paused run has incremental `journal.jsonl` only. This is a bug report, not documented behavior. — [claude-code#65796](https://github.com/anthropics/claude-code/issues/65796)
- GitHub issue: after resuming a compacted Opus 4.6 1M session, auto-compact did not fire again; a later comment reports the same on Opus 4.7 with a manual `/compact` that did work (preTokens 868123, postTokens 3628). Treat the token figures as the reporter’s measurements, and the bug as possibly fixed or still open; the issue was not re-checked for current status. — [claude-code#36751](https://github.com/anthropics/claude-code/issues/36751)
- An April 2026 paper (arXiv 2604.14228) describes five context shapers in Claude Code’s `query.ts` before each model call: budget reduction of oversized tool outputs, snip, microcompact, context collapse, then auto-compact as a last resort via `compactConversation()`. That is a reading of source, not Anthropic’s docs, and it is from April 2026, so it may be stale by October. — [paper PDF](https://www.rivista.ai/wp-content/uploads/2026/04/2604.14228v1.pdf)

**Claude chat / Cowork durability and the usage meter**

- Unified experience: longer agentic tasks (web search, code, files) count more toward plan limits than a quick question. Usage is in Settings > Usage. While the new experience rolls out, metering “may be measured slightly differently” for accounts that have it and accounts that do not. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)
- A dated promotion (1 October 2026 11:00 PT through 15 October 2026 23:59 PT) discounts the five-hour session limit by 50% after artifact create/edit, for Pro, Max, and Team, not Free or Enterprise, and not the weekly limit. In chat the discount covers the next 10 messages and only the first 15 steps of each reply. In cloud Cowork it covers about the first 45 minutes of a Document/Presentation/Design task, or up to the next 80 steps after an artifact edit in other tasks. Local desktop Cowork tasks are excluded. The step language is evidence that Cowork replies are metered in steps, not only in messages. — [Claude Help Center](https://support.claude.com/en/articles/17274727-artifact-usage-promotion)
- Phone check-in: a task started at the desk shows up in Claude Mobile, where the user can see progress, answer questions, and redirect. Scheduled tasks can run in the cloud with the computer off. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)

**ChatGPT Work, goals, and Codex cloud**

- Desktop Goal mode: type `/goal`. The goal text is both the first prompt and the completion criteria. A progress row above the composer can pause, resume, edit, or clear the goal. Follow-up messages can be sent while it runs. A side chat is for a status recap without interrupting the main chat. Pause before losing connectivity, then resume. Starting a goal does not widen the sandbox or approval policy. `/plan` is the documented way to interview toward a measurable goal first. — [ChatGPT Learn](https://learn.chatgpt.com/docs/long-running-work)
- Parallel goals are parallel chats, each with its own context, messages, results, and goal. The doc says not to let two chats change the same files, and to use worktrees for separate checkouts. Local work has a “Prevent sleep while running” setting. Notifications (Pets or system) fire when a chat needs input or is ready for review. — [ChatGPT Learn](https://learn.chatgpt.com/docs/long-running-work)
- Work + local computer access: if the computer is unavailable when a new turn starts, an eligible task can continue in a cloud container that cannot see that computer’s files or tools. Work cannot switch from local to cloud during a turn. Turning off local-computer access interrupts running turns; the continuation path is a new message in the existing cloud conversation, without local files. Existing tasks do not gain local-file access just because sync is enabled; the user starts a new task. — [ChatGPT Learn](https://learn.chatgpt.com/docs/get-started-with-work)
- Codex cloud (learn doc, from search index; page not fully fetched): each task has its own workspace and can keep working while the computer is asleep; continue from web, mobile, or desktop; review diffs and tests; follow up in the same task. — [ChatGPT Learn](https://learn.chatgpt.com/docs/cloud.md)
- Codex cloud help article (fetch returned 403; the following is the search excerpt of that URL): return to the original task to continue; a new task is a separate workspace and does not recover another task’s uncommitted changes; by default saved VM state is recoverable for up to 7 days after the last start of a turn or task resume, and that window is not a conversation-history retention period. — [OpenAI Help Center](https://help.openai.com/en/articles/20001545-using-codex-cloud)
- The ChatGPT agent help page is internally inconsistent. The overview, updated “18 days ago” relative to the 2026-10-02 fetch, says “ChatGPT agent is no longer available. Use ChatGPT Work.” The rest of the same page still documents `/agent`, monthly message caps (Plus 40, Pro 400, Business & Enterprise 40), pause for confirmation, interrupt mid-task, takeover of the virtual browser, and screenshot retention until the chat is deleted (then within 90 days). Treat the banner as the current status and the body as leftover spec, possibly stale. — [OpenAI Help Center](https://help.openai.com/en/articles/11752874-chatgpt-agent)
- Codex-managed git worktrees: one chat typically maps to one disposable worktree in a detached HEAD; the most recent 15 are kept by default; a snapshot is saved before deletion and a reopened chat can restore it. Permanent worktrees are a separate project and are not auto-deleted. This is environment branching, not message branching. — [ChatGPT Learn](https://learn.chatgpt.com/docs/environments/git-worktrees)

**LibreChat agent loop, steer, compaction accounting, meters**

- Max Agent Steps defaults to 25 if unset, with an admin global default and global maximum in `librechat.yaml`. A step is either an API request or a round of tool usage. The docs’ accounting for one tool round is usually 3 steps: API request, tool usage (one or many tools from that request), follow-up API request. A text-only response is 1 step. — [LibreChat agents](https://www.librechat.ai/docs/features/agents)
- Subagents: the parent delegates with a tool call; the child has its own context window and tool loop and returns a compact result so intermediate steps do not fill the parent. This is distinct from Agent Chain, a beta mixture-of-agents sequence of up to 10 agents where each layer sees the previous layer’s outputs. — [LibreChat agents](https://www.librechat.ai/docs/features/agents)
- Deferred tools: MCP tools marked deferred stay out of the initial context; a `ToolSearch` tool loads them on demand for the rest of the conversation. `deferred_tools` is on by default. — [LibreChat agents](https://www.librechat.ai/docs/features/agents)
- Programmatic tool calling (opt-in): selected MCP tools run from inside the Code Interpreter sandbox. The model writes code that calls generated tool functions and can loop, branch, retry, and transform results before answering. Unregistered tool calls from the sandbox are rejected. Requires `programmatic_tools`, `execute_code`, and a Code Interpreter deployment with a Tool Call Server. — [LibreChat agents](https://www.librechat.ai/docs/features/agents)
- Steering (documented in the docs repo on `main`, and named from the published message-actions page; the published agents page fetched the same day did not include this section): Steer inserts the message at the next tool or agent step. Queue holds it for a normal follow-up after the response completes. Interrupt & steer stops at the next provider-safe boundary, keeps the partial response, inserts the message, and resumes the same assistant response (Ctrl/Cmd+Shift+.). If the deployment cannot interrupt the provider stream, it falls back to ordinary steering. One run accepts up to 10 pending steers; each can include up to 10 files, length-capped by `STEER_MAX_LENGTH`. Settings → Chat chooses what Enter does while generating. — [agents.mdx on main](https://github.com/LibreChat-AI/librechat.ai/blob/main/content/docs/features/agents.mdx); [message actions](https://www.librechat.ai/docs/features/message_actions)
- Quoted excerpts (up to 10 per message, 1,500 characters each) stay attached to Steer, Queue, and Interrupt & steer across reconnects. On a current server, an ordinary queued follow-up keeps its quotes through app restarts and replica handoffs. If an older replica cannot accept them, they return to the composer instead of being dropped. Manually selected Skills are not injected mid-run; they wait for the next full turn. — [LibreChat message actions](https://www.librechat.ai/docs/features/message_actions)
- The PR that added steering describes the server shape: `POST /api/agents/chat/steer`, a job-store queue (Redis or in-memory), drain at a `PostToolBatch` boundary, rejection codes `NO_ACTIVE_RUN`, `RUN_PAUSED`, `STEER_UNSUPPORTED`, `STEER_QUEUE_FULL`. That is implementation notes, useful as a design sketch, not a stability guarantee. — [LibreChat PR 14220](https://github.com/danny-avila/LibreChat/pull/14220)
- Context meter: a gauge during the conversation, fed by streaming usage events. It can show prompt/context against the window, a color-coded split, and a breakdown for dialogue, retained tool results, agent instructions, cached input, completions, branch totals, and conversation totals, plus per-tool disclosures and a runway estimate when consecutive snapshots match. Deferred tool definitions are hatched. The breakdown is collapsed by default and the expand choice is remembered. After summarization, the gauge counts only post-summary turns on top of the summary baseline, while usage and cost totals still include the full branch spend. Reopened chats keep branch and total usage. Subagent totals are labeled as covering all branches. Admins can show cost with `interface.contextCost` (default hidden) and optionally convert displayed USD with a static currency rate. — [LibreChat token usage](https://www.librechat.ai/docs/configuration/token_usage)
- Balance checks (when enabled) look at prompt tokens and allow a completion-token deficit. Plugins are checked at each generation step because a turn is multiple API calls. With summarization on, a request is blocked if summarizing plus the message payload would exceed the balance. Subagent child-run usage is recorded on the parent transaction. — [LibreChat token usage](https://www.librechat.ai/docs/configuration/token_usage)
- Admins can open a Langfuse session link from the usage breakdown when the conversation has a sampled trace. That is the only first-party “trace viewer” mention found for LibreChat in this pass. — [LibreChat token usage](https://www.librechat.ai/docs/configuration/token_usage)

**Msty: per-message tool traces, scripted queues, not a hidden agent loop**

- Response Metrics: estimated input and output tokens, latency, and if tools were used, which tools. “View Tools Usage” shows tool name, input, and output. These actions sit in the additional-actions menu, not on the primary action row. — [Msty responses](https://docs.msty.ai/studio/conversations/responses)
- Turnstiles (Aurum license) are user-authored queues, not a model-driven loop. Entry types: Prompt (optional model, attachments, toolsets), Persona, meta actions (Continue, Regenerate, Context Shield, Context Shield with Summary), Conditional on assistant or user output, Loop Start/End with max iterations and optional early exit, and Checkpoint (pause for review, variable edit, and manual routing: continue, skip next N, jump to a label, abort). Queue-level errors: Stop, Retry Once, or Use Fallback Model, overridable per step. Run controls: Run, Pause, Continue, Stop, plus Rounds to repeat the whole queue. Separator commands in chat text include `--m--`, `--r--`, `--c--`, `--cs--`, `--css--`. — [Msty Turnstiles](https://docs.msty.ai/studio/add-ons/turnstiles)

**Open WebUI traces**

- No official Open WebUI page fetched in this pass documents a built-in tool-call trace or token meter comparable to LibreChat’s gauge or Msty’s View Tools Usage.
- A third-party filter, LLMTrace, appends a diagnostic panel: model id, parameters, tool name and category, round-trip count, reasoning blocks, streaming chunk counts, TTFT, and duration. That is an extension, not the product. — [LLMTrace README](https://github.com/FAI-Solutions/open-webui-extensions/blob/main/llmtrace/README.md)
- A maintainer discussion shows pipelines are expected to emit tool-call UI somehow, and users report empty tool-call blocks; the thread does not establish a stable public contract. — [open-webui discussion 24472](https://github.com/open-webui/open-webui/discussions/24472)

### Inferences

- “Durable run” in 2026 hosted products means a server-side workspace that outlives the desktop process, with an explicit ban on switching local and cloud in the middle of a turn. “Resume” in Claude Code means reload a local transcript and keep going, with a separate, lossy compact step when the cache is cold or the window is full. A local Electron + FastAPI app can copy the second without a cloud VM; it cannot honestly claim the first unless a run continues after the Electron process exits.
- Parallel tool calls are documented as safe only for read-only work. A loop that parallelizes writes will be ahead of the published Claude contract and will need its own locking story.
- The meter users can actually read is not one number. LibreChat separates “what is in the window now” from “what this branch has spent,” and keeps the spend total across compaction. Claude Code’s `/cost` is session spend for API keys, while chat Claude is a plan window in Settings. Copying only a single context-percent bar drops the distinction these docs treat as the point of the meter.
- Mid-run steer (LibreChat) and a goal pause row (ChatGPT desktop) are the two documented ways to interrupt without discarding the partial. They are different: steer injects a user message into the live tool loop; pause freezes a goal the model is still trying to satisfy.

### Gaps

- Codex cloud’s 7-day VM recovery figure comes from a search excerpt; the help URL returned 403 on fetch. Do not treat the number as re-verified.
- No official trace schema was fetched for Claude desktop Cowork or ChatGPT Work (what the user sees for each tool call, whether args are expandable, whether that UI survives reload).
- Claude Code checkpoint/rewind is named from the sessions page (“see Checkpointing”) but that page was not fetched.
- Open WebUI’s native tool-round and compaction behavior is not in the docs fetched here.
- The April 2026 five-shaper compaction paper may not match October Claude Code.
- The ChatGPT agent article’s monthly caps and `/agent` flow should not be cited as current product behavior; the same page says the feature is gone.

## What do users and official docs treat as table stakes versus differentiators in 2026?

### Takeaway

Official docs present streaming-with-stop, a model or effort picker, persistent chats, a tool loop that pauses for approval, and some usage readout as the ordinary controls. What they still explain at length — and what disappears loudly when vendors remove it — is in-thread branching, side-by-side models, a run that survives closing the app, compaction that does not silently restart work, and a meter that separates context from spend.

### Cited Findings

**Treated as ordinary (documented as controls, not as launches)**

- Switch model without clearing the thread (Claude Code `/model`; Msty regenerate after a model change; LibreChat per-conversation parameters and presets). — [Claude Help Center](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code); [Msty responses](https://docs.msty.ai/studio/conversations/responses); [LibreChat settings](https://www.librechat.ai/docs/features/settings)
- Stop a generation and try again. OpenAI’s troubleshooting still names Stop generating and Regenerate. LibreChat hides message actions until the stream settles, which assumes a stream. — [OpenAI Help Center](https://help.openai.com/en/articles/7996703-troubleshooting-chatgpt-error-messages); [LibreChat message actions](https://www.librechat.ai/docs/features/message_actions)
- Ask before consequential actions, and allow a more autonomous mode. Claude: Manual default vs Auto. Claude Code: `default` vs `acceptEdits` / `plan` / `bypassPermissions`. ChatGPT Work: pauses for information or approval; a goal does not widen that policy. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude); [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop); [ChatGPT Learn](https://learn.chatgpt.com/docs/long-running-work)
- Shared instructions and files across related chats (Claude Projects; ChatGPT projects; LibreChat agent instructions). Pinning is explicitly not context. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude); [ChatGPT Learn](https://learn.chatgpt.com/docs/projects)
- A visible usage ceiling. Claude chat: Settings > Usage, and a five-hour session limit distinct from a weekly limit (the promotion page). Claude Code API keys: `/cost`. LibreChat: context gauge, optional cost, optional balance. ChatGPT Work: “check plan usage” and credits that scale with task length. — [Claude usage promotion](https://support.claude.com/en/articles/17274727-artifact-usage-promotion); [Claude Code usage](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code); [LibreChat token usage](https://www.librechat.ai/docs/configuration/token_usage); [ChatGPT Work](https://learn.chatgpt.com/docs/get-started-with-work)
- Tool use inside the same turn until the model stops calling tools, with a step or turn cap (Claude `maxTurns`; LibreChat default 25 steps; Cowork discount counted in “steps” of a reply). — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop); [LibreChat agents](https://www.librechat.ai/docs/features/agents); [Claude usage promotion](https://support.claude.com/en/articles/17274727-artifact-usage-promotion)

**Treated as differentiators (explained as product behavior, or mourned when removed)**

- Conversation branching from an earlier message. Claude’s new chat lists its absence as a current limitation. LibreChat documents three fork copy modes. Msty documents edit-as-branch plus a diff explorer. ChatGPT users describe losing in-thread arrows as a broken workflow even after “See versions” and “Branch to a new chat” appeared. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude); [LibreChat forking](https://www.librechat.ai/docs/features/fork); [Msty responses](https://docs.msty.ai/studio/conversations/responses); [OpenAI Developer Community](https://community.openai.com/t/chatgpt-web-update-removed-message-version-arrows-cannot-access-edited-message-history/1374666/220)
- Multi-model compare in one send. Open WebUI documents it as a permissioned feature with a merge step. Msty documents split panes and presets. Neither Claude’s unified article nor ChatGPT’s Work/projects docs describe sending one prompt to several models at once. — [Open WebUI docs](https://docs.openwebui.com/features/chat-conversations/chat-features/multi-model-chats/); [Msty Split Chat](https://docs.msty.ai/studio/conversations/split-chat)
- A run that continues with the app or computer closed, versus one that needs the desktop open for local files. Both Claude and ChatGPT document this split, and both forbid silently moving a local turn into the cloud mid-turn. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude); [ChatGPT Work](https://learn.chatgpt.com/docs/get-started-with-work)
- Steering a live tool loop without waiting for the final answer (LibreChat) versus pausing a goal from a progress row (ChatGPT desktop) versus stop-and-redirect in Claude’s unified composer. These are three different interrupt models, each documented. — [agents.mdx](https://github.com/LibreChat-AI/librechat.ai/blob/main/content/docs/features/agents.mdx); [ChatGPT long-running work](https://learn.chatgpt.com/docs/long-running-work); [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)
- Compaction as a user-visible, instructable operation (`/compact`, compact boundary event, LibreChat gauge baseline vs lifetime spend) rather than an invisible truncation. Users file bugs when resume after compact re-runs finished work or stops compacting. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop); [LibreChat token usage](https://www.librechat.ai/docs/configuration/token_usage); [claude-code#65796](https://github.com/anthropics/claude-code/issues/65796)
- Per-message tool name, input, and output (Msty), and a context breakdown that isolates retained tool results (LibreChat). Claude Code exposes the same facts as a message stream and `/context`, aimed at developers more than at a chat bubble. — [Msty responses](https://docs.msty.ai/studio/conversations/responses); [LibreChat token usage](https://www.librechat.ai/docs/configuration/token_usage); [Manage sessions](https://code.claude.com/docs/en/sessions)
- Context Shield / isolate-one-message (Msty) is a manual alternative to semantic summary. It is documented as its own control, including inside Turnstile steps. — [Msty responses](https://docs.msty.ai/studio/conversations/responses); [Msty Turnstiles](https://docs.msty.ai/studio/add-ons/turnstiles)
- Subagent context isolation (child transcript stays out of the parent) is documented for both Claude Code and LibreChat. That is a differentiator against a single growing transcript. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop); [LibreChat agents](https://www.librechat.ai/docs/features/agents)

**User reaction that is actually sourced**

- The sourced complaints found in this pass are about ChatGPT’s regenerate/version UI: people used multiple saved answers per turn, then “Try again” replaced the previous answer, then a versions menu required branching to a new chat to continue. Official support said there is no setting to restore the old behavior. — [OpenAI Developer Community](https://community.openai.com/t/where-are-options-for-choosing-better-answers-in-chatgpt/1375312); [OpenAI Developer Community](https://community.openai.com/t/chatgpt-web-update-removed-message-version-arrows-cannot-access-edited-message-history/1374666/220)
- No 2026 survey or help-center “what’s table stakes” article was found. The table-stakes list above is inferred from what docs present as default controls.

### Inferences

- If a control is in the composer or on every message (model, stop, copy, retry) it is table stakes. If a vendor writes a limitation that the control is missing (Claude: no branch from an earlier point) or a permission flag to turn it off (Open WebUI multi-model), it is still a recognized feature, just not universal.
- Hosted assistants are spending their differentiation on durability and delegation (cloud tasks, goals, schedules, permission Auto). Local multi-provider apps are spending it on comparison and transcript control (splits, forks, shields, tool inspectors). A personal desktop app is compared to both groups.

### Gaps

- No broad 2026 user-review corpus was collected (app-store reviews, large Reddit samples). Sentiment here is a handful of threads about one ChatGPT UI change.
- “Table stakes” is not a phrase these docs use. The split above is an inference from documentation depth and from one regression complaint.
- Pricing and exact model SKUs move fast (Claude’s usage article says `/model` is the source of truth; ChatGPT’s Work page and its release notes name different picker labels). Do not freeze a model list from this note.

## Which mechanisms are documented well enough to copy the idea (not the code) into a local Electron plus FastAPI app?

### Takeaway

Four designs are specified clearly enough to reimplement locally: Claude Code’s turn loop with parallel-read / serial-write, budgets, and compact events; LibreChat’s step math, fork copy modes, context-versus-spend meter, and steer-at-tool-boundary; ChatGPT’s goal row plus the rule that a turn does not migrate between local and cloud; and Msty/Open WebUI’s compare, per-target regenerate, and per-message tool inspector. Session file formats and hosted VM recovery are not copyable from public docs.

### Cited Findings

**Copyable from Claude Code’s published loop**

- Store each run as a session id. Stream three visible event classes: assistant output (text and tool-call requests), tool results, and a terminal result that always includes usage, cost, turn count, and session id even on `error_max_turns`, `error_max_budget_usd`, or `error_during_execution`. Offer `stop_reason` of at least end-of-turn, max output tokens, and refusal. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- Cap tool-use rounds and USD separately. A cap ends the run; it does not discard the session id. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- In one model message, run read-only tools concurrently and state-changing tools one at a time. Surface a denial as a tool result so the model can recover inside the same run. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- Compaction is a modeled event, not a silent splice: summarize older turns, keep recent turns, emit a boundary the UI can show, let the user pass focus instructions, and run a pre-hook that can archive the full transcript. Re-inject standing instructions every request so they survive the summary. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- Resume reloads history, tool calls, and the model, and is explicit about what it does not reload (MCP config, extra directories, background shell tasks). After a long idle period over a large transcript, ask whether to compact before the next full-price request, because the cache is cold either way. The published thresholds are “about an hour” and “over 100,000 tokens” on Pro/Max; a local app can use its own thresholds. — [Manage sessions](https://code.claude.com/docs/en/sessions)
- Fork copies history up to now into a new session id and leaves the original intact. Do not append two live clients to one transcript. — [Manage sessions](https://code.claude.com/docs/en/sessions)
- Subagents: fresh context, only the final text returns to the parent. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- Partial token streaming is a flag on top of the turn messages, not a different loop. — [Claude Code agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- Do not parse Claude’s on-disk JSONL. The docs say the format changes between versions. Copy the event model, not the file. — [Manage sessions](https://code.claude.com/docs/en/sessions)

**Copyable from LibreChat**

- Count a text reply as one step and a tool round as request + tool batch + follow-up request. Default cap in the mid-twenties, overridable. One model message may contain many tool calls and still be one tool step. — [LibreChat agents](https://www.librechat.ai/docs/features/agents)
- Edit in place versus rerun-as-sibling are different buttons. Rerun keeps attachments and quoted excerpts. — [LibreChat message actions](https://www.librechat.ai/docs/features/message_actions)
- Fork dialog with three explicit histories: visible path only, path plus branches on that path, or everything up to this depth. Remember the user’s default. — [LibreChat forking](https://www.librechat.ai/docs/features/fork)
- While a run is in progress, three composer outcomes: inject at the next tool-batch boundary, queue for after the run, or interrupt at a provider-safe boundary, keep the partial assistant text, and continue that same response. Cap the pending inject queue. If interrupt is unavailable, fall back to inject-at-boundary rather than dropping the message. Quotes survive reconnect; if the server cannot accept them, return them to the composer. — [agents.mdx](https://github.com/LibreChat-AI/librechat.ai/blob/main/content/docs/features/agents.mdx); [message actions](https://www.librechat.ai/docs/features/message_actions)
- Meter two series: current window (after a summary, only the summary plus later turns) and lifetime spend of the branch (includes pre-summary turns and labeled subagent totals). Show retained tool results as their own slice. Hide dollar cost unless enabled. Persist the breakdown on the message so a reopened chat still has it. — [LibreChat token usage](https://www.librechat.ai/docs/configuration/token_usage)
- Load tool schemas on demand when the catalog is large, instead of putting every MCP schema in the first request. — [LibreChat agents](https://www.librechat.ai/docs/features/agents)

**Copyable from ChatGPT desktop / Work**

- A goal is a completion criterion pinned above the composer, with pause, resume, edit, and clear, plus ordinary follow-up messages while it runs. A second chat can ask for status without injecting into the run. Pause before disconnect. — [ChatGPT Learn](https://learn.chatgpt.com/docs/long-running-work)
- Parallel work is parallel chats. Do not give two chats write access to the same files. Worktrees are the documented isolation for code. — [ChatGPT Learn](https://learn.chatgpt.com/docs/long-running-work); [git worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees)
- If a task uses the local machine, do not migrate that turn to a machine-less runner. The next turn may continue without local files, and the UI should say so. A new task does not inherit another task’s uncommitted workspace. — [ChatGPT Work](https://learn.chatgpt.com/docs/get-started-with-work); [Codex cloud excerpt](https://help.openai.com/en/articles/20001545-using-codex-cloud)
- Projects share files and instructions; each outcome is its own chat. — [ChatGPT Learn](https://learn.chatgpt.com/docs/projects)

**Copyable from Open WebUI and Msty**

- Compare mode: one user message, N model columns, regenerate one column by resending the parent prompt with that column’s model id. Merge only when every column has finished, only on the latest exchange, using one of the models already in the comparison, and store the merged text on the chat. — [Open WebUI docs](https://docs.openwebui.com/features/chat-conversations/chat-features/multi-model-chats/); [Chat.svelte](https://github.com/open-webui/open-webui/blob/53764fe6/src/lib/components/chat/Chat.svelte)
- Split panes with a synced composer, savable layout presets, and “try this one message in a new unsynced pane” without copying the path. — [Msty Split Chat](https://docs.msty.ai/studio/conversations/split-chat); [Msty responses](https://docs.msty.ai/studio/conversations/responses)
- On each assistant message: regenerate, continue a truncated completion, estimated input/output tokens, latency, and tool name plus input plus output. — [Msty responses](https://docs.msty.ai/studio/conversations/responses)
- Manual context edits that are not compaction: drop all prior context (optional summary), or exclude one message from later requests while keeping it visible. Hide (still in context) is different from delete (reconnect the path, or delete descendants). — [Msty responses](https://docs.msty.ai/studio/conversations/responses)
- A user-built queue (prompt, regenerate, continue, shield, conditional, loop, checkpoint, fallback model, pause/continue) is a separate feature from the model’s own tool loop. Documented completely enough to copy as a macro runner beside chat. — [Msty Turnstiles](https://docs.msty.ai/studio/add-ons/turnstiles)

**Claude chat ideas that are specified as behavior, not as an API**

- One composer for questions and multi-step work. Permission is a conversation-level Auto vs Manual, changeable mid-task, with stop and redirect always available. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)
- Local capabilities (folders, built-in browser, computer use) are unavailable when the desktop app is not open; cloud work is. Say which one a task is. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)
- Do not pretend in-thread branching exists if it does not. Claude documents the absence. — [Claude Help Center](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)

### Inferences

- The smallest local design that matches what these docs make concrete: a FastAPI run that streams assistant, tool, and result events over SSE; SQLite (or JSONL you own) keyed by session id; read-only tools gathered and awaited together; writes awaited one by one; `max_rounds` and a token or dollar budget on the result event; a compact endpoint that writes a boundary message and a pre-compact archive; fork as a new session id with a copied prefix; a context gauge that resets its numerator on compact and a spend total that does not.
- Electron’s job is the controls those events already imply: stop, pause/resume, model picker that does not clear history, per-message regenerate-as-sibling, optional compare columns, and an expander for tool name/input/output. None of that requires a hosted VM.
- Steer-at-boundary is the one interrupt model that fits a single FastAPI loop without a second “goal interpreter”: the client POSTs a steer, the server holds it until the current tool batch finishes, then appends it as a user message and continues the same run. Interrupt-and-keep-partial is the same with an abort of the provider stream first.
- Copying ChatGPT/Claude cloud continuity means a run worker that is not the Electron process. The docs are clear about the failure mode to avoid: flipping a local-file turn onto a worker that cannot see those files.

### Gaps

- No public schema for Cowork or ChatGPT Work tool-trace UI, so “show the tool card like they do” is not specified beyond Msty’s name/input/output and LibreChat’s retained-tool-result bucket.
- Checkpointing inside Claude Code (rewind code and conversation) is referenced but the page was not read.
- Open WebUI compaction, resume-after-crash, and native tool traces are not documented in the pages fetched.
- Hosted schedule/recurrence is named (Claude scheduled tasks, ChatGPT schedules) but the scheduler contract was not fetched, so it is a weak copy target compared with the loop itself.
- LibreChat’s published agents page and its `main` docs source disagree on whether steering is in the rendered article. The behavior is specified in the docs source and alluded to in published message actions; confirm against a running build before treating every steer detail as shipped.
