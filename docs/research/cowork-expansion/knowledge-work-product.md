## 1. What Cowork gives the agent

Sources: https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork ; https://support.claude.com/en/articles/13364135-use-claude-cowork-safely ; https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile ; https://claude.com/product/cowork ; https://claude.com/docs/cowork/changelog ; https://support.claude.com/en/articles/12138966-release-notes ; https://claude.com/blog/dispatch-and-computer-use

- Folder model (V/S): user connects specific folders in Claude Desktop; reads/writes limited to them. Help text recommends a dedicated working folder rather than broad access. Changelog: `allowedWorkspaceFolders` policy, `blockReadsOutsideWorkingDirectories`, home-folder attach excluding sensitive credentials (v1.46388.x, Sep 2026). Per-folder "folder instructions" (Claude may update them itself) plus "global instructions" in Settings > Cowork (S).
- Sandbox: originally a local VM on the user's machine (S, PromptArmor https://www.promptarmor.com/resources/implement-claude-cowork-securely). By July 2026 there are local AND cloud sessions; cloud runs in "an isolated, temporary environment on Anthropic's servers ... deleted after each session"; cloud sessions fetch copies of specific files, deleted at session end (S). One fetch says Pro/Max move to cloud-only on Oct 6 2026 (S, unverified; do not rely on it).
- Network egress: VM egress setting "Package Managers Only" or custom additional allowed domains (`coworkEgressAllowedHosts`). Egress rules do NOT apply to web fetch, web search or MCPs (V). Computer use bypasses the sandbox, so egress rules do not constrain it (S).
- Deliverables: files appear in the session for preview/download (xlsx with working formulas, pptx, docx, pdf). Files pane with search, inline video playback (Sep 2026 changelog). Artifacts (live HTML) shared with chat.
- Connectors/MCP: Google Workspace, M365, Slack, GitHub etc. Three approval modes: Manual / Automatically approve (self-check before executing) / Skip all approvals. Admin can disable per-tool "Always allow"; `mcpToolTimeoutSec` default 180; scheduled-task approvals expire (`mcpScheduledTaskApprovalLifetimeDays`).
- Plugins: bundle skills + connectors + sub-agents; marketplace with admin controls (Feb 24 2026). Skills: /docx /pdf /pptx /xlsx are built-in slash skills; account skills synced at session start, also in scheduled sessions.
- Browser: built-in browser pane (own profile, independent of the user's logins) plus Claude in Chrome (user's real browser, own sign-ins). `builtinBrowserEnabled` + domain policies. Anthropic cites ~1% attack success on Chrome after mitigations (S, PromptArmor).
- Computer use (Mar 23 2026): connector-first, then browser, then screen. Tiered by app category: browsers/trading apps view-only, terminals/IDEs click-only, rest full; shell-equivalent apps (Terminal, VS Code), Finder, System Settings flagged at approval; approvals per session; one session holds a global lock; other apps hidden while working; Esc aborts globally and the keypress is consumed so injected content can't dismiss dialogs; the agent's own terminal is excluded from screenshots (V, https://code.claude.com/docs/en/computer-use). Claude picks the most precise tool first: MCP > Bash > Chrome > screen (V).
- Scheduled tasks (Feb 25 2026): recurring or on-demand; cloud-run so no device needed unless local files are touched; auto-retry at 5/15/30 min if device unreachable; auto-approve by default where org allows.
- Parallelism: Claude "breaks complex work into smaller tasks and coordinates parallel workstreams"; plan shown before execution; steer mid-task from any device; clarifying questions mid-run (S).
- Dispatch (Mar 2026): one persistent conversation that runs on the user's computer, messaged from phone; spawned sessions can use computer use. Mobile notification when a task completes or needs input.
- Memory/projects: projects shared across chat+Cowork (Jul 7 2026); memory toggle in "+" menu. Org instructions up to 3,000 chars appended to the system prompt.
- Audit gap: Cowork activity not in Audit Logs/Compliance API (S, PromptArmor).

## 2. Built-in tool inventory (Claude Code / Agent SDK)
Sources (V): https://code.claude.com/docs/en/tools-reference ; https://code.claude.com/docs/en/permission-modes ; https://code.claude.com/docs/en/sandboxing ; https://code.claude.com/docs/en/sub-agents ; https://code.claude.com/docs/en/hooks ; https://code.claude.com/docs/en/agent-sdk/todo-tracking

Full list: Agent, Artifact, AskUserQuestion, Bash, CronCreate/CronDelete/CronList, Edit, EndConversation, EnterPlanMode/ExitPlanMode, EnterWorktree/ExitWorktree, Glob, Grep, ListAgents, ListMcpResourcesTool/ReadMcpResourceTool, LSP, Monitor, NotebookEdit, PowerShell, PushNotification, Read, RemoteTrigger, ReportFindings, ScheduleWakeup, SendFeedback, SendMessage, SendUserFile, Skill, SubagentHandback, TaskCreate/TaskGet/TaskList/TaskUpdate/TaskStop/TaskOutput, TodoWrite, ToolSearch, WaitForMcpServers, WebFetch, WebSearch, Workflow, Write.

Per-tool details worth copying:
- Read: absolute paths; line-numbered; whole-file over token limit returns first page with `PARTIAL view` notice + how to use `offset`/`limit`; explicit limit too big errors early ("use smaller limit or Grep"); images returned visually (resized; >500KB re-encoded JPEG); PDFs >10 pages need `pages:"1-5"`, max 20 pages/request (pdftoppm); ipynb returns cells+outputs, refuses >100MB; empty-file and past-EOF notices; directories not readable.
- Edit: exact `old_string`/`new_string`, `replace_all`; three checks: read-before-edit (a PARTIAL view doesn't count; newer models may skip), exact match, uniqueness. A stale file is still editable if old_string matches current content uniquely; result notes the file changed. Viewing via cat/head/sed -n/grep counts as read.
- Write: full overwrite only; read required for existing files for older models and always for notebooks/partial reads.
- NotebookEdit: `cell_id`, mode replace|insert|delete, `cell_type` required on insert.
- Glob: mtime-sorted, cap 100 files with truncation flag; ignores .gitignore by default. Grep (ripgrep): modes files_with_matches (default)/content/count; `glob`, `type`, `multiline`, `head_limit`, `offset`; count total covers all matches even when listing truncated; rejected regex returns rg diagnostic; honors .gitignore. On mac/Linux Glob/Grep are off by default and the shell embeds bfs/ugrep.
- Bash: separate process per command; cwd persists only inside project/additional dirs else reset with "Shell cwd was reset" appended; env vars don't persist; default timeout 2 min, max 10 min; output spooled to a file (kill at 5 GB); inline limit ~30,000 chars (failure ~10,000 head+tail); larger valid output returned as file path + 2,000-char preview, truncated at 64 MiB; benign exit-1 allowlist (grep, rg, find, diff, test, git diff). `run_in_background:true`: 30 min default, 2 h max; on foreground timeout auto-moves to background (not for `sleep`), result states task id + output file; background `cd` doesn't leak. A stop notice tells the model why a background cmd died.
- Monitor: background script whose stdout lines become events; deadline 5 min default, 30 min max; WebSocket source (`ws` input; text msgs = events, >1 MiB ends watch); same permission rules as Bash.
- WebFetch: URL + extraction prompt run through a separate small model (lossy by design; curl for raw); refuses localhost/dotless hosts; http upgraded to https; 15-min cache; 5-min deadline; cross-host redirects returned as text, not followed; `Accept` prefers markdown; UA `Claude-User`; permission `WebFetch(domain:x)`; domain safety check before fetch. WebSearch: up to 8 backend searches per call; `allowed_domains` xor `blocked_domains`; session cap 200 across all subagents (cap notice says "continue with what you have", not an error that invites retry).
- AskUserQuestion: multiple choice + "Other"/notes; open indefinitely by default; optional `askUserQuestionTimeout` 60s/5m/10m auto-closes, submits any selections and tells the model the user may be away so it proceeds on its own judgement; plan approval never auto-resolves.
- Task tools (TaskCreate{subject, activeForm, description}, TaskUpdate{taskId, status pending|in_progress|completed|deleted, dependencies}, TaskList, TaskGet): on by default only for older/smaller models (Claude 3.x, Opus<=4.7, Sonnet<=4.6, Haiku 4.5), off for the newest because they track work without a list. Relevant: Grain's non-frontier models need it. Keys are repaired defensively (id/task_id -> taskId, active_form -> activeForm).
- Agent (subagents): fresh context, only the final report returns; frontmatter: name, description, tools, disallowedTools, model, permissionMode, maxTurns (partial result flag, resumable), skills, mcpServers, memory (user|project|local; first 200 lines of MEMORY.md injected), background, isolation:worktree, effort, hooks. Defaults: background by default; background permission prompts surface in the main session naming the subagent (Esc denies that call only); spawn depth 3; 20 concurrent; resume via SendMessage by id/name; a "fork" subagent inherits full conversation and shares prompt cache.
- Skill, ToolSearch (deferred tool loading), EnterPlanMode/ExitPlanMode (approval), EnterWorktree, CronCreate (session-scoped, restored on resume), ScheduleWakeup (self-paced loop, 1 min to 1 h), PushNotification (desktop + phone push), SendUserFile (`display: render|attach`; delivers a generated file to the user's device), SendMessage (agent to agent; classifier reviews messages in auto mode), TaskStop, Workflow (script orchestrating many subagents).
- Hooks: events incl. PreToolUse, PostToolUse, PermissionRequest, PermissionDenied, Stop, SubagentStart/Stop, TaskCreated/Completed, Notification, PreCompact, FileChanged; handler types command/http/mcp_tool/prompt/agent; PreToolUse output `permissionDecision` allow|deny|ask|defer, `updatedInput`, `additionalContext`; exit 2 blocks.

Permission/safety mechanics worth copying (V):
- Modes: default (reads only), acceptEdits (edits + mkdir/touch/mv/cp in scope), plan, auto (second-model classifier), dontAsk (deny anything that would prompt), bypassPermissions.
- Protected paths never auto-approved for writes outside bypass; `rm`/`rmdir` on critical paths (/, ~) handled separately; classifier presumes `git reset --hard`, `git clean -fd`, and recursive delete of an unassigned `$VAR` destructive.
- Classifier: blocks escalation beyond the request, unrecognised infrastructure, actions driven by hostile content; user-stated boundaries ("don't push") are block signals re-read from the transcript (lost on compaction, so use deny rules for hard guarantees); 3 consecutive or 20 total blocks pauses auto mode and resumes prompting; no verdict = deny.
- Sandbox: OS-enforced (Seatbelt on mac); writes default to cwd + temp + added dirs; reads broad with `denyRead`/`allowRead` (narrower path wins); network via a local proxy with allowlist starting EMPTY, unknown hosts decided by mode (prompt/classifier); per-command allowed domains in auto mode; `excludedCommands`; unsandboxed retry via `dangerouslyDisableSandbox` param, can be forced to ask by rule `Bash(dangerouslyDisableSandbox:true)` or disabled with `allowUnsandboxedCommands:false`; credential masking: command sees a sentinel, proxy swaps the real secret on outbound requests to `injectHosts` only (needs TLS termination). Built-in tools (Read/Edit/WebFetch) are NOT inside the sandbox. Anthropic reports sandboxing cut permission prompts 84% (https://anthropic.com/engineering/claude-code-sandboxing).

## 3. UX patterns
- Plan before action; progress indicators per step; reasoning surfaced; steer mid-task from any device (Cowork pages).
- Agent view (https://code.claude.com/docs/en/agent-view, V): sessions grouped Pinned / Ready for review / Needs input / Working / Completed; states Working, Needs input, Idle, Completed, Failed, Stopped; each row = name + one-line Haiku-generated status + age + PR label; Space = peek panel (pending question, current status, or result) with inline reply without attaching; Enter attaches; filters like `s:blocked a:name`; `/bg` backgrounds current session, `/fork` copies it; per-session worktree isolation; notifications on needs-input / finished / failed (Notification hook types `agent_needs_input`, `agent_completed`). A footer hint counts sessions needing input.
- Task checklist rendered from TaskCreate/Update: subject while pending, `activeForm` ("Running tests") while in_progress, N/M completed counter.
- Handoff: PushNotification for long runs, mobile push on completion or needs-input; SendUserFile to deliver outputs; background-subagent permission prompts bubble to the main session with the agent's name.
- Questions: multiple choice with Other; optional timeout so unattended runs continue.

## 4. Safety model
- Cowork: explicit permission before permanently deleting any file, in every mode (V, support.claude.com/en/articles/13364135). Content classifiers scan untrusted content for injection (V). Cannot access files outside connected folders; cloud sessions can't reach the user's network (V). Guidance: restrict browser to trusted sites, avoid scheduling sensitive tasks, block sensitive apps from computer use, review scheduled outputs, start with low-risk tasks.
- Known failure: Jan 2026 exfiltration via the allowlisted Anthropic file-upload API from inside the VM (S, https://www.promptarmor.com/resources/claude-cowork-exfiltrates-files); a "SharedRoot" VM escape write-up exists (S, Cloud Security Alliance). Lesson: an allowlisted host that accepts uploads is an exfil channel; web fetch/search/MCP bypass egress rules.
- Computer use: Claude checks each action and flags injection from screen content; Esc is consumed; terminal hidden from screenshots.

## Mechanisms worth copying (concrete)
1. Tool-result handles: spool big output to a file; inline cap ~30k chars valid / ~10k failure (head+tail); path + 2,000-char preview. (Grain has paged handles; match the failure rule and the benign exit-1 list.)
2. Bash: auto-background on timeout (not for sleep) with task id + output path; background limit 30 min / max 2 h with an explicit "stopped after reaching its time limit" notice so the model can restart with a longer timeout.
3. Monitor: line-per-event watcher, 5 min default / 30 min max deadline, one notice at expiry.
4. Task tool with `activeForm`, `deleted` status, dependencies; enable for non-frontier models.
5. AskUserQuestion with `askUserQuestionTimeout`, neutral relay of typed answer; plan approval never times out.
6. Read: PARTIAL view notice; early reject of oversize `limit`; PDF `pages` max 20; image downscale.
7. Edit read-before-edit that still allows stale-file edits when the match is unique; viewing via cat/sed/grep counts as read.
8. Glob cap 100 mtime-sorted + truncation flag; Grep 3 output modes with `head_limit`/`offset`; surface rg diagnostics.
9. WebSearch session cap (200) with soft notice; WebFetch redirect-as-text, localhost refusal, extraction prompt, 15-min cache.
10. Approval hygiene: stated boundaries as block signals; 3 consecutive/20 total blocks pauses autonomy; no verdict = deny; hard guarantees via deny rules.
11. Credential masking via proxy sentinel with `injectHosts`.
12. Background-subagent prompts bubbled to the parent with agent name; `maxTurns` returns partial and resumable output.
13. Agent-view row: name, state, one-line status, age; peek + inline reply; needs-input counter.
14. SendUserFile `display: render|attach`; PushNotification.
15. Subagent persistent memory (first 200 lines of MEMORY.md).
16. Tool preference order: structured connector > shell > browser > screen.

## Not worth copying / risks
- Cloud-VM-first architecture and server-side classifier (Grain is local-first).
- EndConversation, SendFeedback, ShareOnboardingGuide, ReportFindings, LSP (code-centric; low value for knowledge-work desks).
- Trusting an allowlist that includes upload-capable APIs; exempting fetch/search/MCP from egress rules (Cowork's gap).
- Full computer use as default: slow, broad trust boundary, ~1% injection success on Chrome even after mitigations. Keep it last-resort and per-app approved.
- "Skip all approvals" and auto-approved scheduled tasks; conflict with Grain's propose-only jobs anti-goal.
- A classifier on a weak local model: Anthropic's auto mode depends on a strong second model; prefer deterministic rules (I).
- Task tools are deliberately dropped for newest models; for Grain's weaker models keep them (I).
- Cowork activity is outside audit logs; Grain should keep its run tape/journal (already has).

## Ranked recommendations for Grain
1. Egress proxy for the shell sandbox and browser: empty-by-default domain allowlist, per-host prompt on first contact, per-command allowed domains, block upload-capable hosts; route fetch_url/MCP through the same allowlist (closes Cowork's gap). Effort M. Extends: host shell under Seatbelt, permission rules.
2. Built-in browser as a first-class desk tool (webview per desk, own profile, domain policy, text-first page reads, injection scan on page text, view-only on sensitive domains). Effort L. Extends: web widget, open_page, fetch_url.
3. Desk board ("agent view"): per-desk state (working / needs input / ready for review / done / failed), one-line status, peek + inline reply to pending question/approval, "N need you" counter, notifications on needs-input/finished. Effort M. Extends: desks, desk_status on /events, approvals.
4. Task checklist tool with `activeForm` + N/M counter in the desk UI (create/update/list; status incl. deleted; optional deps), always on for non-frontier models. Effort S. Extends: todo_write plan re-injection and plan mode.
5. Deliverables channel: `send_file(path, caption, display=render|attach)` + per-desk Outputs pane (preview/download) and built-in document skills (docx/xlsx/pptx/pdf) backed by python-docx/openpyxl/python-pptx in the sandbox. Effort M. Extends: HTML artifacts, container sandbox, skills.
6. Ask-user hardening: multiple choice + Other, optional auto-continue timeout for unattended desks (model told user may be away; never for plan or destructive approvals), notification when blocked. Effort S. Extends: desk_ask.
7. Monitor tool + Bash auto-background-on-timeout + explicit time-limit stop notice (watch 5 min default/30 max; bash 30 min/2 h). Effort S/M. Extends: background shell jobs.
8. Deletion protection as a hard invariant: every permanent delete (rm, trash purge, Drive/Gmail delete) always asks in every mode including auto/scheduled; critical paths deny-by-default; classifier-free. Effort S. Extends: permission rules, files tools, trash.
9. Approval hardening: 3-consecutive/20-total denial counter pauses autonomy, chat-stated boundaries persisted as deny rules, background-subagent prompts bubbled with agent name, per-subagent `permissionMode`. Effort M. Extends: subagents, rules, approvals.
10. Credential masking in shell/sandbox: sentinel env vars, proxy injects real key only to `injectHosts`; default denyRead for ~/.ssh, ~/.aws. Effort M. Extends: host shell under Seatbelt, container sandbox.
Honorable: subagent `maxTurns` with partial+resume, subagent persistent memory dir, WebSearch per-session cap (S), per-folder instructions file the agent may update (S), computer use as last-resort tier with per-app approval and global Esc (L, defer).
