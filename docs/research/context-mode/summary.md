# Skip Context Mode, index spilled results

Context Mode is a local MCP server that keeps bulky coding-agent output in a SQLite full-text index and hands the model snippets or a pointer. Grain’s use of that idea is a search query on rows it already stores, written in Grain, with the plugin left uninstalled. The free plugin, npm `context-mode` at **1.0.169** under Elastic License 2.0, withholds raw bytes only when the model calls its own `ctx_*` tools, or when a coding-agent hook blocks a call before it runs. It never observes the calendar, mail, document, and page results Grain produces inside its own tool loop. Grain already stores tool JSON longer than **4,000 characters** and pages it with `read_tool_result`, and the next user message replays assistant prose, so those tool rows do not accumulate across turns. The one behavior Grain lacks is a keyword query over blobs it has already stored. Build that query in Grain’s database. Leave the plugin, its sandbox, and its paid Platform out.

## Sandbox tools withhold bytes only on calls they receive

The repository is [mksglu/context-mode](https://github.com/mksglu/context-mode), copyright 2026 Mert Koseoglu, with the site footer naming MKSF LTD in London. On 2026-10-02 GitHub reported **24,973 stars** and the description “Context window optimization for AI coding agents” ([GitHub API](https://api.github.com/repos/mksglu/context-mode)). `package.json` on `main` and the npm `latest` tag both say **1.0.169**, license `Elastic-2.0`, Node **`>=22.5.0`**, author Mert Koseoğlu ([package.json](https://github.com/mksglu/context-mode/blob/main/package.json), [npm](https://www.npmjs.com/package/context-mode)). The registry `updated` timestamp is 2026-06-29 while GitHub `pushed_at` is 2026-10-02, and this pass did not diff the tarball against `main`, so the installable package can differ from the tree described here. npm recorded **29,499 weekly downloads**. The homepage’s “331,200+ developers” line has no published method ([context-mode.com](https://context-mode.com/)).

The README’s problem is a coding session: every MCP call dumps raw data into the window, compaction then drops files and the last request, and the model spends output tokens on filler ([README](https://github.com/mksglu/context-mode/blob/main/README.md)). The marketing page says the plugin sits between the agent and its tools and that raw data never touches context ([context-saving](https://context-mode.com/context-saving)). The source is narrower. Eleven tools are registered in `src/server.ts`. Six move data: `ctx_execute`, `ctx_execute_file`, `ctx_batch_execute`, `ctx_index`, `ctx_search`, and `ctx_fetch_and_index`. Five are housekeeping: `ctx_stats`, `ctx_doctor`, `ctx_upgrade`, `ctx_purge`, and `ctx_insight` ([server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)). `ctx_execute` runs caller-supplied code in one of twelve languages. It is annotated `openWorldHint: true`, the schema’s mark for full network access. The README says the subprocess still inherits the process filesystem, and that the boundary guard is a defense-in-depth layer for the file-read tool, short of an OS sandbox ([README](https://github.com/mksglu/context-mode/blob/main/README.md)).

What comes back depends on an optional `intent` string and two constants: **5,000 bytes** for intent search, **102,400 bytes** for automatic indexing ([server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)). With a non-empty intent and stdout over 5,000 bytes, the full stdout is indexed and the model receives search snippets. Over 100 KB, stdout is indexed and the model receives a pointer. Otherwise the model receives the stdout itself, up to that 100 KB ceiling. The **98%** figure is the project’s own byte arithmetic on a fixture set, about **315 KB** of selected outputs reduced to about **5.4 KB** ([README](https://github.com/mksglu/context-mode/blob/main/README.md)). The author told Hacker News the percentage is UTF-8 bytes, converted with bytes/4 and marked estimated, and that a real tokenizer would differ ([Hacker News](https://news.ycombinator.com/item?id=47148025)). An older benchmark rollup of roughly **45,300** tokens down to **2,600** is about 17× ([BENCHMARK.md](https://github.com/mksglu/context-mode/blob/eb6ddac6c1c3a1868c391a2527497e0586086c15/BENCHMARK.md)). The homepage’s “30× fewer tokens” has no method of its own ([context-mode.com](https://context-mode.com/)). One small fixture in that same file goes the other way: 0.4 KB of network requests becomes 349 bytes ([BENCHMARK.md](https://github.com/mksglu/context-mode/blob/eb6ddac6c1c3a1868c391a2527497e0586086c15/BENCHMARK.md)).

Search is lexical. A Porter FTS5 table and a trigram FTS5 table are merged with reciprocal rank fusion, then a proximity rerank and a Levenshtein retry. `src/store.ts` contains no embedding step ([store.ts](https://github.com/mksglu/context-mode/blob/main/src/store.ts), [README](https://github.com/mksglu/context-mode/blob/main/README.md)). `ctx_search` returns windowed snippets, default limit 3. After **8** calls inside a **60-second** window the tool refuses ([server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)). Content databases older than **14 days** are deleted on server startup. Session rows have a 7-day cleanup method. The files are ordinary SQLite, with no encryption in the schema, under a per-host directory overridable by `CONTEXT_MODE_DIR` ([session/db.ts](https://github.com/mksglu/context-mode/blob/main/src/session/db.ts)). Any local process that can open the file can read indexed mail or page text.

Hooks are a second layer, aimed at coding-agent tool names. Shell HTTP, build logs, and web fetch can be denied or rewritten into an instruction to call `ctx_fetch_and_index` or `ctx_execute`. File read and grep receive guidance and still run. Other MCP tools are left alone: the router periodically tells the model to pipe large results through `ctx_execute`, and the original payload still returns to the model ([routing.mjs](https://github.com/mksglu/context-mode/blob/main/hooks/core/routing.mjs)). If the MCP server is not ready, that redirect does nothing and the original command runs. Generated Cursor hook entries set `failClosed: false` ([cursor adapter](https://github.com/mksglu/context-mode/blob/main/src/adapters/cursor/index.ts)). The README’s “~98%” with hooks and “~60%” without them are the project’s compliance estimates, separate from the fixture table ([README](https://github.com/mksglu/context-mode/blob/main/README.md)).

## Platform mode uploads prompt text the homepage denies

The free plugin is the only generally available product. The site says that today there is one paid Solution: Context Mode Insight, **$20 per seat per month**, with no annual plan and no volume discount ([Insight](https://context-mode.com/insight), [homepage](https://context-mode.com/)). Memory, Audit, and Cost are marked coming in 2026 and roadmap. Insight is org analytics for an engineering team: adoption, persona views, a CISO lens. Counts disagree across pages, 222 versus 177 patterns and 13 versus 9 versus 8 remote tools, so the live fact is a hosted dashboard, and the larger counts are unverified ([platform docs](https://platform.context-mode.com/docs), [Insight](https://context-mode.com/insight)). Self-host is absent from v1. Rows land in Cloudflare D1, isolated per org, with **90-day** retention advertised for Insight.

With no `~/.context-mode/platform.json`, the forwarder returns immediately. The install that creates the file is a bootstrap script which writes a `ctxm_` API key and `https://platform.context-mode.com/api/v1` ([platform docs](https://platform.context-mode.com/docs)). Once that file exists, `hooks/platform-bridge.mjs` POSTs event fields after a regex pass and a **200-character** cap per string. The comment in that file says all fields pass through and the server selects columns per event type. Redaction covers common token shapes, email addresses, and a US Social Security number pattern, replaces `$HOME` and the username segment of a home path, and leaves the rest of the path. It is a pattern list, so a secret that misses the regex stays in the payload ([platform-bridge.mjs](https://github.com/mksglu/context-mode/blob/main/hooks/platform-bridge.mjs)).

That code and the marketing pages describe different products. The homepage and the Insight page say forwarding is “only structural metadata — tool names, error counts, file paths” and “Never source code. Never prompt content. Never file content” ([context-mode.com](https://context-mode.com/), [Insight](https://context-mode.com/insight)). The Platform docs open by saying the plugin already ships “tool calls, errors, prompts, file edits,” one firehose, no client-side classification ([platform docs](https://platform.context-mode.com/docs)). The README’s capture list includes every user message, rule-file content, and the first 500 characters of subagent findings ([README](https://github.com/mksglu/context-mode/blob/main/README.md)). A hook at commit `429d6f2c` stores the prompt in the event `data` field ([userpromptsubmit.mjs](https://github.com/mksglu/context-mode/blob/429d6f2c/hooks/userpromptsubmit.mjs)). That hook was not re-read on the 2026-10-02 tip, so the current shape of `data` is the open detail. The docs’ statement that prompts are on the wire is current. The full-text database is a different store. The bridge that was read forwards events, and it does not upload the content SQLite file. A snippet already copied into an event still goes.

The default process is also on the network when Platform is off. At commit `429d6f2c`, startup calls `https://registry.npmjs.org/context-mode/latest` and repeats the GET every hour, with a five-second timeout, errors treated as `"unknown"`, and no disable flag beside the call ([server.ts at 429d6f2c](https://github.com/mksglu/context-mode/blob/429d6f2c/src/server.ts)). The request body carries no prompt. Whether `main` on 2026-10-02 still does this unconditionally was not re-checked. `ctx_fetch_and_index` fetches URLs when invoked, `ctx_upgrade` pulls from GitHub when invoked, and `ctx_insight` opens the hosted dashboard in the browser. The context-saving page’s “fully air-gapped” line does not describe this tool surface ([context-saving](https://context-mode.com/context-saving)).

Roadmap Memory, in the one published sentence, carries coding-agent decisions, conventions, and architectural rules across sessions, teammates, and projects ([context-mode.com](https://context-mode.com/)). Grain already stores personal memory and a knowledge graph. A second writer for project decisions, scoped to people who share a Platform org, would overlap that coding slice and would miss mail, calendar, and notes. It is unshipped. “Across teammates” implies the hosted store. The site does not say Memory is local-only.

Local trust bugs are on the record. Issue #293 reports a local Insight API sending `Access-Control-Allow-Origin: *`, so another localhost origin can read session events ([issue #293](https://github.com/mksglu/context-mode/issues/293)). Issue #442 reports `ctx_index` reading an arbitrary path into the index without the deny check `ctx_execute_file` uses, after which `ctx_search` returns the text ([issue #442](https://github.com/mksglu/context-mode/issues/442)). Issue #415 reports an installer that deleted unrelated user hooks; the maintainer said that was fixed in v1.0.108, with no restore of hooks already removed ([issue #415](https://github.com/mksglu/context-mode/issues/415)). Fix status for #293 and #442 was not confirmed on `main`.

## Elastic License 2.0 allows a local binary and forbids a hosted copy

The LICENSE file is Elastic License 2.0. The grant is non-exclusive, royalty-free, worldwide, **non-sublicensable, and non-transferable**: use, copy, distribute, make available, and prepare derivative works, subject to the limits ([LICENSE](https://github.com/mksglu/context-mode/blob/main/LICENSE)). The hosted-service limit is quoted in the file: you may not provide the software to third parties as a hosted or managed service where the service gives users access to any substantial set of the features or functionality of the software. The same text forbids circumventing license-key controls and forbids altering or removing licensing notices. Modified copies need a prominent notice that you modified the software, and anyone who receives a copy must receive these terms. A patent claim against the software terminates the patent license. The README says the project left MIT because MIT permits repackaging the code as a competing closed-source SaaS ([README](https://github.com/mksglu/context-mode/blob/main/README.md), [commit a482980](https://github.com/mksglu/context-mode/commit/a48298080e90f2824dfb4e5c883085ea019fd255)). The homepage still says “open-source plugin.” The README’s word is source-available.

Elastic’s own FAQ, written about Elasticsearch, says you may use and redistribute the software inside a self-managed application, and that giving customers direct access to a substantial portion of the product as a service is the forbidden case ([ELv2 FAQ](https://www.elastic.co/licensing/elastic-license/faq)). That FAQ is Elastic’s intent for Elastic’s products. It is persuasive analogy, and it is a weak ruling about this repository. “Substantial set” is undefined in the license text. No license-key check turned up in the files read; the clause is still in the LICENSE, so a later fork should leave such a check in place if one appears.

For Grain as a local app, shelling out to a `context-mode` binary the user installed is ordinary use. Vendoring the sources beside a closed-source desktop build is also inside the grant, provided the LICENSE travels with the copy, notices stay, and any edit is marked. Grain would not become the licensor. Recipients would still be under Koseoglu’s grant. The forbidden shape is a service whose users receive the sandbox, the index, or the hook engine as the product. A cloud backend that ran the plugin for other people is that shape. A process on the owner’s machine is the permitted one. Clean-room code that Grain writes against its own tables never enters this license.

## Grain already spills past 4,000 characters and drops tool rows next turn

One Grain reply is an in-memory loop in `_chat_stream`. Each round sends the whole message list, including tool-role rows from earlier rounds of that same reply ([app.py](../backend/personal_os/app.py)). The model-facing string is `ToolResults.for_model`. At or under **`INLINE_CHARS` = 4,000**, the JSON stays in the window. Above that, the content is stored, capped at **2,000,000 characters**, and the model receives a handle: `result_id`, tool name, total length, shape, preview, and a note ([working.py](../backend/personal_os/working.py)). `read_tool_result` pages the blob, default **4,000** characters, clamp **20,000**, and only for the same conversation. A shape marked `untrusted` taints the run again when it is read back. `tool_results` rows are deleted after **30 days**; shell spills go after **7** ([retention.py](../backend/personal_os/retention.py), [shell.py](../backend/personal_os/shell.py)).

Several tools cut before that gate, so the stored blob is already a window. `fetch_url` defaults to **12,000** characters and clamps at 40,000. `gmail_get` keeps **8,000** of the body. Drive read keeps 8,000, Docs get **20,000**. A local file window defaults to 8,000 and clamps at 30,000. Shell keeps a 50 KB tail and stores the scrubbed full output aside. External MCP text is sliced at **20,000** characters before the chat loop applies the handle again ([mcp_client.py](../backend/personal_os/mcp_client.py)). Calendar briefs clip descriptions to **120** characters and page at 30. Web search and Gmail search return short rows. A page whose body fills the 12,000-character default is already a handle, because that JSON is past 4,000 characters. The model pages it today.

The following user message does not replay those tool rows. History selects `id, role, content` and drops empty content. Tool-role messages are never stored as rows, and `tool_events` are not selected ([repos.py](../backend/personal_os/repos.py)). What the next turn can quote is the assistant’s written answer. Inside a single reply, once estimated tokens pass half of the default **128,000**-token window, microcompaction keeps the newest three tool results the model has seen and stubs older ones. Inline results between **400 and 4,000** characters can be cleared with `result_id` null, so those particular strings cannot be read back ([compaction.py](../backend/personal_os/compaction.py)). The notes contain no count of how often live mail, fetches, or calendar payloads cross 4,000 characters, and no count of how often that half-window compaction fires on personal-assistant chats.

Grain already has Porter FTS5 for memories, uploaded-file chunks, the user’s own documents, and meeting title, notes, and transcript ([db.py](../backend/personal_os/db.py), [docs.py](../backend/personal_os/docs.py), [meetings.py](../backend/personal_os/meetings.py)). `tool_results.content` is a plain `TEXT` column. Lookup is by id, then a character slice. There is no query. Pointing the document or memory index at tool output would place mail, web pages, and shell text on the path `build_context` injects into later chats, and it would ignore the 30-day deletion of `tool_results`.

Grain can already attach an external MCP server over stdio or HTTP. Discovered tools default to **ask**, are marked external, taint the reply, and, once more than **12** ready schemas are loaded, sit behind `mcp_tool_search` ([mcp_client.py](../backend/personal_os/mcp_client.py), [llm.py](../backend/personal_os/llm.py)). That server receives what the model chooses to send it. Gmail, calendar, documents, and `fetch_url` are executed inside the toolbox and appended in `_chat_stream`. Their results never arrive as arguments to a foreign process unless the model copies them there.

## An attached server misses the tools that hold mail and calendar

Attaching `context-mode` as a stdio server fits the client and misses the data. Grain’s long payloads are a fetched page, a full email, a Drive or Docs body, a local file, a shell or Python log. The plugin’s router has aliases for shell, read, grep, and web fetch. It has none for calendar, mail, or documents ([routing.mjs](https://github.com/mksglu/context-mode/blob/main/hooks/core/routing.mjs)). Its branch for foreign MCP tools nudges and still returns the original payload, and Grain’s loop is a separate host that does not run those hooks. The model can place a body into `ctx_index` only by putting that body in the tool call, which spends the window the spill just saved, or by fetching the same resource again through `ctx_execute`, which repeats work Grain already ran under its permission check. Each external call is an approval card and a taint source. Eleven tools join the schema list, and the client stops inlining ready MCP schemas once that list passes **12**. The plugin’s unconditional ceiling is **100 KB** unless the caller passes `intent`. Grain’s gate is **4,000 characters**. A `ctx_execute` that prints a mail body without `intent` would put more text in the window than `for_model` does now.

The side effects are a second store and a second trust boundary. Indexed personal text would sit in plaintext SQLite outside Grain’s conversation scope, outside the `untrusted` flag, on a **14-day** content clock that does not match the **30-day** tool retention. `ctx_execute` runs arbitrary code with the process’s files and with network. If issue #442 is still open, `ctx_index` can pull a path Grain’s own rules would refuse, and `ctx_search` can hand it back. A Platform config file is enough to start uploading prompts, which is the wrong default beside mail and calendar. The hourly registry poll, on the commit where it was read, announces the machine to npm even when that config file is absent. `package.json` requires Node **22.5**; the context-saving footer still says Node 18+ ([context-saving](https://context-mode.com/context-saving)).

Vendoring the TypeScript under ELv2 is available for a local app and brings the same mismatch. Grain would be carrying a twelve-language executor and a hook layer for other hosts to recreate a pointer `ToolResults` already returns. The license would remain non-sublicensable. A later hosted Grain that exposed `ctx_search` or `ctx_execute` to other people would be the use the maintainer left MIT to prevent. Gating the version poll would be a modification that must carry a notice, and no opt-out was documented beside the call that was read.

## Conclusion

Skip the plugin. The piece to add is a conversation-scoped full-text query on `tool_results` rows Grain has already stored, beside `read_tool_result`, using the Porter tokenizer the other FTS tables already use. Take `conversation_id` from the run, refuse other chats’ rows, and set the run tainted when a hit’s shape is `untrusted`. Delete the index rows in the same retention pass that deletes the blob, because Grain’s existing virtual tables are not covered by foreign-key cascade. Keep results at or under 4,000 characters inline. Keep calendar briefs and search snippets inline. Leave the 400-to-4,000-character microcompaction hole alone: those strings were never given an id, and storing every one of them widens the spill. Search will see what the tools already kept, including MCP text already cut at 20,000 characters. Widening that cut is a different decision.

That query is the whole overlap worth keeping. Context Mode’s session math assumes tool output stays in the window until a compaction snapshot replaces it with a table of contents. Grain’s next turn loads the assistant’s prose, and the **98%** figure belongs to the other loop. Inside one reply, a 12,000-character page or an 8,000-character letter is already a handle, and an offset walk is how the model reaches a sentence outside the preview. A match window on the stored row shortens that walk. The binary, the Elastic License grant, and the Platform forwarder stay outside that change.
