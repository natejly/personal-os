## Coworking: subagents, workflows, files, shell and Python under permissions

Researched 2026-10-01 against Claude Code ([sub-agents](https://code.claude.com/docs/en/sub-agents), [permissions](https://code.claude.com/docs/en/permissions), [sandboxing](https://code.claude.com/docs/en/sandboxing), [checkpointing](https://code.claude.com/docs/en/checkpointing)), the OpenAI Agents SDK ([handoffs, agents-as-tools](https://openai.github.io/openai-agents-python/handoffs/)), Codex CLI ([approvals and sandbox modes](https://learn.chatgpt.com/docs/agent-approvals-security)), Goose ([sub-recipes](https://block.github.io/goose/docs/guides/recipes/sub-recipes/)), LangGraph ([interrupts and checkpointers](https://docs.langchain.com/oss/python/langgraph/interrupts)), Cline ([shadow-git checkpoints](https://docs.cline.bot/features/checkpoints)), Roo, Gemini CLI and OpenHands.

### Where we are

- **Files.** `find_files` (Spotlight), `read_local_file`, `write_local_file`, `move_local_file`, `trash_local_file` (`mac.py`, `tools.py` ~1670-1759). Home-scoped through `mac.allowed_path` (symlinks resolved, `~/Library` and dot-folders refused), executable file types refused on write. Reads are `safe`/on; writes `external`/ask. No copy, mkdir, glob, content grep or exact-string edit; no per-folder roots.
- **Python.** `run_python` (`sandbox.py`): host subprocess, `python -I`, temp dir, macOS `sandbox-exec` profile (no network, writes only in the work dir, `.env` and the data dir denied), rlimits, 30s default. Stateless across calls.
- **Shell.** Only inside a container: `sandbox_exec` and friends (`microvm.py`), docker under colima, `--network none` by default, 1 GB / 2 CPU, no bind mounts. Nothing runs on the host; a desk workspace can't be mounted in.
- **Permissions.** Per-tool on/ask/off resolved chat > project > global > default, danger tiers (`safe, writes, network, executes` on; `external, plan, schedules` ask), taint forcing external tools to ask, approval card with `allow | deny | always_chat | always_global`. No argument-pattern rules (no `Bash(git *)`, no path rules), no session scope.
- **Subagents.** None. `_chat_stream` is one serial ReAct loop. Desks run in parallel but only the user can start one, and they get the chat's full toolset.
- **Workflows.** None deterministic. Jobs schedule one prompt; `propose_plan` is an approval card, not an executor; skills are prose.

### What the reference systems do

- **Permission rules (Claude Code).** `allow / ask / deny` arrays of `Tool(specifier)`; evaluation is deny, then ask, then allow, first match wins. `Bash(npm run *)` with `*` anywhere. Compound commands split on `&& || ; | |& &` and newlines; every subcommand must be allowed, while one denied or asked subcommand (including inside `$()` and subshells) decides. Wrappers (`timeout`, `time`, `nice`, `nohup`, `stdbuf`, `command`, `xargs`) are stripped; anything unparseable falls to ask. A fixed read-only set (`ls`, `cat`, `grep`, `git status` ...) runs without a prompt. The docs are explicit that command rules are UX and the OS sandbox is the boundary. "Don't ask again" saves one exact rule per subcommand.
- **Sandbox (Claude Code, Codex).** macOS Seatbelt: deny by default, reads broadly allowed minus secrets (`~/.ssh`, keychains, `.env`), writes only to the workspace, temp and granted roots, `.git/hooks` and `.git/config` protected, network denied or forced through a local allowlisting proxy. Codex's modes `read-only | workspace-write | danger-full-access` with network off by default. Escape from the sandbox is a forced approval, never a rule.
- **Shell UX (OpenHands, Claude Code).** Timeout default 2 min, max 10; output truncated near 30k chars with the full text behind a handle; background processes return an id to poll or kill; kill the whole process group.
- **Subagents (Claude Code, Agents SDK, Goose).** Agents-as-tools: the child starts with only its task, a project-instructions snapshot and a tool allowlist; only its final report returns, escaped as untrusted data; caps on concurrency (Claude Code 20, Goose 10; 4-6 sensible on a laptop), depth (Claude Code 3) and turns; a child can never exceed its parent's permissions and its approvals surface in the parent's UI; read-only by default, writers isolated.
- **Workflows (Goose recipes, LangGraph, n8n).** A declarative file with typed params; steps that are tool calls, agent calls or fan-outs; approval of the expanded plan bound to a hash; per-step state in a checkpointer; pause points as durable approval rows; resume from the first incomplete step, side-effecting steps keyed by an idempotency id.
- **File editing (Claude Code, Cline).** Exact-string `Edit` that fails loudly on zero or multiple matches; glob and ripgrep; checkpoints so edits are undoable.

### Shared contract (all four specs build against these names)

Tool names: `shell_run`, `shell_poll`, `shell_kill`, `fs_glob`, `fs_grep`, `fs_edit`, `fs_copy`, `fs_mkdir`, `agent_spawn`, `agent_wait`, `agent_stop`, `desk_start`, `workflow_run`, `workflow_resume`. Rule subjects: `Bash(<command>)` for `shell_run`, `Read(<path>)` for `read_local_file/fs_glob/fs_grep`, `Edit(<path>)` for `write_local_file/fs_edit/fs_copy/fs_mkdir/move_local_file`, `Agent(<agent type>)` for `agent_spawn`, plain `ToolName` for everything else. Granted roots: setting `workspaceRoots` (list of absolute folders, default empty), plus the active desk's workspace; `fs_*` and `shell_run` refuse anything outside home and outside the roots-or-desk unless the call is approved.

### Specs

#### cowork-1: Permission rules engine and session-scoped approvals (M)

**Why.** Every reference agent pairs shell and file autonomy with argument-pattern rules; ours can only say on/ask/off per tool, so the user faces a choice between approving every `ls` and trusting every `rm`.

**Files.** `backend/personal_os/permrules.py` (new), `backend/personal_os/tools.py` (mode resolution hook only), `backend/personal_os/app.py` (approval decision handling: new `always_session` and `always_rule` choices), `backend/personal_os/llm.py` (DEFAULT_SETTINGS `permissionRules: {allow: [], ask: [], deny: []}`), `src/renderer/src/components/ToolPermissions.tsx` (rules editor), the approval card component, `backend/tests/test_permrules.py` (new).

**Design.** `parse_rule("Bash(git push *)") -> Rule(tool, pattern)`. `subject_for(tool, args)` per the shared contract. Bash matching: `split_command(cmd)` with a conservative tokenizer (shlex-based, quote-aware): split on `&& || ; | |& &` and newlines; any `$(`, backtick, `<(`, heredoc, unbalanced quote or trailing operator makes the command "opaque". Strip wrappers `timeout N, time, nice [-n N], nohup, stdbuf ..., command, builtin, xargs` (bare) before matching; for allow rules strip only `LANG/LC_*/TZ/NO_COLOR` env prefixes, for deny/ask strip any `NAME=value` prefixes. Glob semantics: `*` matches any run of characters; trailing ` *` also matches the bare command (`Bash(ls *)` matches `ls`, not `lsof`). Path rules: gitignore-ish (`~` expanded, `**` any depth, `*` one segment), matched on the symlink-resolved absolute path. `evaluate(tool, args, rules) -> 'deny' | 'ask' | 'allow' | None`: deny if any subcommand hits deny, else ask if any hits ask or the command is opaque, else allow if every subcommand hits allow or the built-in read-only set (`ls, cat, head, tail, wc, pwd, echo, which, file, stat, grep, rg, find` without `-exec/-delete/-ok`, `git status|diff|log|show|branch`), else None (fall through to tool mode). Integration: in Toolbox mode resolution, `deny` turns the call into a refusal the model sees, `ask` forces a card, `allow` downgrades ask to on, BUT never for forced approvals (taint, plan mode, schedules, `external` tier tools in proposal-only runs), which stay unbypassable. Approval card gains "Allow for this chat session" (in-memory per conversation, cleared on restart) and, for rule-keyed tools, "Always allow `<suggested rule>`" which appends the exact rule (one per subcommand, max 5) to `permissionRules.allow`; the card shows the rule text verbatim. Settings UI: three lists with add/remove and a "test a command" box calling `POST /permissions/evaluate`.

**Tests.** Offline: splitting and opacity (`a && b`, `$(rm -rf /)`, quotes), wrapper stripping, `Bash(ls *)` vs `lsof`, deny beats allow, one asked subcommand asks, read-only set, path rules with `**` and symlinks (tmpdir), forced approvals not downgraded, session grant scoping.

**Done when.** `git status && rm -rf x` asks even with `Bash(git *)` allowed; `Bash(npm run test *)` lets `npm run test -- -k foo` through without a card; a denied path is refused before the tool runs.

#### cowork-2: Host shell in a workspace under Seatbelt, with background jobs (M)

**Why.** The container sandbox can't see the user's files or a desk's workspace, so the agent can't actually do work on a folder. Claude Code and Codex run the shell on the host inside an OS sandbox with the workspace writable and the network off.

**Files.** `backend/personal_os/shell.py` (new), `backend/personal_os/sandbox.py` (factor the Seatbelt profile builder so both use it), `backend/personal_os/tools.py` (register `shell_run`, `shell_poll`, `shell_kill` in a new `shell` group), `backend/personal_os/llm.py` (DEFAULT_SETTINGS `shellNetwork: false`, `shellTimeoutSec: 120`, `shellMaxBackground: 4`), `backend/tests/test_shell.py` (new), README section.

**Design.** `shell_run(command, cwd?, timeout_s?, background?)`. `cwd` must resolve inside the active desk workspace or a `workspaceRoots` entry (default: desk workspace, else first root, else refuse with a message telling the user to add a root in Settings). Run `/bin/zsh -c` (fallback `/bin/sh`) under `sandbox-exec` with a generated profile: deny default; allow process exec/fork; reads everywhere except `~/.ssh`, `~/.gnupg`, `~/Library/Keychains`, `~/.aws`, `~/.config/gcloud`, any `.env`, and the app data dir; writes only to cwd's root, a per-run tmp dir and the desk workspace; deny writes to `.git/hooks` and `.git/config`; network denied unless `shellNetwork` (then the run is tainted). Environment scrubbed to a minimal allowlist (PATH, HOME, LANG, TERM=dumb, TMPDIR); never the app's secrets. `start_new_session=True` and kill the process group on timeout (default 120s, max 600s). Output: stdout+stderr interleaved, last 30k chars returned, full output stored through the existing paged-handle mechanism in `working.py`. Background: returns `{job_id}`; `shell_poll(job_id)` returns new output and exit status; `shell_kill`; at most `shellMaxBackground` live, all killed on app shutdown and when their conversation's run ends. Tier `executes`, default **ask**; with cowork-1 present, its `Bash(...)` rules and read-only set apply. If `sandbox-exec` is missing or fails to apply the profile: refuse unless the user approves an explicit "run unsandboxed" forced approval; never silently downgrade. Non-macOS: same flow with the forced approval.

**Tests.** Offline, macOS-gated where Seatbelt is required: cwd outside roots refused; write outside workspace fails under the profile; write inside succeeds; `curl` fails with network off; timeout kills a `sleep 100` process group; output truncation plus handle; background poll/kill; env does not contain a planted secret var.

**Done when.** In a desk, the agent can `shell_run("python3 make_report.py && ls outputs")` and the file appears in the workspace, while `touch ~/Desktop/x` from the same call fails.

#### cowork-3: File tools over granted roots, and the workspace mounted into the VM sandbox (M)

**Why.** Claude Code-style glob, grep and exact edit are what let an agent work on a folder cheaply and safely; today the only edit is a whole-file overwrite.

**Files.** `backend/personal_os/fsx.py` (new), `backend/personal_os/mac.py` (reuse `allowed_path`; add `in_roots`), `backend/personal_os/tools.py` (register `fs_glob`, `fs_grep`, `fs_edit`, `fs_copy`, `fs_mkdir` in the `files` group), `backend/personal_os/microvm.py` (optional read-write bind mount of the active desk workspace at `/workspace/desk`), `backend/personal_os/llm.py` (DEFAULT_SETTINGS `workspaceRoots: []`, `sandboxMountDesk: true`), Settings UI for roots (small list editor in the existing files or sandbox section), `backend/tests/test_fsx.py` (new).

**Design.** All paths pass `mac.allowed_path` and then must be inside a granted root or the desk workspace for writes; reads may be anywhere `allowed_path` allows. `fs_glob(pattern, root?)`: pathlib glob with `**`, skip dot-dirs, `node_modules`, `.git`, cap 500 results, sorted by mtime. `fs_grep(pattern, root?, glob?, context?)`: use `rg --json` when on PATH, else a pure-Python regex walker; cap 200 matches, 400-char lines, binary files skipped. `fs_edit(path, old, new, replace_all=false)`: exact string replace; error on zero matches and on multiple matches unless `replace_all`; returns a unified diff; writes atomically (tmp + rename) and, if the agentloop branch's `filesnap.py` is present, snapshots the pre-image for undo. `fs_copy(src, dst)` refuses to overwrite; `fs_mkdir(path)` with parents. Tiers: `fs_glob/fs_grep` safe/on; `fs_edit/fs_copy/fs_mkdir` writes tier, default **on inside the desk workspace and ask elsewhere** (decide in the tool by path; with cowork-1 present, `Edit(path)` rules apply). MicroVM: when a desk is active and `sandboxMountDesk`, add `-v <desk workspace>:/workspace/desk:rw` to container creation; never mount anything else.

**Tests.** Offline in a tmpdir with a fake home: glob caps and skips; grep with and without rg (monkeypatch `shutil.which`); edit zero/one/many matches and the diff; refuse writes outside roots; symlink escaping a root refused; copy refuses overwrite; docker argv includes the mount only when a desk is active.

**Done when.** The agent can find, grep and surgically edit files in a granted project folder, and a desk's sandbox container sees the desk files at `/workspace/desk`.

#### cowork-4: Subagents (`agent_spawn`) and agent-started desks (L)

**Why.** Every reference agent fans work out to children with isolated context; ours is one serial loop, so research-heavy or multi-file tasks blow the context and run one at a time.

**Files.** `backend/personal_os/subagents.py` (new), `backend/personal_os/runs.py` (add `parent_run_id` via the db migration style; `RunStore.children(run_id)`), `backend/personal_os/app.py` (a small refactor so one bounded reply loop can run headless with a given system prompt, tool filter, budget and parent; register the tools; route `GET /runs/{id}/children`), `backend/personal_os/tools.py` (register `agent_spawn`, `agent_wait`, `agent_stop`, `desk_start` in an `agents` group), `backend/personal_os/llm.py` (DEFAULT_SETTINGS `subagentMaxConcurrent: 4`, `subagentMaxDepth: 2`, `subagentMaxRounds: 12`, `subagentMaxCost: 0.25`), `src/renderer/src/components/ToolEvents.tsx` (child-run card with live status, expandable to its trace), `backend/tests/test_subagents.py` (new).

**Design.** `agent_spawn(task, role?, tools?, model?, background?)` where `role` is one of `researcher` (read-only: knowledge, web, `read_local_file`, `fs_glob`, `fs_grep`), `worker` (adds file writes and `shell_run` but only inside the active desk workspace or a granted root) or `reviewer` (read-only). `tools` may only narrow the role's set, and the role set is intersected with the parent's effective tool modes: a child never gets a tool the parent has off, and anything that is ask for the parent is ask for the child. The child's approval cards surface in the parent conversation's card stream, labelled with the child. A child never gets `agent_spawn` beyond `subagentMaxDepth`, never gets `schedule_task`, `workflow_run` or external tools (mail, calendar, Google) — those stay with the parent. The child's context is its system prompt, the task, the project instructions and pinned memories only, with no parent history. Each child is a durable run (`kind='subagent'`, `parent_run_id`) on its own budget (`subagentMaxRounds`, `subagentMaxCost`) that also counts against the parent's budget. Concurrency is capped by an asyncio semaphore across the app. Foreground `agent_spawn` waits; several `agent_spawn` calls in one model round run concurrently (gather only these calls; other tools stay serial). `background=true` returns `{agent_id}`, then `agent_wait(ids, timeout_s)` collects reports and `agent_stop(id)` cancels. The result is the child's final text, capped at 6k chars with the full transcript behind a handle, wrapped as untrusted data (taints the parent like `read_local_file` does). On restart, running children become `interrupted`. `desk_start(title, brief, mode)`: tier `plan` (always a card); creates a desk exactly as the REST route does, never in a looser mode than `plan`, and counts against `deskMaxLive`.

**Tests.** Offline with a stubbed `llm.stream_chat` that scripts child replies: tool narrowing (a child cannot see a tool the parent has off; a role cannot widen), depth cap, concurrency cap (semaphore observed), several spawns in one round run concurrently, budget roll-up, untrusted wrapping and taint, background spawn then wait, `desk_start` requires approval and creates a plan-mode desk.

**Done when.** "Research these five companies and write a one-page comparison into my desk" spawns researchers in parallel, collects their reports and writes the deliverable, each child visible as a card.

#### cowork-5: Workflows: declarative, approved by hash, resumable (L; builds on cowork-4)

**Why.** Repeatable multi-step work (weekly review, folder digest, research fan-out) should be a definition the user approves once, not a prompt the model improvises each time. Goose recipes and LangGraph checkpointing are the models.

**Files.** `backend/personal_os/workflows.py` (new), `backend/personal_os/db.py` (tables `workflows`, `workflow_runs`, `workflow_steps`), `backend/personal_os/app.py` (routes under `/workflows`), `backend/personal_os/tools.py` (`workflow_run`, `workflow_resume`, `workflow_list`), `src/renderer/src/components/LibraryView.tsx` (Workflows tab: list, YAML/JSON editor with validation, run with params, run history with per-step status), `backend/tests/test_workflows.py` (new).

**Design.** A workflow is JSON (YAML accepted if `yaml` is importable): `{name, description, params: {k: {type, required, default}}, steps: [{id, tool?|agent?|fan_out?, args, needs?, approval?: 'required', when?}], output?}`. Templates are `{{param}}`, `{{step_id.result}}` and `{{item}}` inside fan-outs, rendered by a tiny safe substitutor (no expression evaluation). `agent` steps call `subagents.spawn` (cowork-4) with a role; `fan_out: {over: "{{scan.result}}", max_parallel: N, agent: {...}}` maps over a list. `validate(defn)` checks unique ids, `needs` refer to earlier steps, no cycles, and every tool exists. Running: expand the step list, compute `plan_digest = sha256(canonical definition + params)`; a run starts only after the user approves that digest (the same approve-by-hash model as `plans.py`), and any edit to the definition invalidates it. Each step's state (`pending|running|done|failed|waiting_approval`, result handle, `idempotency_key = run_id:step_id`) is a `workflow_steps` row. Steps marked `approval: required` pause on a durable approval row. Tool steps go through the normal Toolbox, so permission rules, taint and forced approvals all still apply. Resume starts at the first non-done step; a done side-effecting step is never re-run (`runs.call_once` semantics). Scheduled jobs may reference a workflow but run it proposal-only. `workflow_run` from chat proposes a run (card with the expanded plan); it never starts one without approval.

**Tests.** Offline: validation errors, template rendering, digest changes on edit, approval gate, fan-out with max_parallel (stubbed agents), pause on a step with `approval: required` and resume, resume after a simulated crash skips done steps, a failed step stops dependants.

**Done when.** A user can save "Folder digest" (glob a folder → fan-out summarize → write `digest.md` with approval), run it from the Library with a folder param, watch steps complete, and resume after a restart.

### opencode, and the amendments it adds

[opencode](https://github.com/sst/opencode) (`packages/opencode/src/{permission,tool/shell.ts,tool/edit.ts,tool/task.ts,agent/agent.ts,snapshot,session/compaction.ts}`) solves the same problems with no OS sandbox and no workflow engine, but several of its mechanisms are better than our first draft. Rules are flat `{permission, pattern, action}`, last match wins, miss means ask. Bash is parsed with tree-sitter into every nested `command` node; each yields a match string, an arity-based "always" suggestion (`git commit -m x` → `git commit *`) and the external directories its path arguments touch, which triggers a separate `external_directory` ask. Approvals reply `once | always | reject`, and a reject with typed text goes back to the model as feedback instead of ending the turn. Three identical consecutive tool calls trigger a `doom_loop` permission. Agents are markdown files (`description, mode primary|subagent, model, temperature, steps, permission, hidden`); the `task` tool creates a child session that inherits the parent's permissions minus `task` and `todowrite`, returns `<task id state>`-wrapped results, can be resumed by `task_id`, and at its `steps` cap is forced into one summarizing text turn rather than killed. Edits run a replacer chain (exact, line-trimmed, block-anchor with 0.65 similarity, then looser ones) and append LSP diagnostics. Snapshots live in a private git dir (`--git-dir` outside, `--work-tree` the project): `add -A` + `write-tree` per step, undo by `checkout <tree> -- files` and deleting files that did not exist, so shell side effects are undoable too. Tool output is pruned beyond the last 40k tokens of tool output when that frees at least 20k.

Not copied: last-match-wins ordering (order-dependent lists are fragile in a UI; we keep deny > ask > allow), `"*": allow` defaults, the unsandboxed shell with the full `process.env`, and `` !`shell` `` expansion in command templates (runs before any approval).

**Amendments (binding on the builders):**

- **cowork-1.** (a) Parse Bash with the `tree_sitter_bash` Python binding when importable to extract nested commands from `$()`, subshells and pipelines, each evaluated separately; fall back to the shlex splitter with opaque-means-ask. (b) "Always allow" suggestions use an arity table (`git, npm, yarn, pnpm, cargo, docker, kubectl, uv, pip` take the subcommand: `git commit *`, `npm run test *`, `docker compose up *`; default one token) and are editable on the card before saving. (c) Add `?` as a one-character wildcard and expand `$HOME` as well as `~`. (d) "Deny with note": the note is returned to the model as the tool result and the turn continues; a plain deny behaves as today. Store the note on the approval row. (e) Doom loop: three consecutive calls with the same tool and args digest force a card with subject `doom_loop(<tool>)` that no allow rule can downgrade; if the agentloop branch's `stuck.py` exists, hook into it instead of duplicating it. (f) `external_directory(<path>)` subject: path arguments of `cd, rm, cp, mv, mkdir, touch, chmod, chown, ln, tee` and redirect targets resolving outside the granted roots and desk workspace force an ask, shown as "outside workspace", before the command runs.
- **cowork-2.** Kill sequence is SIGTERM to the process group, then SIGKILL after 3 s. Truncate at 2000 lines or 50 KB, whichever comes first, with a hint naming `fs_grep` / offset reads and, when the agent has it, `agent_spawn`. Spilled outputs older than 7 days are swept. Seatbelt and env scrubbing stay; opencode's lack of them is the thing not to copy.
- **cowork-3.** (a) `fs_edit` tries exact, then line-trimmed, then block-anchor (first and last lines unique and exact after trimming, middle similarity ≥ 0.65 by `difflib.SequenceMatcher`), reports which matcher applied, and still errors on multiple matches unless `replace_all`. (b) Read-before-write: record `(conversation, path, mtime_ns)` whenever `read_local_file`, `fs_grep` or `fs_edit` returns content; `fs_edit` and an overwriting `write_local_file` refuse if the file was never read in this conversation or changed since. (c) After `fs_edit`/`write_local_file` on `.py` run `py_compile`, on `.json` `json.loads`, and append any error to the result.
- **cowork-4.** (a) Roles become agent definitions: markdown with frontmatter `name, description, model, steps, tools, hidden`, stored in the Library beside skills, `researcher | worker | reviewer` shipped as built-ins; user-authored ones are approve-only like skills. (b) `agent_spawn(..., resume_id?)` continues a finished child with its history. (c) Children never get `agent_spawn` past depth 2 and never get `todo_write`. (d) At `steps`, force one tool-less turn that summarizes progress and what remains, and return it with `state="partial"`; the cost cap stays a hard stop. (e) Results are wrapped `<subagent id=... state=completed|partial|error>`. (f) Concurrent `worker` children never share a writable root: overlapping roots serialize on a per-root lock. (g) Inside any loop (parent or child), once tool outputs older than the last ~40k tokens would free ≥ 20k tokens, replace them with their handle stub; skill results are exempt. If the context branch's compaction already does this, reuse it.
- **cowork-5.** Add commands as the light tier: markdown prompt templates with `$ARGUMENTS` and `$1..$n`, an optional `subtask: true` that runs the command as a child agent, and no shell or file expansion at template time.

#### cowork-6: Shadow-git snapshots and undo for agent turns (M)

**Why.** Per-file pre-images (agentloop `loop-2`) cannot undo what `shell_run` did. opencode snapshots the whole granted root in a private git dir, so any turn can be rolled back, shell effects included.

**Files.** `backend/personal_os/snapshots.py` (new), `backend/personal_os/app.py` (take a snapshot before the first mutating tool call of a reply and after the reply, record both tree hashes on the run; routes `GET /runs/{id}/changes`, `POST /runs/{id}/undo`, `POST /runs/{id}/redo`), `src/renderer/src/components/Message.tsx` (a "Files changed (n) · Undo" footer on replies that changed files), `backend/tests/test_snapshots.py` (new).

**Design.** One private repo per root at `<data>/snapshots/<sha1(root)>`, every call `git --git-dir=<that> --work-tree=<root>`. Only granted roots and desk workspaces, never all of home. Copy the root's `.git/info/exclude` and `.gitignore` semantics; skip files over 2 MB, `node_modules`, `.venv` and `.git`. `track()` = `add -A` + `write-tree` → tree hash. `changes(a, b)` = `diff --name-status`. `undo(run)` = for each changed path, `checkout <before> -- path` or delete if absent in `before`; `redo` restores the `after` tree the same way. Undo refuses (and says which files) when a file changed again after the run ended. `gc --prune=7.days` daily. Without a `git` binary, the feature reports itself unavailable and nothing else changes.

**Tests.** Offline in a tmp root: snapshot, mutate via a subprocess (create, modify, delete), changes listed, undo restores all three, redo reapplies, refusal on a later edit, the user's own `.git` untouched.

**Done when.** After a desk turn that ran `shell_run("rm draft.md && python build.py")`, Undo brings `draft.md` back and removes what the build wrote.
