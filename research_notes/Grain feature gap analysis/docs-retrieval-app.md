## What file types are ingested, how are they chunked and indexed, and what is injected into a reply?

### Takeaway
Every upload up to 20 MB is stored. PDF, Word, spreadsheets, slides, OpenDocument, EPUB, RTF, delimited text, source-like text, and (when binaries exist) scanned PDFs and images yield text; other binaries are stored with a name-only marker. Text is structure-chunked, full-text indexed, and optionally embedded. A normal reply injects the top 6 fused chunks as fenced excerpts, not the whole file.

### Cited Findings
- **Shipped — accept-any-file upload, 20 MB cap.** `POST /documents` (`upload_document` → `_store_upload` in [app.py](backend/personal_os/app.py)) reads the body, refuses past `MAX_UPLOAD_BYTES` (20 × 1024 × 1024) with HTTP 413, writes bytes under `uploads/`, and indexes extracted text. Parsing runs in a worker thread. — [extract_text.py](backend/personal_os/extract_text.py) `MAX_UPLOAD_BYTES`; [app.py](backend/personal_os/app.py) `_read_upload`, `_store_upload`, `upload_document`
- **Shipped — content-hash dedup inside one scope.** SHA-256 of the raw bytes. `Documents.find_by_hash` returns an existing live row in the same project (or personal, `project_id IS NULL`) and the route responds with `duplicate: true` instead of inserting again. — [app.py](backend/personal_os/app.py) `_store_upload`; [repos.py](backend/personal_os/repos.py) `Documents.find_by_hash`, `Documents.create`
- **Shipped — structured extraction, not “paragraphs only.”** `extract_structured` returns blocks `{kind: heading|para|table|page, level, text, page}`. PDF: per-page `pypdf` text, a `page` marker, paragraphs split on blank lines, headings only when `_guess_heading` accepts a short line (all-caps → level 1, or a short Title-Case line → level 2). DOCX: body children in order; style `Heading N` or `Title` becomes a heading; tables become pipe-markdown via `_md_table`. Markdown and other text: ATX headings, fenced code kept whole, pipe tables, blank-line paragraphs (`markdown_blocks`). CSV/TSV go through that markdown path after a line cap. — [extract_text.py](backend/personal_os/extract_text.py) `extract_structured`, `markdown_blocks`, `_guess_heading`, `_pdf_page_texts`
- **Shipped — extra formats on the plain-text path, then re-parsed as markdown.** `extract_text` / `_more_parsed`: `.xlsx`/`.xlsm` (openpyxl if installed, else stdlib zip XML; 200 rows × 30 columns per sheet, rendered as `## Sheet:` plus a pipe table), `.pptx` (slide title, body, tables, speaker notes as `## Slide N`), `.odt`/`.ods`/`.odp`, `.epub` (HTML stripped), `.rtf` (control-word strip), `.csv`/`.tsv` (first 2,000 lines). `extract_structured` falls through to `markdown_blocks(extract_text(...))` for those, so the generated `##` lines become heading blocks. — [extract_text.py](backend/personal_os/extract_text.py) `_more_parsed`, `_xlsx_text`, `_pptx_text`, `_odf_text`, `_epub_text`, `_rtf_text`, `SHEET_ROWS`, `SHEET_COLS`, `DELIMITED_LINES`
- **Shipped — a long explicit text-extension list, plus a UTF-8 sniff.** Extensions include `.txt .md .markdown .mdx .csv .tsv .json .jsonl .yaml .xml .html .css .py .ts .tsx .js .tex .org .ipynb .rtf .srt` and many source suffixes (`TEXT_EXT`). `text/*` and a few text MIMEs count. Anything else that decodes as UTF-8 with >90% printable in the first 8 KB and no NUL is kept. `.tex` is treated as text/markdown, not compiled. — [extract_text.py](backend/personal_os/extract_text.py) `TEXT_EXT`, `_looks_textual`
- **Partial — OCR is optional and bounded, not always on.** A PDF whose extracted text averages under 12 characters per page is OCRed only if both `pdftoppm` and `tesseract` are on `PATH`: first 15 pages, 150 DPI, 20 s per page, 120 s total. Images (png/jpg/jpeg/webp/tif/bmp/gif) use `tesseract` if present (30 s); otherwise the stored text is a marker that names `view_image`. OCR failure degrades to the “no text could be extracted” marker. There is no in-process OCR library. — [extract_text.py](backend/personal_os/extract_text.py) `_ocr_pdf`, `_image_text`, `_pdf_page_texts`, `OCR_PDF_PAGES`, `SCAN_CHARS_PER_PAGE`
- **Partial — index caps, not a full-text copy of a huge file.** `for_index` keeps 400,000 characters (`MAX_INDEX_CHARS`) and appends `[Extract truncated. The full file is stored.]`. PDFs stop at 80 pages (`MAX_PDF_PAGES`). Zip-based office files that declare more than 50 MB uncompressed, or a single XML part over 40 MB, are refused and stored as the no-text marker. The original bytes stay on disk. — [extract_text.py](backend/personal_os/extract_text.py) `for_index`, `_bounded`, `_check_zip`, `MAX_INDEX_CHARS`, `MAX_PDF_PAGES`, `MAX_UNZIPPED_BYTES`
- **Shipped — structure-aware chunks; paragraph packing is only the fallback.** `chunk_blocks`: max 1,200 chars, merge peers under 300, overlap 120. Heading stack; tables split by row with the header repeated; oversized prose splits on line then sentence, then a hard cut, with a word-aligned overlap tail. Small neighbours merge only when the next section is a child or a peer under the same parent, and only if the merge still fits. `ctx` is `"{title} > {heading path}\n{text}"`. `Documents._build_chunks` uses that and, on any exception or empty result, `chunk_text` (900-char paragraph pack, overlap 120 only when one paragraph exceeds 900). — [chunker.py](backend/personal_os/chunker.py) `MAX_CHARS`, `MIN_CHARS`, `OVERLAP`, `chunk_blocks`, `contextualize`, `split_text`, `split_table`; [repos.py](backend/personal_os/repos.py) `CHUNK_SIZE`, `chunk_text`, `Documents._build_chunks`
- **Shipped — two FTS tables, contextualised text in the index, clean text in the chunk row.** Uploads: `chunks(id, document_id, idx, text, heading, page)` plus `chunks_fts` (the `ctx` string). User docs: `doc_chunks` plus `doc_chunks_fts` the same way, and a separate whole-document `docs_fts(title, content)`. Tokenizer is FTS5 `porter unicode61`. `fts_query` ORs up to 12 terms of 3+ characters (`[A-Za-z0-9_]` plus internal `'`/`-`), no stopword list, no prefix on retrieval. BM25 order is SQLite `bm25()`. — [repos.py](backend/personal_os/repos.py) `fts_query`, `Documents._store_chunks`, `Documents.search`; [docs.py](backend/personal_os/docs.py) `SCHEMA` (`docs_fts`, `doc_chunks`, `doc_chunks_fts`), `_index_chunks`, `chunk_search`
- **Shipped — re-chunk without re-upload.** `POST /documents/reindex` calls `Documents.reindex`: if the file is still at `documents.path`, it re-runs `extract_structured`; otherwise it treats stored `documents.text` as markdown. Old chunk rows are deleted (embeddings cascade) and `on_chunks` schedules a new embed. — [app.py](backend/personal_os/app.py) `reindex_documents`; [repos.py](backend/personal_os/repos.py) `Documents.reindex`
- **Shipped — what a normal reply injects.** `app.py` `_doc_hits` calls `Retriever.search(..., limit` default 6`)` with sources `("files","docs")` when `useDocsInContext` is true (default), else `("files",)`. `build_context` writes a volatile block `## Relevant document excerpts` — each hit is `### {header}` plus the chunk `text` inside a fence the chunk cannot close. Header for a file is `name — heading (p.N)`, or `name (chunk N)` when both heading and page are missing. Header for a doc is `{title} (your doc) — {heading}` (docs have no page). The block is labelled data, not instructions. It is skipped when the chat’s `useDocuments` is false. `useDocsInContext: false` drops `source == "doc"` hits even if they were fetched. On any exception, `_doc_hits` returns `None` and `build_context` falls back to `documents.search` only (upload BM25, no doc chunks, no vectors). — [app.py](backend/personal_os/app.py) `_doc_hits` (around the message path near line 1428 and `context_preview`); [context.py](backend/personal_os/context.py) `build_context`, `_excerpt_header`, `_fence`; [llm.py](backend/personal_os/llm.py) `DEFAULT_SETTINGS` `useDocsInContext`, `retrievalCandidates` 20, `retrievalPerDocCap` 3
- **Shipped — recorded context is a shorter copy than the prompt.** `context_used.chunks` stores `chunk_id`, `document_id`, `name`, `idx`, `heading`, `page`, `source`, `doc_id`, and `text` truncated to 400 characters. The prompt fence gets the full chunk text (already ≤ ~1,200 characters). — [context.py](backend/personal_os/context.py) `build_context` `used["chunks"]`
- **Shipped — a second, non-retrieval injection when the turn carries page context.** If the client sends `page_context`, `build_context` adds `## What the user is looking at` (`page_block`), capped at 6,000 characters of detail and 2,000 of selection. The Docs screen sends the live editor body (unsaved edits included) clipped at 4,000 characters in the client. The Documents screen sends the open upload’s text, also clipped at 4,000. That path is the open page, not the index. — [context.py](backend/personal_os/context.py) `PAGE_DETAIL_LIMIT`, `page_block`; [app.py](backend/personal_os/app.py) message handler `page=body.page_context`; [DocsView.tsx](src/renderer/src/components/DocsView.tsx) `usePageContext`; [DocumentsView.tsx](src/renderer/src/components/DocumentsView.tsx) `usePageContext`; [pageContext.ts](src/renderer/src/lib/pageContext.ts) `clip` default 4000
- **Shipped — tools can pull more than the six excerpts.** `search_documents` (hybrid, scope `all|files|docs`, default limit 8, hard max 20, offset paging) returns `source`, `document` name, `chunk` index, `section`, `page`, `text`, and `doc_id` or `document_id`. `read_document` pages `documents.text` (default 6,000 chars, max 20,000). Both are tainted. `list_documents` is names and chunk counts in chat scope. — [tools.py](backend/personal_os/tools.py) `search_documents`, `read_document`, `list_documents`
- **Absent — old Word `.doc`, `.xls`, and a PDF viewer.** No `.doc` or `.xls` branch in `_more_parsed`. The library UI is a card list plus a `<pre>` of extracted text, not a page viewer. — [extract_text.py](backend/personal_os/extract_text.py) `_more_parsed`; [DocumentsView.tsx](src/renderer/src/components/DocumentsView.tsx)

## Are there citations back to a passage? Hybrid or embedding retrieval, or FTS only?

### Takeaway
Retrieval is hybrid: FTS5 BM25 and optional embedding KNN, fused by reciprocal rank fusion. The model is shown a heading and, for uploads, a page. The Context panel only shows the file name, “chunk N”, and a 400-character preview. Nothing highlights a passage in a viewer, and the reply text itself is not given citation markers.

### Cited Findings
- **Shipped — hybrid with a BM25 fallback, not FTS-only.** `Retriever.search` runs BM25 (`Documents.search` or `Docs.chunk_search`, up to `retrievalCandidates * 2`, default candidates 20) and, when `retrievalMode` is `hybrid` (the default), an embedding model is configured, and at least one vector exists for the current model, embeds the query and ranks by a numpy dot product of unit float32 vectors. Lists are fused with `rrf` at k=60, equal weights. Vector-only hits below `retrievalMinSimilarity` (default 0.25) are dropped; a hit that also matched BM25 is kept. `retrievalPerDocCap` (default 3) limits chunks per `(source, document_id)`. `retrievalMode=bm25`, no model, a route failure, or no stored vectors skips the vector leg. Embed errors do not raise out of `Embedder.embed` (it returns `None`). — [retrieval.py](backend/personal_os/retrieval.py) `Retriever.search`, `_vector_rank`, `RRF_K`; [embed.py](backend/personal_os/embed.py) `rrf`, `Embedder.embed`, `embed_texts`; [llm.py](backend/personal_os/llm.py) defaults
- **Shipped — embeddings are an OpenAI-shaped POST, brute force, no vector extension.** `POST {baseUrl}/v1/embeddings`, model default `qwen3-embedding-8b`, batches of 32, 10 s timeout, vectors L2-normalised before storage. After a failure that model is skipped for 300 s unless `embedder.reset()` (the embed-backfill route does this). KNN loads every in-scope blob for the current model and computes `matrix @ query`. The module comment says this is fine to about 100k chunks; that figure is a comment, not a measurement. — [embed.py](backend/personal_os/embed.py); [retrieval.py](backend/personal_os/retrieval.py) module docstring and `_vector_rank`
- **Shipped — index text is “title plus heading path plus body”, not an LLM blurb.** `contextualize` prepends `title > heading` before FTS and before the embed call. There is no second model call that writes a 50–100 token situating paragraph. — [chunker.py](backend/personal_os/chunker.py) `contextualize`; [retrieval.py](backend/personal_os/retrieval.py) `_embed_store`
- **Shipped — background embed, separate from the upload/save transaction.** Upload calls `retriever.schedule` for that file. Doc chunk rebuilds call `schedule_docs`, which waits `DOC_DEBOUNCE` (2.0 s) and then embeds the docs store. Startup schedules both. `POST /documents/embed-backfill` runs `docs.backfill_chunks()` then `embed_pending` for both stores. `GET /documents/index-status` returns `{chunks, embedded, model, mode}` and, when docs are wired, `doc_chunks` and `doc_embedded`. `Docs.__init__` also calls `backfill_chunks()` so a doc with no `doc_chunk_state` row gets chunks on process start. — [app.py](backend/personal_os/app.py) wiring near lines 461–473, `index_status`, `embed_backfill`; [retrieval.py](backend/personal_os/retrieval.py) `schedule`, `schedule_docs`, `status`; [docs.py](backend/personal_os/docs.py) `backfill_chunks`
- **Partial — citation is a header on an injected excerpt, not a link to a passage.** Prompt header includes section and page when the chunk has them (`_excerpt_header`). `search_documents` returns `section` and `page`. The Context drawer renders `name · chunk {idx+1}` and `text` only. `ContextUsed.chunks` in the shared types lists `chunk_id`, `document_id`, `name`, `idx`, `text` and does not declare `heading`, `page`, or `source`, and the drawer does not read those fields. No click-through, no PDF highlight, no inline footnote in the assistant message. The drawer’s “manage” button opens Settings → Knowledge base → Documents, which is the upload list, not the chunk. — [context.py](backend/personal_os/context.py) `_excerpt_header`; [ContextDrawer.tsx](src/renderer/src/components/ContextDrawer.tsx); [types.ts](src/shared/types.ts) `ContextUsed`; [SettingsModal.tsx](src/renderer/src/components/SettingsModal.tsx) knowledge tab
- **Absent — reranker, query splitting, neighbour expansion, pin-into-context.** `Retriever.search` has no cross-encoder or second-pass LLM rank. No query decomposition. No expansion to adjacent chunks. No setting that pins one document into every turn. (Pinning exists for memories, which is a different store.) — [retrieval.py](backend/personal_os/retrieval.py) `search`
- **Absent — index-status UI.** The HTTP route exists. The renderer has no `index-status` or `retrievalMode` string. — [app.py](backend/personal_os/app.py) `index_status`; search of `src/`

### Inferences
- Calling the system “FTS only” is wrong for the default settings, and right whenever the embedding route is down or the user sets `retrievalMode` to `bm25`.
- “Citation back to a passage” is half-shipped: the model can name a section and page because they are in the prompt; the user cannot jump to that passage from the reply.
- Hybrid fusion treats a file chunk and a doc chunk as different keys (`files:{id}` vs `docs:{id}`) in one RRF, so they compete for the same six slots.

### Gaps
- No live call confirmed that `qwen3-embedding-8b` is actually routed in the running proxy. The default string is in settings; availability is runtime.
- The “~100k chunks” bound is a comment in `retrieval.py`, not a benchmark in this tree.

## Are the user’s own docs in the same index as uploads?

### Takeaway
No. Uploads and Docs are two chunk stores with two FTS tables and two embedding tables. One retriever searches both and fuses the rankings. Whole-document `docs_fts` is a third index used only by `doc_search`. Canvas notes are in neither.

### Cited Findings
- **Shipped — parallel schemas, one ranker.** `Retriever._STORE`: files → `chunks` / `chunk_embeddings` / parent `documents`; docs → `doc_chunks` / `doc_chunk_embeddings` / parent `docs`. `search` takes `sources` and RRF-merges every store’s BM25 list and vector list together. Default argument is `sources=("files",)` but the chat path passes both when `useDocsInContext` is true. Hits are tagged `source` `file` or `doc`. — [retrieval.py](backend/personal_os/retrieval.py) `_STORE`, `ALL_SOURCES`, `search`
- **Shipped — doc chunks stay in sync with accepted text only.** `_reindex` (create, save, accept, and other writes that call it) refreshes `docs_fts` and, if `sha256(title + NUL + content)` changed, rebuilds `doc_chunks`. Unchanged autosave does not rebuild. Deleting chunks cascades vectors. Pending `propose` does not reindex. — [docs.py](backend/personal_os/docs.py) `_reindex`, `_index_chunks`, `doc_chunk_state`, `accept`
- **Shipped — scope matches for the fused search.** Both `Documents.search` and `Docs.chunk_search` use `_scope_clause`: a project chat sees that project plus personal (`project_id IS NULL`); personal sees only personal. — [repos.py](backend/personal_os/repos.py) `_scope_clause`; [docs.py](backend/personal_os/docs.py) `chunk_search`
- **Not the same index — canvas notes, memories, transcripts.** `notes.py` has no FTS and no chunk calls. Memories use `memory_index.py` (`memory_vectors`), gated by `hybridRetrieval` and the same embedding model, injected as a different block. Meeting transcripts stay on meeting tables; only an accepted summary is doc body and therefore doc chunks. — [notes.py](backend/personal_os/notes.py); [memory_index.py](backend/personal_os/memory_index.py); [docs-editor.md](docs/docs-editor.md) “What is stored where”
- **Partial — three ways to “search docs”, not one index.** (1) Auto excerpts and `search_documents` use chunk hybrid over both stores. (2) `doc_search` uses whole-document `docs_fts` and is unscoped. (3) Page context dumps the open editor, clipped, without searching. — [tools.py](backend/personal_os/tools.py); [context.py](backend/personal_os/context.py)

### Inferences
- A fact that exists only in a Docs note is eligible for ordinary chat retrieval without `doc_search`, as long as `useDocuments` and `useDocsInContext` are on and the note is in scope. That is the opposite of the retrieval research note’s “where we are” section.
- Sharing a ranker is not sharing a table. Reindexing uploads does not rebuild doc chunks, and a doc id cannot collide with a file chunk id inside one embedding table because the tables are separate.

### Gaps
- Trash/restore behaviour for `doc_chunks` was not re-read. Deleted docs are excluded by `deleted_at IS NULL` in `chunk_search`. Whether a purge cascades `doc_chunks` is implied by `REFERENCES docs(id) ON DELETE CASCADE` and was not executed.
