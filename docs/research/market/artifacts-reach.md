# Artifacts, dashboards, charts, web research, and code sandboxes

Researched 2026-10-02 from primary help and developer docs. Products are named because the assignment is a market comparison. No Grain code was reviewed. Snippets that could not be re-fetched in full are marked.

## What happened to Claude artifacts and ChatGPT canvas by late 2026, and what interactive artifacts do desktop assistants ship now?

### Takeaway
Claude did not retire artifacts. By early October 2026 it had replaced the old chat artifact with a saved, shareable object (documents, decks, designs, dashboards, small tools) on web and Claude Desktop, and it froze pre-16 September 2026 artifacts as legacy. OpenAI removed Canvas from GPT-5.5 Instant and GPT-5.5 Thinking on 28 May 2026 and moved writing and coding into in-chat writing blocks and code blocks; a full-screen writing editor and in-answer interactive charts followed on 8 June 2026, documented for web (charts also on iOS and Android), not named for the desktop app.

### Cited Findings
- Anthropic’s current artifacts help (the older article id and a newer one returned the same page) defines an artifact as something you would put in front of someone: a design, a deck, a document, a dashboard, or a small interactive tool. It opens beside the conversation. Artifacts exist on Free, Pro, Max, Team, and Enterprise, and in Claude Code on every plan that includes Claude Code. Templates (Claude Design, Claude Slides, Claude Docs) are in beta on paid plans, on by default for Pro, Max, and Team, and off on Enterprise until an owner enables each one. They require “Cloud code execution and file creation” under Settings > Capabilities (or Organization settings on Team and Enterprise). — [Claude Help: What are artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them); same body at [the older article id](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them)
- Legacy artifacts are ones made in a chat before 16 September 2026. They keep working and can still be published and shared, but new ones of that kind cannot be made. Claude still creates an artifact for content that is significant and self-contained (typically over 15 lines), likely to be edited or reused, and able to stand without the chat. Types listed include documents, code snippets, single-page websites, images, diagrams, flowcharts, dashboards, and small interactive tools. — [Claude Help: What are artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)
- Surfaces: Claude on the web and Claude Desktop can create, edit, and share artifacts and start from a template. Claude Code can publish session output as an artifact or make designs and docs. iOS and Android can ask for a design, deck, or doc and view it in the Artifacts tab; starting from a template, editing, or changing sharing is web or Claude Desktop. Saved artifacts live in an Artifacts tab in the sidebar. Template artifacts open on a canvas or page you can edit directly (type in a doc, edit a slide, move elements). Markdown can be highlighted and sent to “Edit with Claude.” — [Claude Help: What are artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)
- Exports: template artifacts export from an Export control. Docs go to Word, PDF, Markdown, and Google Docs. Decks go to PowerPoint and PDF. Designs go to a .zip, PDF, PowerPoint, standalone HTML, or another tool. Legacy artifacts use panel controls to view code, copy, or download. — [Claude Help: What are artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)
- Claude Code publishes a live page on claude.ai that updates in place. Examples in the docs: annotated pull-request diffs, a dashboard of deploy failures, side-by-side design options, an investigation timeline, and a status board that refreshes through MCP connectors. On the desktop app the doc opens in the side panel; in the terminal Claude returns a web link. Publishing from the desktop app requires version 1.13576.0 or later, a claude.ai login, and the Anthropic API (not Bedrock, Google Cloud Agent Platform, or Microsoft Foundry). Sessions authenticated with an API key, gateway token, or cloud-provider credential cannot publish. `/design` and `/slides` need Claude Code v2.1.265 or later. — [Claude Code docs: Artifacts](https://code.claude.com/docs/en/artifacts.md); [Claude Help: What are artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)
- Cowork’s older “live artifacts” stopped being creatable on 19 August 2026. Ones made before that date stay viewable and cannot be edited in place; Share offers a republish into the new system. The updated system is generally available on Pro, Max, Team, and Enterprise for Cowork in Claude Desktop and Cowork in the cloud, and new Cowork artifacts open on the web. A later help note says Cowork and chat are becoming one Claude, rolling out gradually to Pro and Max, while Team and Enterprise still keep them separate. — [Claude Help: Use artifacts in Claude Cowork](https://support.claude.com/en/articles/14729249-use-artifacts-in-claude-cowork); [Claude Help: Cowork architecture](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview)
- OpenAI’s model release notes for 28 May 2026: “With this update, canvas will no longer be available in GPT-5.5 Instant or GPT-5.5 Thinking. Writing and coding functionality is now supported directly in chat responses through writing blocks and code blocks. Paid users can continue using canvas for a limited time through legacy models until those models are sunset.” The same day’s ChatGPT release notes repeat that sentence. The same notes retire o3 from ChatGPT on 26 August 2026 and GPT-4.5 on 26 June 2026. — [OpenAI Help: Model release notes](https://help.openai.com/en/articles/9624314-model-release-notes/); [OpenAI Help: ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-can-now-generate-images); [The Verge, 29 May 2026](https://www.theverge.com/ai-artificial-intelligence/940028/openai-is-sunsetting-chatgpts-canvas-interface)
- On 8 June 2026 ChatGPT release notes, under Web, iOS, and Android: “Interactive charts in answers” — bar, line, pie, and scatter charts in the conversation, either when asked or when ChatGPT decides a chart helps. Under Web only: full-screen writing blocks for essays, PRDs, reports, blog posts, notes, and other document work; longer writing opens in a focused full-screen editor; documents can be saved to the Library; the editor adds a wider layout, titles, a table of contents, download, and undo/redo. — [OpenAI Help: ChatGPT release notes, 8 June 2026](https://help.openai.com/en/articles/6825453-chatgpt-can-now-generate-images)
- Earlier, 19 February 2026: interactive code blocks can be written and edited in line, can preview diagrams and mini apps in chat, and can be reviewed in a split-screen view. — [OpenAI Help: ChatGPT release notes, 19 February 2026](https://help.openai.com/en/articles/6825453-chatgpt-can-now-generate-images)
- The ChatGPT desktop app’s documented agent surface, as of the current sandbox docs, is a permissions control under the composer (Ask for approval, Approve for me, Full access, and named profiles), not a Canvas pane. ChatGPT web does not expose the local Codex sandbox selector. — [ChatGPT Learn: Sandbox](https://learn.chatgpt.com/docs/sandboxing)
- A separate first-party dashboard, not a generated artifact: from 15 May 2026, ChatGPT Finances (Pro, United States, web and iOS) connects accounts through Plaid and shows spending, bills, subscriptions, net worth, and investments. It cannot move money. — [OpenAI Help: ChatGPT release notes, 15 May 2026](https://help.openai.com/en/articles/6825453-chatgpt-can-now-generate-images)
- Gemini’s Deep Research agent (preview, Interactions API only) can include visualizations such as charts and graphs in cited reports, and can take documents as input. Default tools are Google Search, URL context, and code execution. Consumer Gemini “canvas” was not covered by the pages fetched. — [Gemini API: Deep Research](https://ai.google.dev/gemini-api/docs/deep-research)

### Inferences
- The 2026 split is a side-by-side saved object (Claude) versus an in-transcript block that can expand to a full-screen editor (ChatGPT). Desktop assistants still ship both kinds of surface: Claude Desktop keeps the artifact pane and Cowork/Code publishing; the ChatGPT desktop app’s documented interactive work is the agent permissions UI, code/writing blocks in chat, and Computer Use, not the old Canvas.
- Charts are no longer only “ask for a React dashboard.” ChatGPT renders a small set of interactive chart types inside the answer. Claude still treats a dashboard as an artifact page, or as a PNG from the code-execution environment.

### Gaps
- The Canvas help article still resolves and, when fetched, showed a title and “Updated: 10 days ago” with no how-to body ([OpenAI Help: canvas](https://help.openai.com/en/articles/9930697)). OpenAI does not say, in the pages read, whether any model still opens Canvas after the 26 August 2026 o3 retirement. Secondary guides disagree: one treats Canvas as gone ([felloai, citing the 28 May notes](https://felloai.com/chatgpt-canvas/)); another, reviewed 31 July 2026, still lists Canvas on web and the Windows and macOS apps except on pro-series models and GPT-5.5 and later ([theappguides](https://theappguides.com/chatgpt/how-to-use-chatgpt-canvas/)). The release notes are the primary source; they do not inventory remaining Canvas-capable models as of 2 October 2026.
- Full-screen writing blocks and in-answer charts are explicitly tagged Web, or Web plus mobile. The release notes do not say the ChatGPT macOS or Windows app has those views.
- No 2026 primary page was fetched for a Gemini or Perplexity desktop artifact/canvas equivalent.

## How do leading apps sandbox generated widgets and keep API keys out of the widget?

### Takeaway
Both Claude artifacts and ChatGPT app widgets run on a separate sandbox origin. Privileged calls are made by the host with the viewer’s own connection. The page is not given the author’s API key. Claude states this directly for AI-backed artifacts and for connector calls. ChatGPT states the iframe, the sandbox origin, and a per-widget connect/resource/frame allowlist; an OpenAI-hosted builder write-up adds that the widget should not hold secrets.

### Cited Findings
- Claude artifacts that call Claude run on Anthropic’s infrastructure. People sign in with their own Claude account and use their own plan limits. “No API keys are required.” Legacy artifacts can disable this with an AI-powered artifacts setting; new artifacts ask permission the first time they want to use Claude. — [Claude Help: What are artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)
- Artifacts can read and write apps the user has connected (examples named: Asana, Google Calendar, Slack, plus custom connectors) on Pro, Max, Team, and Enterprise, web and desktop. The first use shows which apps and tools will run and asks for approval; individual tools can be turned off, and that choice persists. Connector tools that need approval on every action are not available to artifacts. Each person connects their own apps, including on a shared artifact. — [Claude Help: What are artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)
- Claude Code’s connector model: the published page declares which connectors it may call and cannot call others. On view, each call uses the viewing account’s connection, not the publisher’s. “The page never sees anyone’s credentials; claude.ai makes the calls on the page’s behalf.” Viewers approve before the first call. A viewer who declines, or who is signed out on a public link, still sees the page without live sections. Local MCP servers can feed the build, but the published page cannot call them. File downloads the page starts itself, including `data:` and `blob:` URLs, are blocked; a declared downloads capability is required. — [Claude Code docs: Artifacts](https://code.claude.com/docs/en/artifacts.md)
- The same docs: the viewer loads each artifact from a sandboxed `*.claudeusercontent.com` origin. The page is one HTML document under a strict CSP. It may load typefaces from Google Fonts and scripts from five CDN hosts (cdnjs, unpkg, the Tailwind CDN, the jQuery CDN, and selected jsDelivr `/npm/` paths). The CSP blocks every external image and all other external scripts, stylesheets, and fonts. `fetch`, XHR, and WebSocket may reach only the page’s own origin and the Google Fonts hosts. Images are data URIs. There is no backend and the page cannot authenticate viewers itself. Rendered size limit is 16 MiB. — [Claude Code docs: Artifacts](https://code.claude.com/docs/en/artifacts.md)
- Persistent artifact storage (Pro, Max, Team, Enterprise, web and desktop) is text only, 20 MB per artifact, split into personal storage (each user sees only their own) and shared storage (everyone sees the same data). The builder chooses which is which. Shared storage shows a confirmation. Legacy storage works only after publish, and unpublishing a legacy artifact deletes its stored data. New artifacts can store without publishing. — [Claude Help: What are artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)
- ChatGPT plugin UI runs in an iframe. The resource domain defaults to `https://web-sandbox.oaiusercontent.com`. CSP is declared on the resource as `_meta.ui.csp`: `connectDomains` for fetch/XHR, `resourceDomains` for images, fonts, scripts, and styles, and optional `frameDomains`. Subframes are off unless `frameDomains` is set, and setting it triggers a stricter review. The widget calls tools through `window.openai.callTool` (or the MCP Apps bridge), which mirrors a model-initiated tool call, rather than embedding a credential. Widget state is a UI snapshot via `setWidgetState`; `structuredContent` is visible to both the widget and the model. — [OpenAI Developers: Plugins reference](https://developers.openai.com/plugins/reference); [OpenAI Developers: Build your ChatGPT UI](https://developers.openai.com/apps-sdk/build/chatgpt-ui)
- A 4 February 2026 post on OpenAI’s developer blog, written by an Apps SDK builder rather than OpenAI staff, says ChatGPT renders apps in a double-nested iframe, widgets are served under `.web-sandbox.oaiusercontent.com`, and connect, resource, frame, and redirect domains must be declared or requests fail. It also says tool calls are slow because of “security sandboxing,” and that a widget may XHR a public API when it does not need to tell the model. It does not quote an OpenAI rule that forbids placing an API key in widget source. — [OpenAI Developers blog, 4 February 2026](https://developers.openai.com/blog/15-lessons-building-chatgpt-apps)
- Cowork cloud sessions, a related isolation fact: connector authorization tokens never enter the sandbox; connector calls are made server-side. The sandbox holds only session-scoped tokens that expire within hours. Egress goes through a proxy the sandbox cannot reconfigure. — [Claude Help: Cowork architecture](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview)

### Inferences
- The stable pattern is: untrusted UI on its own origin, a host-owned allowlist, and a broker that attaches the user’s credential after an approval. The generated page is a client. Keys live in the host or in the user’s connected account.
- “No API key in the widget” is an explicit product claim for Claude’s built-in model calls and connector calls. For ChatGPT Apps it is the shape of the API (CSP plus `callTool`) more than a single sentence that says “never put a key in the HTML.” A builder can still ship a key inside widget source if they ignore that shape; the platform does not appear, in the official reference fetched, to scan widget source for secrets.

### Gaps
- No Anthropic help page fetched here prints the literal CSP directive list (`connect-src`, `frame-src`). The Claude Code artifacts page describes the effects of the policy. A third-party write-up that names those directives ([clawnify](https://www.clawnify.com/resources/claude-artifacts-explained)) was not used as a source.
- The official plugins reference does not say “do not put API keys in `widgetState`.” That warning shows up on secondary walkthroughs, not in the OpenAI reference pages fetched.
- Whether ChatGPT Apps widgets render inside the macOS/Windows desktop app, as opposed to ChatGPT on the web, is not stated in the UI reference.

## What do strong web-research tools ship (citations, fetch, site and time filters)?

### Takeaway
Citations and a way to read a specific URL are standard on Claude, ChatGPT, Perplexity’s APIs, and Gemini Deep Research. Site allow/deny is a first-class control on the Claude API, the Perplexity Search and Sonar APIs, and ChatGPT Deep Research (specific sites, or prioritize-but-still-search-the-web). A real time filter (hour/day/week/month/year, or publication and last-updated dates) is documented for Perplexity’s APIs. Claude’s consumer research help and the ChatGPT pages fetched do not document a time-range control.

### Cited Findings
- Claude consumer web search, help updated the week of this research, is available on listed current models (Sonnet 5.5, Opus 5.5, Fable 5.1, Opus 5, Sonnet 5, Fable 5, Opus 4.8, Opus 4.7, Sonnet 4.6, Opus 4.6, Haiku 4.5). Every response includes citations, source links, and quotes when appropriate. With web search on, Claude can also web-fetch a URL the user supplies and pull the page into context; the help warns that a long article consumes a large share of a free account’s limit. Image results are part of web search and are powered by Bing, each image with a source link. Location may be inferred from IP. On the “new Claude experience” there is no web search toggle; Claude searches when it helps. Team/Enterprise owners must enable web search before members can. — [Claude Help: Web search](https://support.claude.com/en/articles/10684626-enable-and-use-web-search)
- Claude Research (help dated 2 June 2026) is on paid plans (Pro, Max, Team, Enterprise) on web, Claude Desktop, and mobile. It requires web search. It runs multiple searches, can use connected internal context (Gmail, Google Calendar, Google Docs are the examples), and returns answers with citations. The help does not mention a site list or a time filter. Usage counts against normal plan limits, faster because more sources are retrieved. — [Claude Help: Research](https://support.claude.com/en/articles/11088861-use-research-on-claude)
- Claude API web search always returns citations. Each `web_search_result_location` includes `url`, `title`, `encrypted_index`, and `cited_text` of up to 150 characters; those three citation fields are not billed as tokens. Domain control is `allowed_domains` or `blocked_domains`, not both (both yields HTTP 400). Entries are bare domains with an optional path (`example.com` or `example.com/blog`), no scheme. `max_uses` caps searches per request. `user_location` takes city, region, ISO country, and IANA timezone. Versions: `web_search_20250305` (basic), `web_search_20260209` (dynamic filtering), `web_search_20260318` (response inclusion). From `web_search_20260209`, Claude can filter results in code execution before they enter context; that path is the default caller. Dynamic filtering is documented for Claude 4.6 and later and for Mythos Preview. — [Claude API: Web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)
- ChatGPT’s academy page distinguishes quick search (a short summary with links) from deep research (multi-step, often 5–30 minutes, documented output with citations). It says citations should be checked, search does not replace subscription databases, and workspace owners can disable search. The prompt guidance includes timeframe as something the user should put in the question, not as a filter control. — [OpenAI Academy: Search and deep research](https://openai.com/academy/search-and-deep-research/)
- The indexed OpenAI Help page for deep research (live fetch returned 403, so this is the search excerpt, not a full re-read) says deep research can use uploaded files, the public web or specific sites, and enabled apps, and returns a report with citations or source links. Sites are set at Sites > Manage sites: either restrict to the domains entered, or “Prioritize these sites, but allow full-web search.” Domains can be a comma-separated list. Completed research opens in a fullscreen report. The excerpt does not mention a time filter. — [OpenAI Help: Deep research](https://help.openai.com/en/articles/10500283-search-in-chatgpt) (403 on direct fetch, 2026-10-02)
- The same site-control wording appears on an OpenAI Academy deep-research resource: set Sites / allowed domains to restrict, or to prioritize while still searching the open web; apps are read-only authenticated sources; interrupt and edit the plan while it runs. — [OpenAI Academy: Deep research](https://academy.openai.com/en/public/clubs/work-users-ynjqu/resources/deep-research)
- ChatGPT’s marketing page says deep research uses authenticated sources, approved URLs, and apps, and that a user can edit the plan, sources, and constraints or interrupt. It repeats “30-minute reports.” — [ChatGPT: Deep research](https://chatgpt.com/features/deep-research/)
- Codex, separate from ChatGPT search, defaults `web_search` to `"cached"` (an OpenAI index, not a live fetch). `"live"` fetches pages. `"disabled"` turns the tool off. Cached mode is described as reducing prompt injection from arbitrary live pages. The command network proxy does not filter web search. — [ChatGPT Learn: Agent approvals and security](https://learn.chatgpt.com/docs/agent-approvals-security)
- Lockdown Mode (all logged-in ChatGPT users as of 4 June 2026) restricts live web browsing, deep research, agent mode, file downloads, and some web-derived images. — [OpenAI Help: ChatGPT release notes, 4 June 2026](https://help.openai.com/en/articles/6825453-chatgpt-can-now-generate-images)
- Perplexity’s Search API returns ranked results and says to use the Agent API when you want an LLM answer with citations. `search_domain_filter` takes at most 20 domains, allowlist or denylist (prefix `-`), not both. Filters can be a root domain, a TLD, a domain part, or a path prefix matched on path-segment boundaries (`example.com/docs` matches `/docs` and `/docs/intro`, not `/documentation`). Date controls: `search_after_date_filter` / `search_before_date_filter` (publication, `MM/DD/YYYY`), `last_updated_after_filter` / `last_updated_before_filter`, and `search_recency_filter` of `hour`, `day`, `week`, `month`, or `year`. The same domain and date parameters are documented for Sonar. Language filter is up to 20 ISO 639-1 codes. — [Perplexity: Search API](https://docs.perplexity.ai/docs/search/quickstart); [Perplexity: Date and time filters](https://docs.perplexity.ai/docs/search/filters/date-time-filters); [Perplexity: Domain filter](https://docs.perplexity.ai/docs/search/filters/domain-filter); [Perplexity: Sonar filters](https://docs.perplexity.ai/docs/sonar/filters)
- Gemini Deep Research (`deep-research-preview-04-2026` and `deep-research-max-preview-04-2026`, preview, Interactions API, model card latest update April 2026) plans and runs multi-step research and returns cited reports. Default tools: `google_search`, `url_context` (read and summarize a page), `code_execution`. Optional: MCP servers and file search. Output can include charts. The docs tell the caller to review the `citations` field because the agent reads the public web. A Google blog post on the same pair of agents says reports are fully cited and can mix the open web with proprietary data. Gemini Enterprise’s Deep Research (docs last updated 2026-08-18 UTC) streams a plan, cites sources, and adds a 1–2 minute audio summary; web results are optional on top of indexed app data. — [Gemini API: Deep Research](https://ai.google.dev/gemini-api/docs/deep-research); [Gemini API model card](https://ai.google.dev/gemini-api/docs/models/deep-research-preview-04-2026); [Google blog: Deep Research and Deep Research Max](https://blog.google/innovation-and-ai/models-and-research/gemini-models/next-generation-gemini-deep-research/); [Gemini Enterprise docs](https://docs.cloud.google.cn/gemini/enterprise/docs/research-assistant)

### Inferences
- A strong research tool in this set is: citations you can open, a fetch of a named URL, and a way to pin or drop sites. Time range is the feature that separates Perplexity’s API from the Claude and ChatGPT consumer docs read here. ChatGPT’s equivalent of a time bound, in the academy guide, is prose in the prompt.
- Claude’s consumer product and Claude’s API are different products on filters. The chat help has citations and fetch and no domain list. The API has allow and block lists and no publication-date parameter in the tool schema that was read.

### Gaps
- The OpenAI deep-research help page returned 403, so the Sites > Manage sites behavior is from the indexed excerpt plus the Academy page, not a full article read.
- No consumer Perplexity UI page was fetched. The filters above are API parameters. Whether the Perplexity app exposes the same hour/day/week control and 20-domain list on 2 October 2026 was not verified.
- No time-range parameter was found in the Claude API web-search schema (location and domain lists, not dates). No ChatGPT time-filter control was found.
- Gemini’s docs do not, in the pages read, document a site allowlist or a recency enum for Deep Research.

## What isolation do local Python or code sandboxes use in personal AI apps?

### Takeaway
There are three different sandboxes, and the docs do not treat them as one. Chat analysis (Claude file creation, ChatGPT data analysis) runs in a hosted container that is not shared between users, with network either off, limited to package registries, or allowlisted. Local agent shells (Claude Code, Codex in the ChatGPT desktop app) use the OS: Seatbelt on macOS, bubblewrap plus seccomp on Linux, a Windows sandbox natively. Cowork on the desktop runs shell and model-written code in a Linux VM (Apple Virtualization.framework on macOS, Hyper-V on Windows) while the agent loop stays on the host. Network defaults to off for local agent commands. Secrets are kept out by not putting them in the sandbox and by brokering connector calls outside it.

### Cited Findings
- Claude “code execution and file creation” (help dated 6 August 2026) is on Free, Pro, Max, Team, and Enterprise, on web, Claude Desktop, and mobile. It runs in an isolated sandboxed container, separate from the user’s systems, and sandboxes are not shared between users. It writes and runs Python or JavaScript, produces xlsx, pptx, docx, and PDF, and can chart data as PNG. Upload and download limit is 30 MB per file. Free, Pro, and Max have network egress on by default so packages can be installed from approved sources. Team defaults to package managers only. New Enterprise orgs default to egress off. Owners can choose off, package managers only, package managers plus named domains, or all domains except Anthropic’s legal blocklist. The published package-manager allowlist names api.anthropic.com, statsig.anthropic.com, github.com, npm registries, PyPI hosts, crates.io, Ubuntu archives, and Yarn. The help says disabling egress stops data leaving the sandbox, and that MCP can still make network calls when MCP is enabled. Other stated limits: task duration and how long one container may be reused, resource caps, a prompt-injection classifier, and no public sharing of chats that contain these file artifacts for Free, Pro, and Max. — [Claude Help: Create and edit files](https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude)
- Cowork local sessions, same architecture on every plan: the agent loop (conversation, folder reads and writes, web fetches, local plugin MCP) runs on the device under an application permission check. Shell commands and code Claude writes run in a dedicated Linux VM, isolated by Apple Virtualization.framework on macOS and Hyper-V on Windows, with the VM’s own network egress filtering, syscall restrictions, and per-session user isolation. If the VM cannot start, file and web tools still run and shell/code report “workspace unavailable.” Host EDR cannot see inside the VM. Cloud sessions are a separate temporary sandbox per session, destroyed when the session ends, with no path to private, link-local, or cloud-metadata addresses, and with connector tokens kept server-side. — [Claude Help: Cowork architecture](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview)
- Claude Code’s Bash sandbox is local, not a remote Python container. macOS uses Seatbelt with nothing to install. Linux and WSL2 use bubblewrap for filesystem isolation and socat to relay network through a proxy; an optional seccomp filter blocks Unix sockets. Native Windows is unsupported. Default writes are the working directory and the session temp directory, enforced for child processes. A new network domain prompts, or goes to the classifier in auto mode. If the sandbox cannot start, the default is to warn and run unsandboxed; `sandbox.failIfUnavailable` makes that a hard failure. An escape hatch can retry outside the sandbox with a permission prompt; strict mode disables that escape. The docs say the OS boundary is the enforcement, and that dev containers or a VM are the stronger options when the whole process (file tools, MCP, hooks), not only Bash, must be isolated. — [Claude Code docs: Sandboxing](https://code.claude.com/docs/en/sandboxing); [Claude Code docs: Sandbox environments](https://code.claude.com/docs/en/sandbox-environments)
- ChatGPT data analysis (official help; direct fetch timed out, wording is the indexed help excerpt): for some tasks ChatGPT writes and runs Python in a stateful Jupyter notebook, can use files in the session, and can show pandas DataFrames as interactive tables. “The Python environment used for data analysis cannot make external web requests or API calls.” External data has to be uploaded or connected first. — [OpenAI Help: Data analysis](https://help.openai.com/en/articles/8437071-advanced-data-analysis)
- The Code Interpreter API, a developer product rather than the ChatGPT app, describes the container as a fully sandboxed virtual machine. Memory tiers are 1 GB (default), 4 GB, 16 GB, or 64 GB for the life of the container. A container expires after 20 minutes without use; metadata remains, data is discarded. — [OpenAI API: Code Interpreter](https://developers.openai.com/api/docs/guides/tools-code-interpreter)
- Codex local execution, including the ChatGPT desktop app and the CLI: the sandbox applies to spawned commands (`git`, package managers, test runners), not only file tools. Default is network off. `workspace-write` can read, edit inside the workspace, and run routine local commands; it is the default low-friction mode. `read-only` cannot edit or run commands without approval. `danger-full-access` removes filesystem and network boundaries. Approval policy is separate: `on-request` asks when leaving the sandbox; `never` does not ask. macOS uses Seatbelt via `sandbox-exec` with a profile for the selected mode. Linux uses `bwrap` plus seccomp. Native Windows uses a Windows sandbox; WSL2 uses the Linux implementation (`bwrap` from Codex 0.115; WSL1 is unsupported). On macOS, Seatbelt works with nothing extra installed. In `workspace-write`, `.git`, `.agents`, and `.codex` under a writable root stay read-only. When network is enabled, an optional proxy is allowlist-first, deny wins, blocks loopback and private addresses unless an exact exception is set, and blocks hostnames that resolve to non-public IPs. The proxy does not cover web search, MCP, the browser, or Computer Use. Version-controlled folders are recommended as Auto (workspace write plus on-request); other folders as read-only. — [ChatGPT Learn: Sandbox](https://learn.chatgpt.com/docs/sandboxing); [ChatGPT Learn: Agent approvals and security](https://learn.chatgpt.com/docs/agent-approvals-security)
- Codex Cloud (legacy, called out as legacy in the same security doc) uses OpenAI-managed containers. Setup can use the network to install dependencies; the agent phase is offline unless internet is enabled. Secrets configured for the environment are available only during setup and are removed before the agent phase. — [ChatGPT Learn: Agent approvals and security](https://learn.chatgpt.com/docs/agent-approvals-security)
- OpenAI’s own cookbook for a self-hosted interpreter tells builders not to run model-written code on the host: use a container with no network and no host filesystem mount. That is guidance for people building an agent, not a description of the ChatGPT app. — [OpenAI Cookbook: secure code interpreter](https://developers.openai.com/cookbook/examples/object_oriented_agentic_approach/secure_code_interpreter_tool_for_llm_agents)

### Inferences
- “Python sandbox” in the chat products is a remote, ephemeral, per-user container with no general internet. “Local sandbox” in the desktop agent products is an OS profile or a hypervisor VM, workspace-scoped writes, network denied until an approval or an allowlist.
- The secret-handling rule that shows up in more than one product is: credentials are not environment variables of the code runner. Connector calls are proxied. Cloud setup secrets are stripped before the agent phase. A local app that injects the model API key into the analysis process would be outside this pattern.

## Which of these matter for a local single-user desktop app?

### Takeaway
The features that transfer are a durable editable surface (side panel or full-screen document, plus in-chat charts), host-brokered tools so generated UI never sees provider keys, citations plus URL fetch plus an optional site allow/deny, and a local code boundary with network off by default. Org sharing, per-viewer connector accounts, and a remote multi-tenant container matter less for one person on one machine. A hypervisor VM is what Cowork uses; Seatbelt-style OS enforcement is what Codex and Claude Code use for the same job and is the lighter local default.

### Cited Findings
- Claude Desktop already creates, edits, and shares artifacts, and Cowork-on-desktop runs code in a per-session VM while files stay on the device under folder permissions. — [Claude Help: What are artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them); [Claude Help: Cowork architecture](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview)

- Credential separation is a host concern even for a single user: Claude’s page never sees connector credentials, and Cowork’s cloud sandbox never receives connector tokens. ChatGPT widgets get a sandbox origin and a tool bridge instead of a raw key. — [Claude Code docs: Artifacts](https://code.claude.com/docs/en/artifacts.md); [Claude Help: Cowork architecture](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview); [OpenAI Developers: Plugins reference](https://developers.openai.com/plugins/reference)

### Inferences
- For one user on one desktop, the artifact that matters is the one they reopen tomorrow: a saved document, deck, or small interactive page, edited in place or by highlighting a span. Multi-user roles, public links, and “usage bills the viewer” do not transfer.
- Generated dashboards still need a sandbox, because the threat is the page reading the app’s own keys or calling arbitrary hosts, not a second tenant. A separate origin or a webview with no parent secrets, plus a broker for tools, matches both Claude and ChatGPT. Sharing storage and per-viewer OAuth matter only if the page is published.
- Citations and fetch are the research baseline. A site allow/deny is the control worth copying from ChatGPT deep research and the Claude and Perplexity APIs. A recency enum is what Perplexity documents and the others, in these pages, leave to the prompt.
- Code: a remote container is how the chat products analyze a CSV without touching the laptop. A local assistant that already runs on the machine can follow Codex and Claude Code instead: OS sandbox, workspace writes, network denied, secrets absent from the environment, and an explicit approval to leave that box. Cowork’s VM is the stricter local option, and Anthropic uses it for code while leaving ordinary file and web tools on the host. Copying only the VM, or only the container, would miss that split.

### Gaps
- These notes do not score a specific local app. They only say which shipped behaviors are about multi-user hosting and which are about untrusted model output on a single machine.
- Desktop parity for ChatGPT’s June 2026 charts and full-screen editor was not documented, so it is unclear whether a desktop user of ChatGPT actually has those views or only the web app does.
