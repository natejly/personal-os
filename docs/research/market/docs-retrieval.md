# Document retrieval and notes-editor UX (market, as of 2026-10-02)

Scope: Claude Projects, Gemini Notebook (help-center name for the NotebookLM product), Open WebUI, and linked-note apps (Obsidian, Logseq, Notion, Craft). Retrieval-practice evidence is limited to pages actually opened or, where noted, to a search snippet after a full fetch failed. Older than 2025 is marked. No Grain codebase audit.

## What do Claude Projects, NotebookLM, Open WebUI, and similar apps do for project knowledge, citations, and full-document versus search?

### Takeaway

The shipped pattern is a size threshold, not “always RAG”: keep the whole project or file in context while it fits, and switch to search when it does not. Citations are a separate product choice. Gemini Notebook cites source passages; Claude’s project-knowledge help describes a search tool and does not document passage citations; Open WebUI says RAG adds citations but does not specify a click-through to a quote.

### Cited Findings

- Claude Projects are self-contained workspaces with their own chat histories and a knowledge base. Uploaded documents, text, code, or other files are used across chats in that project. Project instructions apply to every chat in the project. Context is not shared across chats unless it is added to the knowledge base. — [What are projects?](https://support.claude.com/en/articles/9517075-what-are-projects); [How can I create and manage projects?](https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects)
- On paid plans (Pro, Max, Team, Enterprise), RAG turns on automatically when project knowledge approaches the context-window limit, and the help center says this expands capacity by up to 10x. A visual indicator shows RAG is on. If knowledge later drops under the threshold, Claude can switch back to loading the project in context. The user cannot choose when RAG runs. The help center says in-context processing is used when possible, and that RAG “maintains consistent response quality” with in-context processing. That quality claim is not backed by a published eval on the help page. — [RAG for projects](https://support.claude.com/en/articles/11473015-retrieval-augmented-generation-rag-for-projects) (page said “updated over 3 weeks ago” when fetched on 2026-10-02)
- In RAG mode, Claude uses a project knowledge search tool and retrieves “only the most relevant information” instead of loading all project content. The help page’s best practices are descriptive filenames, grouping related files in one project, and naming a document in the question. It does not document chunk size, hybrid search, reranking, or inline citations for project files. RAG is said to work with web search, extended thinking, and Research. — [RAG for projects](https://support.claude.com/en/articles/11473015-retrieval-augmented-generation-rag-for-projects)
- A different Claude surface, Enterprise “Ask your org” search, does claim “comprehensive, well-cited responses” over connected tools (Slack, Microsoft 365, and others). That is connector search, not the project-file RAG article. — [Use enterprise search](https://support.claude.com/en/articles/12489464-use-enterprise-search)
- On the API, custom RAG can return `search_result` blocks and Claude will cite them when citations are enabled. Citations are off by default on those blocks. The text block is the minimal citable unit: Claude cites whole blocks, not a substring inside a block, and finer citations require splitting content into smaller blocks. `cited_text` is the full text of the cited slice. All active models support this except Claude Haiku 3. This is a developer mechanism, not a description of the Projects UI. — [Search results](https://platform.claude.com/docs/en/build-with-claude/search-results)
- Web search citations are a third path: they are always on, and each `web_search_result_location` includes url, title, and `cited_text` capped at 150 characters. — [Web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)
- **Older (2024-09-19), still the primary Anthropic engineering write-up:** if the knowledge base is under 200,000 tokens (they say about 500 pages), put the whole base in the prompt and skip RAG. Prompt caching is what makes that cheap. Above that, they describe chunking, embeddings, BM25, and rank fusion. — [Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)
- Google’s help center titles the product Gemini Notebook. It says chat answers are grounded in uploaded sources “with clear in-line citations.” Sources can be PDFs, websites, YouTube, audio, Google Docs, or Google Slides. — [Learn about Gemini Notebook](https://support.google.com/notebooklm/answer/16164461?hl=en)
- Official FAQ: if a source is too short, Gemini Notebook references the entire document and does not cite an individual passage. When a notebook has many sources, it “retrieves the most relevant information based on your question, then builds a response from it,” and a vague question makes that retrieval worse. If the answer is not in the sources, it will not answer from outside them. Sources are always used, either the full set or the subset the user selects. Notes are used only when the user selects them. Conversation history is used. — [Gemini Notebook FAQ](https://support.google.com/notebooklm/answer/16269187?hl=en)
- Per-source cap on the FAQ: 500,000 words or 200MB for local uploads, no page limit. Import fails if either cap is exceeded or the PDF is copy-protected. — [Gemini Notebook FAQ](https://support.google.com/notebooklm/answer/16269187?hl=en)
- Free accounts: up to 50 sources per notebook, stated on the add-sources help page. — [Add or discover sources (iPhone & iPad)](https://support.google.com/notebooklm/answer/16215270)
- Upgrade help, captured as a search snippet after a full fetch timed out on 2026-10-02: starting 2026-09-02, usage limits change. The visible table has five unlabeled columns. Notebooks per user: 100, 200, 500, 500, 500. Sources per notebook: 50, 100, 300, 500, 600. Chats per day: 50, 200, 500, 2,500, 5,000. Plan names for those columns were not in the captured header. A third-party 2026 blog that maps those caps onto Plus/Pro/Ultra names disagrees with the middle columns (it reports Plus and Pro both at 300). Prefer the official table and do not treat the blog’s plan names as verified. — [Upgrade Gemini Notebook](https://support.google.com/notebooklm/answer/16206866?hl=en); contradicted on plan naming by [PostToSource](https://www.posttosource.com/blog/notebooklm-source-limit)
- Click-to-passage is not in the official FAQ text that was fetched. A university help article (2025-08-27) says numbered inline citations jump to the passage. An unofficial documentation gist says citations are direct quotes, hover shows the quote, and click scrolls the source viewer. Treat click-through as reported, not as a sentence on the current Google FAQ. — [FSU Service Center](https://servicecenter.fsu.edu/s/article/How-do-NotebookLM-s-inline-citations-work-and-why-are-they-important); [unofficial gist](https://gist.github.com/PauloMoekotte/f603ec3f6dbe946b7d44d302aa013f45)
- Open WebUI splits Notes from Knowledge. Notes inject their full content into every message. Knowledge uses retrieval so large sets do not have to fit in the window. — [Knowledge](https://github.com/open-webui/docs/blob/main/docs/features/workspace/knowledge.mdx) (published at the Open WebUI docs site from this file)
- Per attachment, Open WebUI has two modes. Focused Retrieval (default) injects the top RAG chunks. Full Context injects the whole file with no chunking and no semantic search, including when native function calling is on. The chat docs call the same control “Using Entire Document.” A default upload mode can be set and still overridden per file. — [Knowledge](https://github.com/open-webui/docs/blob/main/docs/features/workspace/knowledge.mdx); [RAG](https://docs.openwebui.com/features/chat-conversations/rag/)
- With native function calling, knowledge attached to a model or folder is not auto-injected. The model must call tools. `query_knowledge_files` is semantic retrieval, plus BM25 and rerank when `ENABLE_RAG_HYBRID_SEARCH` is on, and returns top K (default 5). `grep_knowledge_files` is exact or auto-detected regex and returns matching lines with 1-based line numbers, capped at 50 (`KNOWLEDGE_GREP_MAX_MATCHES`). `view_file` reads by character page (default 10,000, hard cap 100,000) or by line range. The docs recommend semantic search for “what does this say,” grep for identifiers, then a line-range read. — [Knowledge](https://github.com/open-webui/docs/blob/main/docs/features/workspace/knowledge.mdx)
- `kb_exec` is an optional shell-style layer (`ls`, `grep`, `cat`, `sed` line ranges, one pipeline) over knowledge files. It is off by default, experimental, and only works with native function calling. Output is capped at 30,000 characters per call. A grep spanning more than 200 files is refused. Semantic `query_knowledge_files` stays available beside it. — [Knowledge](https://github.com/open-webui/docs/blob/main/docs/features/workspace/knowledge.mdx)
- Open WebUI’s hybrid switch is BM25 plus a CrossEncoder reranker and a relevance-score threshold. The docs do not publish a quality number for that stack. The RAG page says the feature “allows users to easily track the context of documents fed to LLMs with added citations,” and does not describe hover text, quote offsets, or a source viewer. — [RAG](https://docs.openwebui.com/features/chat-conversations/rag/)
- Chunking in Open WebUI: optional markdown header split (H1–H6), then a character splitter (default, `RecursiveCharacterTextSplitter`), a tiktoken splitter, or a Hugging Face tokenizer splitter. A “Chunk Min Size Target” forward-merges undersized header chunks until a minimum is met or the max chunk size would be exceeded. Merges stay inside one source file. The docs claim a threshold of 1000 with chunk size 2000 can cut chunk count by over 90% and improve accuracy. No dataset, metric, or date is attached to that test. Re-index re-chunks stored extracted text; it does not re-parse the original file. — [RAG](https://docs.openwebui.com/features/chat-conversations/rag/)

### Inferences

- Full-document and search are modes of the same product, selected by size (Claude Projects), by the user per file (Open WebUI), or by source selection plus retrieval when the notebook is large (Gemini Notebook). A local app that only chunks everything, or only stuffs everything into the prompt, is off this pattern.
- Citation quality tracks how the retrieved text is addressed. Gemini Notebook’s user-facing promise is a passage you can check. Claude’s API makes the same promise only if the app returns `search_result` blocks with citations enabled and splits those blocks small enough to be useful. Claude’s project-knowledge help never says the chat UI does that. Open WebUI’s citation sentence is too thin to treat as passage-level grounding.
- Agentic read tools (grep, line-range read, paginated `view_file`) sit beside vector RAG in Open WebUI, specifically for exact strings that embeddings miss. That is a product answer to the same failure Anthropic illustrated with an error code in 2024, implemented as tools rather than only as BM25 fusion.

### Gaps

- No primary page found that states Claude Projects’ chunk size, embedding model, hybrid weights, reranker, or whether project-knowledge answers show clickable passages. The “up to 10x” and “same quality” lines are help-center claims without an eval.
- Gemini Notebook’s official FAQ does not say whether “retrieves the most relevant information” means embeddings, BM25, or a long-context selection over whole sources. Click-to-scroll was not confirmed on the FAQ page that was fetched.
- The Gemini Notebook upgrade table’s plan names were not captured; a full fetch of that URL timed out.
- ChatGPT projects, Mem, and Reflect were not opened. They are not covered here.

## What chunking, hybrid search, and reranking practices have primary-source evidence in 2025-2026?

### Takeaway

2025–2026 primary measurements agree that lexical and dense retrieval should be fused, and that a weak extra retriever can hurt. They do not agree that a neural reranker helps: Cohere reranking helped Anthropic’s 2024 setup, LLM listwise reranking helped a TREC 2025 submission, and off-the-shelf cross-encoders hurt a 2026 SQLite hybrid system on BEIR. No opened 2025–2026 source names one best chunk size.

### Cited Findings

- **Older (2024-09-19).** Anthropic’s Contextual Retrieval post, averaged on Gemini Text 004, top-20 chunks, metric 1 − recall@20: contextual embeddings cut the failure rate 35% (5.7% → 3.7%); contextual embeddings plus contextual BM25 cut it 49% (5.7% → 2.9%); adding a Cohere reranker on the top 150 down to the top 20 cut it 67% (5.7% → 1.9%). The prepended context was usually 50–100 tokens, generated by Claude 3 Haiku from the whole document, with a stated one-time cost of $1.02 per million document tokens under their prompt-cache assumptions (800-token chunks, 8k-token documents). They say embeddings plus BM25 beat embeddings alone; Voyage and Gemini were the best embedding models they tried; passing 20 chunks beat 10 or 5. Adding a generic document summary to chunks “saw very limited gains.” Hypothetical document embeddings and summary-based indexing “saw low performance.” They do not publish a winning chunk size; they say size, boundary, and overlap change results. A cookbook commit on 2025-10-24 updated the guide notebook; the published percentages above are from the 2024 post, not a new 2025 eval. — [Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval); [cookbook commit](https://github.com/anthropics/claude-cookbooks/commit/5cb47e13c2b9609ede1b53f8c6a87ad2bd8f560d)
- **2025 (arXiv 2025-08-02; also PVLDB).** “Balancing the Blend” evaluates full-text, dense, sparse, and tensor paths and all 11 hybrid combinations on 11 datasets. The authors report a “weakest link” effect: adding a path can raise accuracy, and a single weak path can pull the fusion down. No hybrid layout is best on every dataset. On DBPE(en), for full-text plus dense vector search, switching from reciprocal rank fusion (nDCG@10 0.668) to their tensor re-rank fusion (0.722) is an 8.1% relative gain. They also compare two learned rerankers, gte-multilingual-reranker-base and bge-reranker-v2-m3, as external baselines. — [arXiv HTML](https://arxiv.org/html/2508.01405v1); [PVLDB PDF](https://www.vldb.org/pvldb/vol19/p1715-gao.pdf)
- **TREC 2025 RAG track (proceedings paper).** UTokyo-HitU fused BM25, SPLADE, BGE-small, and Qwen3-Embedding-0.6B with reciprocal rank fusion, plus a HyDE vector mix, and placed first on Retrieval among 12 teams (46 runs): nDCG@30 0.693, nDCG@100 0.613, recall@100 0.257. LLM reranking with GPT-4.1-mini in a sliding window raised nDCG@5 from 0.486 to 0.778. They report that including the document URL helped the reranker, that raising the candidate pool from 100 to 200 improved P@100, and that windows of 10 documents with 3 passes beat larger windows with fewer passes. — [TREC 2025 notebook paper](https://trec.nist.gov/pubs/trec34/papers/UTokyo.rag.pdf)
- **2026 preprint (arXiv 2604.15484), SQLite hybrid, read in full text.** vstash keeps one SQLite file: sqlite-vec ANN (384-d) and FTS5 with Porter stemming, fused by RRF with k = 60 and default weights 0.6 vector / 0.4 FTS. Adaptive per-query IDF weights beat those fixed weights on all five BEIR sets they report, NDCG@10: SciFact 0.7255 → 0.7263, NFCorpus 0.3525 → 0.3590, SciDocs 0.1911 → 0.1943, FiQA 0.3789 → 0.3917, ArguAna 0.3599 → 0.4370. They attribute most of the ArguAna jump to relaxing a distance cutoff on long queries (average 194 words), not to the IDF sigmoid alone. On a 50,000-chunk synthetic scale test, median search latency is 20.9 ms (NDCG@10 0.6897 on that row of their scale table). Neighbor expansion of ±1 chunk around a ~250-token hit added 2.64× text at +0.12 ms. — [vstash PDF text](https://arxiv.org/pdf/2604.15484)
- Same paper, negative rerank result: ms-marco-MiniLM and BGE-reranker-base changed NDCG by −0.3% to −3.1% and added 560–2100 ms. The authors say those cross-encoders were trained on web search and did not transfer to their technical and scientific sets. A frequency-plus-decay rescore also lost to plain RRF on SciFact (0.7263 → 0.7150 in the best gated config, and to 0.661 with a fixed weight). Their conclusion is specific: for BGE-small on these sets, gains came from the embedding, not from post-RRF scoring. — [vstash PDF text](https://arxiv.org/pdf/2604.15484)
- **Vendor, 2025-07-24, not an independent paper.** TopK reports nDCG@10 on five BEIR sets for their in-engine hybrid versus RRF: FiQA 0.4123 → 0.42853, TREC-COVID 0.76779 → 0.82798, NQ 0.53885 → 0.55271, NFCorpus 0.34593 → 0.36803, FEVER 0.84643 → 0.86464, average +4.58%. Treat as a vendor benchmark of their own engine. — [TopK blog](https://www.topk.io/blog/20250724-beyond-rff-how-topk-improves-hybrid-search-quality)
- A 2026 financial text-and-table RAG abstract, seen only through a secondary paper page and not opened as a PDF, reports hybrid retrieval plus a cross-encoder at Recall@5 0.816 and MRR@3 0.605, and says BM25 beat a dense baseline on that corpus. Do not use those figures as verified until the paper is read. — [secondary abstract page](https://www.emergentmind.com/papers/2604.01733)

### Inferences

- The durable recipe with primary numbers behind it is: retrieve with both a lexical index and a vector index, fuse ranks rather than raw scores, and only then decide whether a reranker is worth its latency on the actual corpus. Anthropic’s 2024 stack, the 2025 VLDB paper, TREC 2025, and vstash 2026 all fuse. They diverge on the rerank step.
- Reranker evidence is conditional. A Cohere reranker on contextualized chunks helped a mixed-domain top-20 failure metric in 2024. An LLM sliding-window reranker helped a TREC web-ish RAG task in 2025. Small cross-encoders trained on MS MARCO hurt BEIR scientific sets inside a local SQLite system in 2026. Copying “add a cross-encoder” from a blog is not supported as a default.
- Chunking evidence in this window is structural, not a magic length. Header-then-merge (Open WebUI docs), a short contextual prefix (Anthropic 2024), and fetching the neighboring chunk at read time (vstash, ~250 tokens plus ±1) are three different ways to stop a chunk from being a sentence with no subject. None of the 2025–2026 sources opened here crowns a single token count.

### Gaps

- The financial hybrid-RAG paper (arXiv id 2604.01733) was not fetched; its Recall@5 figure is unverified here.
- sqlite-vec’s rescore ANN pull request was not read in full, so its recall-versus-latency table is omitted rather than quoted from a search snippet.
- No 2025–2026 primary source opened here measures contextual retrieval again with current embedding models. The 35/49/67% figures remain 2024.
- LlamaIndex’s contextual-retrieval cookbook was not used; it is an implementation note, and the page itself says results depend on queries and chunk size.

## What notes features are table stakes (wikilinks, backlinks, daily notes, proposed edits, version history)?

### Takeaway

Wikilinks, backlinks, and a daily note or journal are core in the linked-note apps that document them (Obsidian, Logseq). Version history is core in page editors (Notion, Craft) but the snapshot grain differs. “Proposed edits” in 2026 covers both human suggestions and an agent that proposes line-level changes for the user to accept. None of these five are universal across every notes product: Gemini Notebook cannot restore a deleted note.

### Cited Findings

- Obsidian internal links default to wikilinks, `[[Note name]]`, including links to notes that do not exist yet. Markdown links are an optional switch under Files and Links; typing `[[` still autocompletes, and the editor then writes a Markdown link. Folder paths in the link create the note at that path. Characters `# | ^ : %%` and brackets are called out as unsafe in link text. — [Internal links](https://obsidian.md/help/links); [Link notes](https://obsidian.md/help/link-notes)
- Obsidian backlinks are a core plugin view for the active note: linked mentions (real internal links) and unlinked mentions (the note’s name as plain text). They can live in the sidebar or at the bottom of the note. The help page’s example is the inverse of a forward link: a link from “Three laws of motion” to “Isaac Newton” is a backlink on Newton. — [Backlinks](https://obsidian.md/help/backlinks)
- Obsidian daily notes are a core plugin. The default file name is today’s date, `YYYY-MM-DD`. Options cover a folder, a date format that can create subfolders, and a template applied at creation. If a note has a date property, live preview turns that date into a link to the daily note. — [Daily notes](https://obsidian.md/help/plugins/daily-notes)
- Logseq’s database-version docs (the docs repo, not a third-party wiki) say nodes are referenced with `[[]]`. A journal page is tagged `#Journal` and is created automatically for the current day. Journals can be referenced in natural language inside brackets (`[[Today]]`, `[[This Friday]]`, `[[Last Friday]]`), inserted with a date picker, or created because a date-typed property points at that day. Next and previous day are `g n` and `g p`. — [Logseq db-version docs](https://github.com/logseq/docs/blob/master/db-version.md)
- A DeepWiki summary of Logseq docs says backlinks render at the bottom of a page as linked references, unlinked references, and block backlinks, and that blocks can be referenced with `((uuid))`. That page is a generated summary of the docs, not the docs repo itself, so the bottom-of-page layout is one step removed. — [DeepWiki summary](https://deepwiki.com/logseq/docs/4.3-linking-and-references)
- Notion page version history: from the page `•••` menu, open Version history, pick a dated version, and restore it. The same help guide also points at Updates & analytics for a change feed, plus Last edited by and Last edited time as database properties. — [Notion help guide](https://www.notion.com/help/guides/tips-to-keep-your-teams-notion-pages-up-to-date)
- **Older (2024-07-29).** Notion 2.43 shipped suggested edits: a collaborator proposes a change and someone else accepts or rejects it. The same release grouped those suggestions with comments in the inbox. That is human track-changes, not an agent. — [Notion 2.43 release](https://www.notion.com/releases/2024-07-29)
- **2026-08-28.** Notion’s release notes say agents can propose edits instead of applying them. The user asks the agent to “suggest edits” and approves each change from top to bottom. The note calls out line-level work such as a grammar pass. — [Notion releases](https://www.notion.com/releases)
- Craft version history: automatic snapshots while the user is editing, one per 60 minutes of continued editing, opened from the Info tab as View Backups, with retention limited by plan. A document that was not edited for a full hour may have no new snapshot. — [Craft version history](https://support.craft.do/en/write-and-edit/version-history) (search-indexed page text; not re-fetched in full)
- Craft Assistant has two edit modes, from search-indexed docs on a Mintlify host that mirrors Craft support: Explore reads the document and proposes changes for approval; Execute applies them as they happen. Max and Fast can edit. Core and On-device are read-only. Editing spends more quota because the assistant reads, plans, and applies. — [Craft Assistant editing](https://craft-support.mintlify.app/en/ai-assistant/editing)
- Gemini Notebook notes are not a linked-note system in the help text that was fetched. Deleted notes cannot be recovered. Notes enter the model prompt only when selected. — [Gemini Notebook FAQ](https://support.google.com/notebooklm/answer/16269187?hl=en)

### Inferences

- For a comparison of “notes,” wikilinks plus backlinks plus a daily page are table stakes inside the linked-note category, because both Obsidian and Logseq ship them as product structure rather than as an integration. They are not table stakes for every writing surface: the Gemini Notebook FAQ describes notes as selectable prompt context with no undelete.
- Version history is table stakes for a page you might ruin, and the bar in 2026 is restore-to-a-previous-copy, not a git log. Notion exposes dated versions the user can restore. Craft’s copy is coarser (about hourly, and only while editing continues) and expires with the plan. A notes feature that autosaves with no restore path is behind both.
- Proposed edits split in two and both now exist in mainstream apps. Human suggestions have been in Notion since July 2024. Agent suggestions that wait for per-change approval shipped in Notion on 2026-08-28 and exist in Craft as Explore versus Execute. The 2026 version is a review queue of model diffs, not a comment thread.

### Gaps

- Obsidian’s File recovery plugin (local snapshots) was not fetched, so this note does not claim how Obsidian versions files.
- Capacities, Tana, Reflect, Anytype, and Apple Notes were not opened. “Table stakes” here means the apps whose docs were read, not a survey of every notes app.
- Logseq’s linked-versus-unlinked backlink layout rests on a generated wiki summary. The official db-version page confirms `[[]]` and journals, not the backlink panel layout.
- Craft Assistant’s Explore/Execute split was taken from search-indexed docs on `craft-support.mintlify.app`, not from a successful full fetch of `support.craft.do`.

## Which mechanisms fit a local SQLite plus FTS5 app?

### Takeaway

FTS5 BM25, snippets, and column weights are in SQLite itself and match the lexical half of every hybrid system above. Vectors are not in core SQLite; the working local design is FTS5 plus the sqlite-vec extension, fuse by rank (RRF, k = 60), and keep a full-document path for small notes so retrieval is optional. A cross-encoder is a poor default on this stack: the 2026 system that measured it on SQLite saw it lose quality and add hundreds of milliseconds.

### Cited Findings

- FTS5’s `bm25()` is a built-in auxiliary function. Better matches return numerically smaller scores, because the implementation multiplies the usual BM25 by −1 so `ORDER BY bm25(ft)` sorts best-first. Constants k1 and b are hard-coded at 1.2 and 0.75. Extra arguments weight columns (title higher than body). The hidden `rank` column defaults to that same bm25 value and is faster to sort on. `snippet()` returns a short fragment biased toward the start of the column and toward text after `.` or `:`. — [SQLite FTS5](https://www.sqlite.org/fts5.html)
- **Older (2024-10-02).** Alex Garcia’s sqlite-vec write-up shows hybrid search as two virtual tables in one SQLite file: an external-content FTS5 table (`content=` / `content_rowid=`) and a `vec0` table. sqlite-vec stores and compares vectors; it does not embed. His local embedding path is a second extension, sqlite-lembed, with a GGUF model. He shows three fusions in SQL: keyword-first, reciprocal rank fusion with separate weights, and “re-rank the FTS hits by cosine distance.” The demo corpus is 14,500+ NBC headlines, 4.3MB, not a retrieval benchmark. He warns that an FTS5 query scans the whole table, that one FTS5 index does not take metadata filters, and that sqlite-vec partitioning and metadata filters were not available yet. — [Garcia, 2024-10-02](https://alexgarcia.xyz/blog/2024/sqlite-vec-hybrid-search/index.html)
- **Older (2024-10-04).** Simon Willison’s note on that post states the reason to fuse ranks: vector distance and FTS relevance are not on the same scale, so RRF never compares the raw scores. It uses `row_number()` inside each list. — [Willison](https://simonwillison.net/2024/Oct/4/hybrid-full-text-search-and-vector-search-with-sqlite/)
- **2026.** vstash is the measured version of that design: WAL-mode SQLite, `vec_chunks` (sqlite-vec, 384-d float, BGE-small via FastEmbed/ONNX, about 700 chunks/second on CPU), `fts_chunks` (FTS5, Porter), RRF with k = 60. Query text is quoted per term and OR-ed so FTS5 operators in the user string are not executed. IDF for adaptive weights is read from FTS5’s `fts5vocab` and cached until a write. Median latency 20.9 ms at 50,000 chunks. Cross-encoder reranking on this substrate lost NDCG and cost 560–2100 ms (figures in the previous section). — [vstash](https://arxiv.org/pdf/2604.15484)
- The same 2024 Anthropic guidance still bounds when this machinery is unnecessary: under about 200,000 tokens, the whole knowledge base can go in the prompt. Claude Projects and Open WebUI both implement that idea as a product switch (automatic threshold, or a per-file full-document toggle). — [Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval); [RAG for projects](https://support.claude.com/en/articles/11473015-retrieval-augmented-generation-rag-for-projects); [Open WebUI Knowledge](https://github.com/open-webui/docs/blob/main/docs/features/workspace/knowledge.mdx)
- Open WebUI itself is not a SQLite-FTS app. Its maintained vector stores are Chroma and pgvector, with other engines listed as non-core, and hybrid search is an application-level BM25 plus CrossEncoder, not FTS5. Useful as a feature checklist, not as a storage design. — [Knowledge](https://github.com/open-webui/docs/blob/main/docs/features/workspace/knowledge.mdx)
- Citation display can be done without a vector index. FTS5 `snippet()` is the lexical highlight. Claude’s API cites whatever text blocks the app returns, so a local app can cite an FTS hit or a neighbor-expanded chunk if it passes that text back as a `search_result` with citations enabled. Gemini Notebook’s short-source rule (cite the whole document when there is no passage to point at) is the matching UI fallback. — [SQLite FTS5](https://www.sqlite.org/fts5.html); [Search results](https://platform.claude.com/docs/en/build-with-claude/search-results); [Gemini Notebook FAQ](https://support.google.com/notebooklm/answer/16269187?hl=en)
- Notes structure that fits the same database: Obsidian-style `[[wikilinks]]` are a string convention parsed into a links table, and backlinks are the inverse query. A daily note is a row keyed by date. Notion-style version history is prior copies of the page body. None of that requires a vector extension. Agent “suggest edits” is an overlay of proposed ranges, accepted or rejected, which Notion shipped as a review pass on 2026-08-28. — [Internal links](https://obsidian.md/help/links); [Backlinks](https://obsidian.md/help/backlinks); [Daily notes](https://obsidian.md/help/plugins/daily-notes); [Notion releases, 2026-08-28](https://www.notion.com/releases)

### Inferences

- A local SQLite app can ship the lexical path with zero extensions: external-content FTS5, `bm25()` with a higher weight on title than body, `snippet()` for the citation highlight, and `ORDER BY rank`. That covers exact identifiers, which is the case where vector-only search fails in both the 2024 Anthropic error-code example and Open WebUI’s grep-versus-semantic split.
- Hybrid search fits the same file only with a loadable extension. sqlite-vec is the one with a public SQL recipe (2024) and a 2026 BEIR measurement (vstash). Embeddings are computed outside SQL, or by yet another extension. Fusion should use ranks and a constant near 60, with FTS able to win on rare terms (vstash’s IDF adjustment, or simply not dropping a keyword hit because its cosine is low).
- Full-document injection fits without any index: if a note or a small project is under the context budget, put the body in the prompt and do not retrieve. Open WebUI’s Notes-versus-Knowledge split is the cleanest statement of that. Retrieval, neighbor expansion, and citations matter once the user has many documents.
- Skip a cross-encoder as a default on this hardware. The only 2026 measurement that ran one on SQLite FTS5 plus sqlite-vec found it slower and slightly worse. If a rerank step is added later, the positive evidence is a stronger reranker on a corpus that resembles the user’s notes (Cohere in Anthropic’s 2024 mix; an LLM window in TREC 2025), not MS MARCO MiniLM.
- Metadata filters are the sharp edge. Garcia’s 2024 caveat still matters: one FTS5 index is not a filtered index. A project or notebook scope has to be applied in SQL around the FTS query (prefilter rowids, or an FTS table per scope). That constraint is independent of the vector extension.
- Wikilinks, backlinks, daily notes, and version history are ordinary tables beside FTS5. They do not wait on hybrid search. Proposed edits are a second body (or a list of ranges) plus an accept/reject state, which matches Notion’s 2026 agent review and Craft’s Explore mode.

### Gaps

- No opened source measures FTS5 plus sqlite-vec on a personal-notes corpus (short daily notes, wikilink titles, meeting notes). vstash’s BEIR numbers are scientific and financial QA sets, plus a synthetic 50k-chunk latency test. Garcia’s headline demo is not a quality score.
- Whether sqlite-vec’s metadata filters or the rescore ANN index have shipped since the October 2024 post was not verified.
- A microbenchmark repo (about 40 passages, SQLite versus LanceDB versus DuckDB) turned up in search and was not used. The set is too small to cite as retrieval quality.
- Core SQLite still has no vector type. “SQLite plus FTS5” does not include hybrid search until an extension is allowed. That deployment constraint was not checked against any app store or sandbox policy.
