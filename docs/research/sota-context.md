## Context engineering, compaction, working memory, tracing and usage/cost

### Where we are

**Context assembly** (`backend/personal_os/context.py`). `build_context()` returns `(system_prompt, context_used)`. It concatenates, in this order: global system prompt, project name and prompt, page block (`page_block`, detail capped at 6000 chars, selection at 2000), memories (`Memories.for_context(project_id, query)`), graph neighbourhood, document-chunk hits, approved skills, style profile, activity digest and meetings digest. Every section is query-dependent or per-turn dependent and has no token budget of its own. `estimate_tokens` is `len//4`. `context_used` is persisted on the assistant message and shown in `ContextDrawer.tsx` (per-source toggles, "view full system prompt", `~N tokens`).

**History** (`repos.py: Conversations.history`, called at `app.py:1028`). It returns every non-empty user/assistant message of the conversation as `{role, content}`, with no limit, no summary and no windowing. Tool calls and results from earlier turns are not replayed, which keeps old turns cheap. Reasoning is never replayed. There is no compaction anywhere: `grep -i compact` over `personal_os/*.py` finds only unrelated "compact digest" docstrings. A long chat grows until the provider rejects it, and there is no model context-window setting or pre-flight check. Within a single run, `messages` (app.py ~1118) grows by every assistant tool-call message and tool result for up to `maxToolRounds` (25) rounds. The only guards are `Budget` caps (`maxRunTokens` 200k, `maxRunSeconds`, `maxRunCost`) with a 60% soft nudge (`SOFT_NUDGE`), and a tool-free `_final_round`. These stop the run rather than shrink it.

**Prefix-cache hostility.** The final system prompt is `system + RENDER_HINT + tools_hint (+ JOB_HINT)` (app.py ~1113). The stable hints come after the volatile retrieval blocks. Memories, graph, chunks and page change on every turn because they are keyed on the user query. The first token that differs is therefore early in the system message, so every turn invalidates the whole cached prefix, including all of history. Nothing in `llm.stream_chat` sends `cache_control` or reads cached-token counts.

**Working memory** (`working.py`). `Plans` (`chat_plans`, one JSON steps row per conversation) is written by `todo_write` and re-injected as the last system message every round (`_reinject_plan`, one slot moved, never accumulated). `ToolResults` (`tool_results` table) stores any result whose JSON exceeds `INLINE_CHARS=4000` as a handle with a 2000-char preview, a `shape_of()` summary and `result_id`. `read_tool_result(result_id, offset, limit)` pages it (max 20k chars) and is scoped to the conversation. This is a good foundation, but the handle is created only at call time. A big or small result already in `messages` is never cleared later, so 25 rounds of 4000-char inline results (~25k tokens) plus previews stay forever. Plans and results have no relationship to history size.

**Tracing** (`trace.py`). A `Tracer` holds a flat list of spans `{id, kind, name, start, end, meta, error}` for kinds context, llm, tool and learn. Spans stream over SSE and are persisted on the message (`finish_message(..., tracer.spans)`). `summary()` sums `usage.prompt_tokens` and `completion_tokens`. `TraceView.tsx` renders the list (106 lines). Gaps: spans are flat with no parent ids, so tool calls are not nested under the llm round that issued them. There is no span for compaction. `meta.usage` holds only prompt, completion and total. Nothing is exportable to OTLP, Phoenix or Langfuse, and a trace can't be replayed.

**Usage and cost** (`usage.py`, `llm._emit_usage`, `db.py:105`). A `usage_log` row per model call holds `model, kind, conversation_id, project_id, prompt_tokens, completion_tokens, duration_ms, cost, estimated`. Cost is `(pt*input + ct*output)/1e6` from the proxy's `/model/info` (`input_cost_per_token`, `output_cost_per_token`, cached 600 s) with `settings.modelPrices` overrides. Weak spots: no cached-input or reasoning-token columns, so a reasoning model's cost and a cache hit's discount are both invisible and misestimated. `Pricing` ignores `cache_read_input_token_cost`. A missing `usage` falls back to `chars//4` and is flagged `estimated`. `kind` is only chat/learn/other, with no per-round or per-tool attribution. `UsageView.tsx` shows daily, hourly, model, kind and project buckets but no cache-hit rate. `docs/research.md` lists G36 (microcompaction) and G37 (full compaction); neither has shipped. G33 (handles) and G38 (plan) have.

### What the best open-source systems do

**OpenHands condensers** ([context-condenser guide](https://docs.openhands.dev/sdk/guides/context-condenser), [blog](https://openhands.dev/blog/openhands-context-condensensation-for-more-efficient-ai-agents)). Condensation is a pluggable `Condenser` over the event history. `LLMSummarizingCondenser` is a `RollingCondenser`. It triggers when the event count exceeds `max_size`, always keeps the first `keep_first` events (system prompt and the initial user task), keeps the recent tail verbatim, and replaces the middle with an LLM summary event. The summary is structured to encode the user's goals, progress so far and what remains, and for coding it keeps critical files and failing tests. Other condensers include observation masking, recent-events-only and amortized forgetting. Reported on SWE-bench Verified: per-turn cost roughly halved once it triggers, with a 54% vs 53% solve rate. Condensing in batches (not every turn) keeps the prefix stable so prompt caching still works between condensations.

**Anthropic context editing and the memory tool** ([context editing docs](https://platform.claude.com/docs/en/build-with-claude/context-editing), [announcement](https://claude.com/blog/context-management)). `clear_tool_uses_20250919` is server-side and applies before the model sees the prompt, while the client keeps the full history. Parameters: `trigger` (default 100k input tokens, or a count of tool uses), `keep` (default last 3 tool uses), `clear_at_least` (so a clear is worth the cache break it causes), `exclude_tools`, `clear_tool_inputs`. Responses report `applied_edits` with `cleared_tool_uses` and `cleared_input_tokens`. `clear_thinking` has its own `keep`. Anthropic reports 84% fewer tokens on a 100-turn search eval from tool clearing alone, and +29% (clearing) and +39% (clearing plus memory tool) on agentic search. The memory tool lets the model write findings to files before they are cleared.

**Codex CLI and Claude Code compaction.** Both follow the same shape: when the transcript nears the window, they run a dedicated summarization turn using a "handoff summary for another LLM" prompt (task, decisions, files, open issues, next steps). Then they rebuild the context as system prompt, the user's recent messages (Codex caps these to a token budget and keeps them verbatim) and the summary. Claude Code also does cheap tool-result clearing first and exposes manual `/compact [focus]`. I could not fetch Codex's prompt template source (404), so the preserve-list details are from general knowledge, not a verified read. Treat the numbers as unverified.

**Cline** ([auto-compact docs](https://docs.cline.bot/features/auto-compact)). Auto-compact replaces older history with a comprehensive summary that preserves technical details, code changes and decisions, instead of the older behaviour of truncating messages. Checkpoints let the user restore pre-summary state.

**Prompt caching practice** ([Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). The prefix is ordered tools, then system, then messages, and any change invalidates that level and everything after it. Place breakpoints on the last identical block, never on content that changes each request. Reads cost 0.1x base input and 5-minute writes 1.25x. Usage reports `cache_read_input_tokens` and `cache_creation_input_tokens`. OpenAI-style providers (including Fireworks) cache prefixes automatically and report `prompt_tokens_details.cached_tokens`. The corollary for agent design is volatile context at the end, stable prefix first, and compaction in rare batches.

**LiteLLM cost tracking** ([prompt caching](https://docs.litellm.ai/docs/completion/prompt_caching), [cost tracking](https://docs.litellm.ai/docs/proxy/cost_tracking)). `prompt_tokens` includes cache-hit tokens, with `cached_tokens` and `cache_creation_input_tokens` as sub-counts. `completion_cost()` prices cache hits and misses separately, using `cache_read_input_token_cost` in the model map. The proxy returns `x-litellm-response-cost` per response, writes `LiteLLM_SpendLogs` (`/spend/logs/v2`), and supports `metadata.tags` for per-project or per-job attribution.

**Langfuse** ([token and cost tracking](https://langfuse.com/docs/observability/features/token-and-cost-tracking)). `usage_details` and `cost_details` are dicts of mutually exclusive buckets: `input`, `output`, `input_cached_tokens`, `output_reasoning_tokens`. `input` excludes the `input_*` buckets, so each token is counted once. Models are matched by regex with user definitions overriding defaults. Token counts are inferred with tiktoken only when the provider reports none.

**Arize Phoenix and OpenInference** ([span kinds and token attributes](https://github.com/Arize-ai/openinference/blob/main/spec/semantic_conventions.md)). Spans carry `openinference.span.kind` of LLM, TOOL, AGENT, CHAIN, RETRIEVER and so on, with real parent/child nesting. Token attributes are `llm.token_count.prompt`, `.completion`, `.total`, `.prompt_details.cache_read`, `.prompt_details.cache_write` and `.completion_details.reasoning`. Phoenix groups traces into sessions (conversations) and projects, adds annotations, and can replay a captured LLM call in a playground.

**OpenLLMetry and OTel GenAI semconv** ([semantic-conventions-genai repo](https://github.com/open-telemetry/semantic-conventions-genai); the old opentelemetry.io page now redirects there). GenAI spans use `gen_ai.operation.name` (chat, execute_tool, invoke_agent), `gen_ai.request.model`, `gen_ai.usage.input_tokens` and `gen_ai.usage.output_tokens`, with cache-token attributes. Prompt and completion content is opt-in because it is sensitive. Because it is standard OTLP, one exporter feeds Phoenix, Langfuse, Jaeger or anything else.

**Helicone** ([caching](https://docs.helicone.ai/features/advanced-usage/caching)). A gateway-side response cache keyed on a hash of the URL, body and selected headers (with a seed namespace, TTL and bucket of N responses), with HIT/MISS headers. It is aimed at deterministic repeat calls and has little value in an agent loop, so we skip it.

### Gaps

| # | gap | who does it | impact | effort |
|---|---|---|---|---|
| 1 | No history compaction: whole transcript replayed forever, no window awareness | OpenHands condenser, Codex, Claude Code, Cline | High: long chats fail or burn money; the single biggest hole | M |
| 2 | No microcompaction: old tool results (inline and handle previews) live in `messages` for the whole run | Anthropic `clear_tool_uses` (84% fewer tokens), Claude Code | High: 25-round runs bloat | S/M |
| 3 | Volatile retrieval blocks sit before the stable hints inside the system prompt, so every turn invalidates the prefix cache | Anthropic caching guidance, OpenHands batch condensing | High: cost and latency on every turn | S |
| 4 | No cached or reasoning token accounting, and no cache-read pricing, so cost is overstated or wrong | LiteLLM, Langfuse, OpenInference | Medium/High: cost numbers can't be trusted, and nobody can see whether (3) worked | S |

| 6 | Context sections have no token budget or priority trimming (docs, graph and memories can each be large) | Letta core-memory char limits, Cline | Medium | S |
| 7 | No manual `/compact [focus]` and no context meter against the window in the UI | Claude Code | Medium (UX, pairs with 1) | S |
| 8 | No per-request attribution (round, tool, job) or tag in usage rows, no budget alerts | LiteLLM tags and spend logs | Low/Medium | S |
| 9 | No replayable run records / trace-to-eval | Phoenix playground, Langfuse datasets | Medium | L |
| 10 | Model write-to-memory-before-clear hook | Anthropic memory tool | Low (auto-learn partially covers it) | M |

### Build next

**ctx-1, history compaction and microcompaction** (gaps 1, 2, 7). A new `compaction.py` adds a `conv_summaries` table holding one rolling summary per conversation. Before each reply it applies the OpenHands/Codex shape: when estimated history tokens exceed `compactAt * contextWindow`, it summarizes the older messages with the extraction model and keeps the first user message plus the recent tail verbatim. Inside the run it clears old tool-result content (keeping the newest `microKeep`, replacing the rest with a one-line stub that names the `result_id` so `read_tool_result` can still recover it). Both emit a `compact` trace span, and the context drawer gets a meter. It runs in batches, not every turn, so caching survives between compactions. Tests stub the summarizer.

**ctx-2, cache-friendly prompt layout plus cached and reasoning token accounting** (gaps 3, 4, 8 partially). The stable pieces (global prompt, project, hints, skills) stay in the system message and the per-turn retrieval blocks move to a separate system message inserted just before the newest user message. `llm.py` starts capturing `prompt_tokens_details.cached_tokens` and `completion_tokens_details.reasoning_tokens`. `usage_log` gains `cached_tokens` and `reasoning_tokens` through the db.py migration. `Pricing` reads `cache_read_input_token_cost` and prices cache-hit tokens at that rate (falling back to the input price). `/usage` and `UsageView` show the cache-hit rate and the reasoning share. This also makes ctx-1's savings measurable.

**ctx-3, OTel GenAI export and span nesting** (gap 5). Spans gain `parent_id` (tool spans nest under their llm round) and OpenInference-style token-detail meta. A new `otel_export.py` converts a finished trace into OTLP/HTTP JSON using GenAI semconv names, with no SDK dependency. It posts only to a user-configured endpoint (for example a local Phoenix on localhost), is off by default, and omits message content unless a second explicit flag is set. This respects the privacy rule: nothing leaves the machine unless the user points it somewhere.

#### ctx-1: History compaction and in-run microcompaction (M)

**Why.** Biggest gap: Conversations.history() replays the whole transcript forever and the in-run messages list holds every tool result for up to 25 rounds; nothing ever shrinks. OpenHands LLMSummarizingCondenser (max_size / keep_first / rolling summary, ~2x cheaper per turn at equal solve rate), Codex/Claude Code compaction, and Anthropic clear_tool_uses (trigger, keep last N, 84% token cut) all solve this. Not in code: grep for compact finds nothing; docs/research.md G36/G37 are unshipped.

**Files.** `backend/personal_os/compaction.py (new)`, `backend/personal_os/db.py`, `backend/personal_os/llm.py`, `backend/personal_os/app.py (two small hook points)`, `src/renderer/src/components/ContextDrawer.tsx`, `src/shared/types.ts`, `backend/tests/test_compaction.py (new)`

**Design.** SETTINGS (add to llm.DEFAULT_SETTINGS or PUT /settings drops them): contextWindow=128000 (tokens), compactAt=0.7 (fraction), compactKeepRecent=8 (messages kept verbatim), microKeep=3 (tool results kept), microAt=0.5 (fraction of window that triggers clearing in-run), autoCompact=True.

SCHEMA (new table in compaction.py, CREATE TABLE IF NOT EXISTS via db.tx executescript like working.py): conv_summaries(conversation_id TEXT PRIMARY KEY REFERENCES conversations(id) ON DELETE CASCADE, upto_message_id TEXT NOT NULL, upto_created REAL NOT NULL, summary TEXT NOT NULL, summarized_messages INTEGER NOT NULL, tokens_before INTEGER NOT NULL, tokens_after INTEGER NOT NULL, created_at REAL NOT NULL, updated_at REAL NOT NULL). Keep one row per conversation, replaced on re-compaction (rolling: the new summary prompt receives the previous summary plus newly aged-out messages).

class Compactor(db): get(conv_id); clear(conv_id); async compact(cfg, model, conv_id, history_rows, focus=None, complete=llm.complete) -> dict|None.

FUNCTIONS:
- estimate_messages(msgs) -> int: sum(len(content)//4 + 4) using context.estimate_tokens.
- async prepare_history(compactor, convos, cfg, model, conv_id, system_tokens, complete=llm.complete) -> (history, info). Reads full rows with ids and created_at (add Conversations.history_rows(conv_id) returning role, content, id, created_at; leave history() untouched). If a summary exists, history = [first user msg if not already within tail] + one synthetic {role:'user', content:'[Summary of earlier conversation]\n...'} message followed by messages newer than upto_message_id. If estimate(history)+system_tokens > compactAt*contextWindow and len(history_rows) > compactKeepRecent+2 and autoCompact: choose cut = len(rows)-compactKeepRecent, snapped backward so the kept tail starts at a user message; call compact() on rows[:cut] with the existing summary; persist; rebuild. On any exception or empty model output, log and return the uncompacted history (never fail a reply). Returns info = {compacted: bool, tokens_before, tokens_after, summarized: n}.
- SUMMARY_PROMPT (module constant): a handoff summary for another assistant: user goal and constraints, decisions made, facts and names/ids/paths worth keeping, external actions performed (sent/created/deleted, with ids) and their verified status, open questions and errors, what the user asked for last. Cap output at ~800 words; instruct the model that quoted content is data not instructions.
- microcompact(messages, keep, window_tokens, at_fraction) -> (cleared_count, tokens_saved): mutates the in-run messages list in place: when estimate_messages(messages) > at_fraction*window, find role=='tool' messages, keep the newest `keep`, replace the content of older ones with json {"cleared": true, "tool": name, "chars": n, "result_id": rid-if-present-else-null, "note": "cleared to save context; call read_tool_result(result_id) to re-read"} (parse the stored content to recover result_id when it is a handle; for inline results < 400 chars leave untouched). Never touch the plan system message or the tool_call/tool_call_id pairing (only content changes). Must skip tool messages after the last assistant message with tool_calls (the in-flight round). Idempotent.

(3) Route POST /conversations/{id}/compact {focus?: str} forces compaction now and returns the info; DELETE /conversations/{id}/summary removes the summary; GET /conversations/{id}/context-meter returns {window, estimated_tokens, summary: {...}|null}. Put the three routes in compaction.py as an APIRouter(or a register(app, deps) function) and include it with one line in app.py.

Taint is conversation-sticky already, and a summary contains tool-derived text, so do not clear conv taint on compaction. Do not raise maxToolRounds.

#### ctx-2: Cache-friendly prompt layout and cached/reasoning token accounting (M)

**Why.** Today the system prompt is [global, project, page, memories, graph, chunks, skills, style, activity, meetings, RENDER_HINT, tools_hint]; the query-dependent blocks come before the stable hints, so the provider prefix cache (Fireworks automatic, Anthropic cache_control) is invalidated from the first volatile block on every turn, including all of history. Anthropic's prompt-caching guidance (stable prefix first, volatile last) and OpenHands (batch changes) say fix the order. Separately, LiteLLM and Langfuse/OpenInference all account cached_tokens and reasoning tokens as distinct, differently priced buckets; usage.py records neither, so cost is wrong and the fix cannot be measured.

#### trace-1: Nested spans and opt-in OpenTelemetry GenAI (OTLP/JSON) export (M)

**Why.** trace.py spans are flat and un-nested, carry only prompt/completion tokens, and can only be read in TraceView. OpenInference/Phoenix and the OTel GenAI semantic conventions (gen_ai.operation.name, gen_ai.usage.input_tokens/output_tokens, cache and reasoning token attributes, tool spans nested under the chat span) are the standard so Phoenix, Langfuse, Jaeger and Grafana can all consume one export. A pure-Python OTLP/HTTP JSON emitter needs no new dependency, and keeping it opt-in and endpoint-configured respects the privacy rule.

**Files.** `backend/personal_os/trace.py`, `backend/personal_os/otel_export.py (new)`, `backend/personal_os/llm.py (DEFAULT_SETTINGS only)`, `backend/personal_os/app.py (parent_id plumbing at llm and tool span starts; one call after finish_message; one route)`, `src/renderer/src/components/TraceView.tsx`, `src/renderer/src/components/SettingsModal (Advanced/Developer section, small toggle block)`, `backend/tests/test_otel_export.py (new)`

**Design.** SPAN SHAPE. Tracer.start gains optional parent: Tracer.start(kind, name, meta=None, parent=None) stores span['parent_id'] = parent['id'] if given. Backward compatible: old persisted spans without parent_id render flat. In app.py, tool spans are started with parent = the llm round span that issued the calls (keep a local `round_span` variable), compaction/micro spans parent to the context span. Tracer.summary adds cached_tokens and reasoning_tokens sums from meta.usage (keys from ctx-2; treat absent as 0, so this spec does not depend on ctx-2 landing first). TraceView.tsx indents child spans under their parent (parent_id lookup, one nesting level is enough) and shows cached/reasoning counts in the llm row when present.

SETTINGS (add to llm.DEFAULT_SETTINGS): otelExport = {"enabled": False, "endpoint": "", "headers": {}, "includeContent": False, "timeoutSeconds": 5}. Patched via PUT /settings (flat dict replace is fine; document it). No content is ever exported unless includeContent is true; with it false, only names, timings, token counts, model, finish_reason, tool names, error strings and hashed ids are sent.

MODULE otel_export.py (stdlib + httpx, already a dep):
- to_otlp(trace_spans, *, conversation_id, message_id, model, project_name=None, include_content=False, content=None) -> dict: builds an OTLP/JSON ExportTraceServiceRequest: resource attributes service.name='grain', service.version, and session id as `session.id`=conversation_id (Phoenix/OpenInference convention) and `gen_ai.conversation.id`; one root span 'grain.reply' (INTERNAL, spans the min start to max end of all spans) then one OTel span per Grain span, with trace_id (32 hex) derived deterministically from message_id via sha256[:32] and span_id (16 hex) from sha256(span id)[:16], parentSpanId from parent_id (else the root), start/endTimeUnixNano from ms*1e6, status ERROR with message when span['error'].
- Attribute mapping: llm spans: gen_ai.operation.name='chat', gen_ai.request.model, gen_ai.usage.input_tokens, gen_ai.usage.output_tokens, gen_ai.response.finish_reasons=[...], plus OpenInference mirrors openinference.span.kind='LLM', llm.token_count.prompt/completion/total, llm.token_count.prompt_details.cache_read, llm.token_count.completion_details.reasoning. Tool spans: gen_ai.operation.name='execute_tool', gen_ai.tool.name, openinference.span.kind='TOOL'. Context spans: openinference.span.kind='RETRIEVER' with counts of memories/entities/excerpts. Learn: 'CHAIN'. Compact spans: 'CHAIN' with cleared/summarized counts. Unknown kinds: 'CHAIN'.
- When include_content: add gen_ai.tool.call.arguments (the already-truncated tool args) and the final reply text as gen_ai.output.messages on the root; never the system prompt or memories (those can carry activity/meeting content), and never when the conversation is tainted... (tainted is irrelevant to privacy; instead skip content whenever used['activity'] or used['meetings'] was present for that reply, regardless of the flag).
- async export(settings, payload, post=None) -> dict: if not enabled or no endpoint returns {'sent': False, 'reason': 'disabled'}; POSTs JSON to endpoint (if it does not end with /v1/traces append it) with headers; never raises, returns {'sent': bool, 'status': int|None, 'error': str|None}. Respects timeoutSeconds. `post` is injectable for tests.
- Refuse non-loopback endpoints unless the setting `allowRemote` is true inside otelExport (so the default cannot leak off-machine by pasting a remote URL by accident); the Settings UI labels it 'Send traces off this machine'.

APP HOOKS. After convos.finish_message in _chat_stream (and the cowork desk path if it shares the function), `asyncio.create_task(otel_export.export_message(...))` fire-and-forget through a one-line call guarded by settings enabled, so it never delays `done`. Route POST /traces/export-test sends a one-span test payload and returns the export() result so the user can verify the endpoint; GET /messages/{id}/otlp returns the to_otlp payload (content omitted) so the trace can be downloaded as a file from TraceView ('Export OTLP JSON' button), which works with no endpoint at all.

**Tests.** backend/tests/test_otel_export.py, plain script. (1) Tracer parent_id: start a root llm span and two tool spans with parent=llm; assert parent_id set and summary() unchanged for old-style spans without parent_id. (2) to_otlp on a hand-built span list: trace_id is 32 hex and stable across calls, span ids 16 hex and unique, tool spans' parentSpanId equals the llm span's spanId, llm span has gen_ai.usage.input_tokens == usage.prompt_tokens, execute_tool spans carry gen_ai.tool.name, an errored span has status code 2 and the message, start<=end and timestamps are ns. (3) Privacy: with include_content False, serialise the payload to a string and assert none of a planted secret string (placed in tool args, reply text, memory text) appears; with include_content True and used['meetings'] set, content is still omitted. (4) export(): disabled -> sent False and `post` never called; enabled with a loopback endpoint calls the stub post once with '/v1/traces' appended and the configured headers; remote endpoint without allowRemote -> sent False reason 'remote-blocked'; a post stub that raises returns error, does not raise. (5) route tests via TestClient: GET /messages/{id}/otlp returns resourceSpans, and POST /traces/export-test with the stubbed post returns sent True. No network, no model calls.

**Done when.** Tool spans render nested under the model round that issued them in TraceView; GET /messages/{id}/otlp downloads a valid OTLP/JSON payload that imports into a local Phoenix or any OTLP collector; with otelExport enabled and a loopback endpoint every finished reply is exported in the background with no content by default; a remote endpoint is refused unless explicitly allowed; failures never affect a reply; python backend/tests/test_otel_export.py passes offline and existing trace-related tests still pass.
