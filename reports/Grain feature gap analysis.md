# Close the holes Grain already ships

As of 2 October 2026, Grain already runs a local personal system on Electron, FastAPI, and one SQLite file: a chat whose run keeps going after the window closes, a tool loop with round, token, time, and dollar caps plus a write journal, deny-before-allow rules, hybrid memory and document retrieval, a Today screen tied to Gmail, Calendar, and Tasks, opt-in meeting and activity capture, desks and scheduled jobs that record outward work as proposals, and HTML artifacts beside live chart widgets. The shortfall against leading personal apps is concentrated in controls that are already present and too wide, too blind, or too hard to check. Skip-permissions lifts forced asks, including a tainted external call. The next turn and a resumed run see assistant prose, while tool payloads stay in the dead process. The memory toggle and the writing-style toggle do not gate the writes and the voice block the screens describe. Two document tools search every project. Today leaves waiting-mail counts and the day plan off the page that already has the data. A clean meeting enhancement can fill the enhanced note on its own. A job slot marked fired dies with the process, and chat cannot place the live widget the dashboards screen already renders. Close those on this codebase, with offline fixtures, in the order at the end. Leave the tool-round cap at 25, leave skill approval as a human status change, leave external mail and calendar writes behind an ask, and leave a heartbeat, pixel control, screenshot capture, auto-send, and a blanket bypass unbuilt. The inventories below are the working tree read on 2026-10-02, including uncommitted skip-permissions wiring. They were not executed as a running app, and they do not split committed code from dirty code.

## A chat turn survives the window and forgets the tools

A chat turn is a background run. The composer posts `POST /conversations/{id}/chat`, and every window tails that run’s stored event tape. Closing the window detaches the viewer. Steer persists the user message, cancels the provider read, and can finish the current assistant row and open another. Stop sets the run’s stop event. Regenerate deletes the trailing assistant row and replies to the last user message. The model follows the conversation, the draft, or `settings.defaultModel`. Effort is per conversation. Fast mode sends `service_tier: "priority"` only for provider ids `openai`, `litellm`, or `custom`. Before the first byte, retryable failures retry (`llmRetries`, default 3, cap 10). Projects put name, description, and `system_prompt` in the stable prefix, with approved skills and the style profile. Page, memories, graph, document excerpts, activity, and meetings are volatile and, with `cacheLayout` on, sit in a second system message immediately before the newest user message. The loop is one streamed completion per round. The parent runs that round’s calls one after another. A child can gather consecutive read-only calls, at most 8, and run identical `(tool, args)` once. Default caps are **25 rounds, 200,000 tokens, 300 seconds, and $0.50**, with `0` meaning unlimited. Approval wait is subtracted from the wall clock. At 60% of the tightest axis, one nudge is appended. Crossing 100% answers pending calls with a budget stop and runs one tool-free closing call. The same tool and args five times in a row stops the loop, and `StuckDetector` (default on) adds four further patterns. Side-effecting tools go through `RunStore.call_once`: a finished write is replayed, a write left `started` is refused, and an error may run again. Resume is user-initiated, only for an interrupted latest non-desk chat, and it inherits that journal. Compaction leaves the messages table alone. Older turns become one `conv_summaries` row when the estimate crosses **0.7 × 128,000**. Usage rows store cached, cache-write, and reasoning tokens. Traces have parent ids. OTLP export exists and defaults off.

The holes are inside that loop. `history` and `history_rows` select content, so the next turn sees assistant prose or a summary, and tool messages from the run live only in the in-memory list. Resume appends a note and does not restore that list. Claude Code accumulates tool inputs and outputs for the session and restores them on resume, while leaving background shell work unrestored ([agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop); [Manage sessions](https://code.claude.com/docs/en/sessions)). The parent loop awaits each call, including reads. Claude Code runs read-only tools concurrently in one model message and runs `Edit`, `Write`, and `Bash` one at a time ([agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)). Grain’s in-run dollar cap calls `Pricing.cost` without the cached and cache-write counts that the usage row already records, so a cached run can trip `partial: cost` at the full input price against a **$0.50** default. The context meter returns window, estimate, threshold, and summary. LibreChat’s gauge resets the numerator after a summary and still counts pre-summary spend, with retained tool results as their own slice ([token usage](https://www.librechat.ai/docs/configuration/token_usage)). `_today_hint()` sits in the stable prefix, so the cacheable prefix changes every calendar day. `stream_chat` sends no `cache_control` field. Order is the lever that is implemented. There is no fork: regenerate deletes the last assistant row. LibreChat’s fork copies a path and leaves the original unchanged ([fork](https://www.librechat.ai/docs/features/fork)). Every send while a reply is answering interrupts. A queue-until-done path is absent. Side-by-side models, a pinned completion criterion, and per-message exclude are later. A client that applies only the `done` payload can miss the style span, which is written after `done`.

Resume, compaction, microcompact, stuck detection beyond the five-identical-call stop, cache columns, parented traces, the write journal, the 60% nudge, the tool-free final round, and read-only parallelism inside the child loop are already in the working tree. The round cap stays at 25. A second column, a sandbox that runs tools from inside a code interpreter, and a cloud continuation of a turn that used this machine’s files stay out. The runner stays on this machine.

## Skip-permissions lifts the cards the rules just forced

Built-in tools resolve `on`, `ask`, or `off` as chat override, then project override, then the global map, then a danger-tier default. `safe`, `writes`, `network`, and `executes` start at `on`. `external`, `plan`, and `schedules` start at `ask`. `shell_run` is in `executes` and its spec default is `ask`. MCP grants live in `mcp_grants`, bound to `schema_hash`. No grant means `ask`. An `on` grant decays to `ask` when the hash changes, and a drifted tool is not offered. Rules are one global allow, ask, and deny list. Deny sets a refusal. Hardline shell subjects are refusals, and a rule or a card cannot lift them. Shell evaluation sees nested command substitution, asks on an opaque line, and asks when a path is outside workspace roots. Saved card rules require a pattern, reject a blanket `*`, and cap at 5. Session grants are in memory for the exact pending keys and clear on process restart. The third identical executed call becomes a forced doom-loop card. Taint forces `external`, `network`, `schedules`, prompt-write tools, and a networked sandbox back to a forced ask. Writes outside granted folders, or inside a granted non-desk folder after untrusted content, set `fs_needs_ask` and force the card. Google writes through `google.py` are re-read and labeled `verified`, `unverified`, or `mismatch`. Anything but `verified` is a tool error that tells the model not to retry. Desk cards park after **180 seconds** when nobody is watching. Interactive chats wait with no auto-deny timer. `propose_plan` and `desk_ask` stay cards.

Skip-permissions is already in the working tree: a composer control, a Settings checkbox, and a context-drawer hint. If the conversation stores `skipPermissions`, that boolean wins. Otherwise the global setting applies, default false. The chat loop clears the flag for `job` and `scheduled` runs. `lift_permission_ask` then turns a remaining `ask` into `on` except for `propose_plan` and `desk_ask`, and it does not consult `forced`. The lift therefore runs ordinary asks, doom-loop cards, taint-forced asks, desk “ask as it goes” cards, outside-folder file cards, and ask-rule asks. A `run_python` bridge returns approved immediately when skip is on. Settings copy says jobs keep their own skip setting. The loop clears the flag. Code on disk is the behavior to trust. `unattendedApprovals` defaults to `ask`. The `deny` value records a denial and refuses a call that would still ask. The app inventory does not say what the default `ask` value does with a card on a job. Claude Code’s `bypassPermissions` still prompts for explicit ask rules, tools marked as requiring user interaction, and critical-path removals, and a non-interactive bypass denies calls that would still have prompted ([permission modes](https://code.claude.com/docs/en/permission-modes)). `dontAsk` runs only pre-approved tools and auto-denies the rest ([permission modes](https://code.claude.com/docs/en/permission-modes)). Codex’s non-interactive read-only combination is a read-only sandbox plus an approval policy of `never`, and `never` leaves the sandbox in force ([Agent approvals & security](https://developers.openai.com/codex/agent-approvals-security)). Grain’s MCP path never calls `resolve`, so a global deny cannot name an MCP slug. Mail and calendar subjects are the bare tool name, so a durable allow cannot name a recipient or a calendar even though `gmail_send` already compares To addresses on read-back. A `Read` deny is a different subject from `Edit`. Rules have no project or chat scope, while tool modes and MCP grants do.

Deny-before-allow, hardline refusals, schema-hash grant decay, Google read-back, desk parking, the chat wait with no 600-second auto-deny, argument rules for shell and paths, and the skip control itself are already in the tree. The close fences the lift. It does not add a second bypass, and it does not let jobs inherit skip. A classifier inside a sandbox is a later review step, after deny, hardline, taint, and folder gates, and a deny or a forced ask never goes to it. Cursor’s own page says classifier instructions are not a guarantee ([Run Modes](https://cursor.com/docs/agent/security/run-modes)). Host-level network deny lists and a wider protected-path set wait on a re-read of the sandbox profile and `mac.allowed_path`, which this inventory did not re-audit. Session grants stay ephemeral.

## Voice and pins miss the promise on the Memory screen

After a successful, non-tainted, non-proposal-only reply, and only when global and chat `autoLearn` are both on, `LearnWorker` runs one extraction and writes `memories` with an FTS5 mirror, provenance, and kinds `fact`, `preference`, `goal`, and `note`. Exact duplicate text in the same scope returns the existing live row. A project chat sees that project plus personal rows. A personal chat sees personal rows only. Injection is a capped list under `## What you remember about the user`, marked as notes rather than instructions. With a query vector, that list is the hybrid top 40: FTS5 BM25, brute-force cosine, recency, and graph-label seeds, fused in-process. The same extraction upserts graph nodes and edges. Identity is the exact label inside a scope. Injection, when `useGraph` is on, seeds labels from the user message, keeps one hop, and caps nodes at 30. Voice is a separate store: verbatim samples and one profile per scope. The profile markdown is appended to the stable system prefix whenever the chat’s Writing style toggle is on and the profile is enabled and non-empty. Extractor updates supersede memories and invalidate contradicted edges. User Forget is 30-day trash. Show history walks the supersession chain. Tidy-up proposals never apply themselves. Pinned rows are skipped by extractor updates.

The Memory panel calls a pin “always in context.” Hybrid search replaces the candidate list with the top 40, and the recency weight is 0.5, so a pinned row with no lexical, vector, or graph support can miss the cut. Letta’s labeled blocks are prepended up to a character limit, so a fact in the block cannot fall out of a ranker ([memory blocks](https://docs.letta.com/guides/core-concepts/memory/memory-blocks)). Once a relevant item is in the prompt, failure to use it stays about **4–8%**, while BM25 retrieval failure on raw chunks in the same study is **35.3%** ([memory-probe](https://arxiv.org/html/2603.02473v1)). The voice block is sent on ordinary replies, not only when the user is drafting, and `STYLE_FOOTER` (“do not imitate this when speaking to the user”) is a paragraph inside that same block. The block sits in the stable prefix, so one drafting turn can leave the voice on the cached prefix. `build_context` does not read taint, while the drawer says the writing voice stays off on a tainted chat. `useMemory` gates injection and does not gate extraction, so a chat with memory off still writes rows that other chats can see. Claude’s current memory-off control neither reads nor writes ([chat search and memory](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)). Relative dates are a prompt instruction plus a tidy proposal for auto rows older than 30 days. Edge column `fact` is unused by extraction. `valid_at` defaults to insert time. The graph screen hides invalidated edges even though `GET /graph` already accepts `include_invalid=true`. A Graphiti operator found **771 of 1,384** edges stamped at midnight UTC on the processing day because the model guessed “today”; the proposed fix is to default `valid_at` to the episode time when the model leaves it empty ([issue 1492](https://github.com/getzep/graphiti/issues/1492)). Hand edits overwrite content and append no history row. `save_memory` stores no conversation provenance.

Hybrid retrieval, supersession, approve-only tidy-up, the sample-and-profile voice store, and 1-hop graph injection are already in the working tree. Stay on this SQLite file. Leave proposals approve-only. Leave personal rows in project chats as the default the panel already states. An opt-in wall is a flag, `include_global=false`, plus a refusal of personal writes from that chat. Sensitive-topic filtering, a synthesized profile that replaces the row list, graph communities, a second transcript store, an LLM reranker on every query, and another vector database stay out. Author-reported LOCOMO scores are not a build target. The 2026 probe found that write strategy moved judge accuracy about **3–8** points inside one retriever, while retrievers moved it about **14–23** points, and raw chunks won under cosine and under that paper’s hybrid ([memory-probe](https://arxiv.org/html/2603.02473v1)). That hybrid is cosine plus BM25 then a GPT-class rerank, which is a different fusion from Grain’s in-process RRF.

## Hybrid excerpts ship, and two tools still see every note

Uploads up to **20 MB** are stored, deduplicated by SHA-256 inside a project or inside personal notes, and parsed off the request thread. Structured extraction covers PDF, DOCX, xlsx, pptx, OpenDocument, EPUB, RTF, CSV, and a long text-extension list. OCR of a sparse PDF runs only when `pdftoppm` and `tesseract` are on `PATH`, and only for the first 15 pages. Whether those binaries are installed was not checked. Searchable text stops at **400,000 characters** and PDFs at **80 pages**. Chunks are structure-aware: **1,200 characters**, peers under 300 merge, overlap 120, heading path prefixed. Uploads and notes have separate FTS5 tables and separate embedding tables. One retriever fuses them with reciprocal rank fusion, **k = 60**, equal weights, and keeps a BM25 hit whose cosine is below 0.25. At most 3 chunks per document. With documents enabled, a normal reply injects the **top 6** fused chunks as fenced excerpts. The prompt header includes heading and, for a file, page. The recorded preview keeps **400 characters**. The open page is a second injection, clipped at 4,000 characters in the client and 6,000 on the server, including unsaved editor text. Tools can search, page an upload, and read a note by line range. A note is one markdown string, with preview, KaTeX, wikilinks, an outline, templates, a daily note titled `YYYY-MM-DD`, per-save history, and proposed diffs. `doc_edit` starts as a pending revision. Default `docEditMode` is `review`. Accept all applies in the same turn, except a scheduled proposal-only run, which stays pending. Creating a note writes immediately.

`doc_search` and `doc_list` call `Docs.search` and `Docs.list` with `project_id="__all__"`. Automatic excerpts and `search_documents` already limit a project chat to that project plus personal notes. Claude’s project knowledge stays in the project ([What are projects?](https://support.claude.com/en/articles/9517075-what-are-projects)). The context drawer shows the file name, “chunk N”, and the 400-character preview. `ContextUsed` does not declare heading, page, or source, and the reply has no citation marker. Gemini’s help says answers are grounded in the uploaded sources with in-line citations ([Learn about Gemini Notebook](https://support.google.com/notebooklm/answer/16164461?hl=en)). A short source is cited as the whole document ([FAQ](https://support.google.com/notebooklm/answer/16269187?hl=en)). Claude’s API, when citations are enabled, cites the whole returned block ([Search results](https://platform.claude.com/docs/en/build-with-claude/search-results)). Click-to-scroll is reported by a university article and an unofficial gist, and it is absent from the FAQ that was fetched, so the close scrolls extracted text or the note. It does not wait on a PDF renderer. Small libraries are always chopped into six chunks. Claude turns retrieval on when project knowledge approaches the window and can switch back to loading the project in context, with an indicator ([RAG for projects](https://support.claude.com/en/articles/11473015-retrieval-augmented-generation-rag-for-projects)). The “up to 10x” and “consistent quality” lines on that page have no published eval. Use a character budget in settings, because the extractor and the page clip are already in characters. `GET /documents/index-status` exists and the renderer never calls it. There is no per-document pin and no line-level exact or regex grep. FTS drops terms shorter than 3 characters.

Hybrid fusion, heading-path chunks, note chunks in ordinary chat, reindex that re-extracts when the file is still on disk, and proposed diffs are already in the tree. Leave the ranker alone. A 2026 SQLite hybrid system lost NDCG and added **560–2100 ms** with small web-trained cross-encoders ([vstash](https://arxiv.org/pdf/2604.15484)). A 2024 reranker and a TREC 2025 LLM window helped on their own setups. They are not the next build on this file. Neighbor expansion in that 2026 paper added **2.64×** text and reported no quality change. An LLM situating paragraph, query splitting, hypothetical-document embeddings, a vector extension, and a refuse-outside-sources mode stay out. One markdown string stays the note model.

## Today already has the morning, and the cards leave it off

Today is a greeting, the local long date, a quick-ask box, and toggleable cards. A missing `homeWidgets` key means the card is on. Defaults turn off the cowork and meetings cards. The card order runs from Agent inbox and Cowork desks through Daily recap, the next 48 hours of calendar, todos, health, unread mail, Google Tasks, Drive, upcoming meetings, projects, recently learned memories, and recent chats. `GET /dashboard` degrades per source into `errors`. Module `today()` must not call Google. **Brief me** opens a new chat and sends a fixed prompt: calendar today and tomorrow, unread mail for replies, open todos with overdue ones flagged, then the three things to do first. A seeded job, “Morning brief,” uses nearly the same prompt on cron `30 7 * * *`, with a read-only allowlist, and is created disabled. Daily recap is one cached markdown note per date, under 180 words, empty if there is no API key. Native todos have date-only `due`, priority, `repeat` JSON, `estimate_min`, and a calendar mirror. ## Conclusion

The stale status pages will send a builder back through resume, compaction, hybrid search, proposed document diffs, recurring todos, the outbox, and the proposal inbox. Those are in the working tree. The 2026 gap is the residual on paths that already run: a skip that undoes a forced ask, a history query that drops the tool trace, a toggle that does not govern the write it labels, a project wall the index honors and two tools ignore, an enhanced note that accepts itself, and a scheduler that can mark a slot fired and then die. Tightening those labels is what makes a later fork, a later folder trigger, and a later live chart trustworthy. A cloud worker, a classifier as the unattended default, a second code kernel, and a research mode that searches the web in a loop are different products, and they wait until a deny still refuses, a send still waits, and the next turn can still see what the last turn already fetched.
