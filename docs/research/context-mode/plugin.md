## What problem does it claim to solve, and what is the actual mechanism?

### Takeaway
It claims to keep large tool output out of the model context by sandboxing work in an MCP server and searching a local FTS5 store. It is not a transparent proxy in front of every tool. Raw bytes stay out only when the model calls `ctx_*` tools, or when a PreToolUse hook denies or rewrites a call before it runs. On Cursor, PostToolUse cannot rewrite tool output (`canModifyOutput: false`).

### Cited Findings
- README problem statement: every MCP tool call dumps raw data into context; compaction then drops files, tasks, and the last request; the model also spends output tokens on filler. Four stated remedies: (1) Context Saving via sandbox tools, (2) Session Continuity in SQLite with FTS5/BM25 retrieval after compact, (3) “Think in Code” — the model writes a script and only stdout enters context, (4) no prose-style enforcement of how the final answer is written. — [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- README mechanism: “Each `ctx_execute` call spawns an isolated subprocess with its own process boundary… The subprocess runs your code, captures stdout, and only that stdout enters the conversation context.” Twelve runtimes: JavaScript, TypeScript, Python, Shell, Ruby, Go, Rust, PHP, Perl, R, Elixir, C#. “When output exceeds 5 KB and an `intent` is provided, Context Mode switches to intent-driven filtering.” — [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- Same README, later and more precise than the marketing line “intercepts large tool output”: hooks “can block dangerous commands and redirect them to the sandbox before execution. Instruction files guide the model via prompt instructions but cannot block anything.” Without hooks, claimed savings fall from “~98%” to “~60%”. Those percentages are the project’s own compliance estimates. — [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- `hooks/cursor/pretooluse.mjs` reads stdin JSON, calls `routePreToolUse(tool, toolInput, projectDir, "cursor", sessionId)`, and writes `formatDecision("cursor", decision)`. It does not read `tool_output`. — [hooks/cursor/pretooluse.mjs](https://github.com/mksglu/context-mode/blob/main/hooks/cursor/pretooluse.mjs)
- `routePreToolUse` in `hooks/core/routing.mjs`:
  - Bash `curl`/`wget` that would print to stdout: `action: "modify"` replaces `command` with an `echo` telling the model to call `ctx_execute` or `ctx_fetch_and_index`. The original command does not run. File-output silent curls are allowed through.
  - Inline HTTP (`fetch(`, `requests.get/post/put`, `http.get/request`) and build tools (`gradle`, `mvn`, `sbt`, wrappers): same pattern, command replaced with an `echo` redirect.
  - `WebFetch` (and Cursor aliases `mcp_web_fetch`, `mcp_fetch_tool`): `action: "deny"` with a reason pointing at `ctx_fetch_and_index` / `ctx_execute`.
  - `Read`: does not deny. Files larger than 50,000 bytes attach guidance plus `redirectMeta` for byte accounting. Smaller reads get one-shot guidance.
  - `Grep`: one-shot guidance, not a block.
  - Other Bash: one-shot guidance unless the command is “structurally bounded” (`pwd`, `whoami`, `git status`, `--version`, and similar). Optional `CONTEXT_MODE_BASH_NUDGE_MIN_COMMAND_BYTES` (default 0) can skip the nudge for short commands.
  - External MCP tools: “We don't deny or modify — the agent still needs the tool's output; we just nudge it to pipe large results through ctx_execute.” Cadence `CONTEXT_MODE_EXTERNAL_MCP_NUDGE_EVERY`, default 10, range [1, 100]. Comment cites Slack/Telegram/gdrive/Notion-style MCP names and Jira.
  - Unknown tools: `return null` (pass through).
  - `mcpRedirect` returns `null` (original call proceeds) when MCP tools are unavailable or MCP is not ready. Security-module load failure is fail-open unless `CONTEXT_MODE_REQUIRE_SECURITY=1`, which then denies every PreToolUse. — [hooks/core/routing.mjs](https://github.com/mksglu/context-mode/blob/main/hooks/core/routing.mjs)
- Cursor adapter capabilities: `preToolUse: true`, `postToolUse: true`, `preCompact: false`, `sessionStart: true`, `canModifyArgs: true`, `canModifyOutput: false`, `canInjectSessionContext: true`. PreToolUse responses: deny → `{ permission: "deny", user_message }`; modify → `{ updated_input }`; context → `{ agent_message }`; ask → `{ permission: "ask", user_message }`. PostToolUse response is `{ additional_context }` only. — [src/adapters/cursor/index.ts](https://github.com/mksglu/context-mode/blob/main/src/adapters/cursor/index.ts)
- README Cursor limitation: “Cursor accepts `additional_context` in hook responses but does not surface it to the model (forum #155689). Routing relies on the `.mdc` rules file instead of hook context injection.” — [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- Marketing page says the plugin “sits between your agent and its tools” and “Raw data never touches context.” That overstates the hook path: native Read/Grep/external MCP results still run unless the model switches tools. — [context-saving](https://context-mode.com/context-saving)
- Marketing “Zero network access / No data sent anywhere / Fully air-gapped” is contradicted by the tool surface: `ctx_fetch_and_index` fetches URLs, `ctx_execute` is annotated `openWorldHint: true` (“full network access”), `ctx_insight` opens `https://context-mode.com/insight`, and `ctx_upgrade` upgrades from GitHub. — [context-saving](https://context-mode.com/context-saving); [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)
- Marketing “No compiled blobs” is contradicted by committed `server.bundle.mjs` (674,733 bytes) and `cli.bundle.mjs` (742,765 bytes) on `main`. — [repo root listing](https://github.com/mksglu/context-mode)
- README security section, after the sandbox claim: “`ctx_execute` and `ctx_batch_execute` run arbitrary code and still inherit the process's filesystem access, so the boundary guard is a defense-in-depth layer for the file-read tool, not a full OS sandbox.” `ctx_execute_file` refuses paths that resolve outside the project root unless a Claude-style `permissions.allow` `Read(...)` rule allows them. Settings are read from `.claude/settings.json` / `~/.claude/settings.json` on every platform. — [README](https://github.com/mksglu/context-mode/blob/main/README.md)

### Inferences
- Adoption as a drop-in filter in front of Grain’s own calendar/email/doc tools will not happen by installing the plugin. Those results enter the model unless Grain calls `ctx_index` / `ctx_execute` / `ctx_fetch_and_index` itself, or a host hook matcher names Grain’s tools and the routing table is extended. The stock router only hard-stops shell HTTP, build logs, and WebFetch.
- On Cursor, the reliable interception is PreToolUse deny/modify (curl, WebFetch). Guidance that depends on `additional_context` / `agent_message` is documented by the project as not reaching the model. Large `Read` still executes.

## What tools does the MCP server expose, and how does search work?

### Takeaway
Eleven tools are registered in `src/server.ts`: six data tools (`ctx_execute`, `ctx_execute_file`, `ctx_batch_execute`, `ctx_index`, `ctx_search`, `ctx_fetch_and_index`) and five meta tools (`ctx_stats`, `ctx_doctor`, `ctx_upgrade`, `ctx_purge`, `ctx_insight`). Search is SQLite FTS5 only: Porter BM25 plus a trigram FTS5 table, merged with reciprocal rank fusion, then proximity rerank and Levenshtein fuzzy retry. No embeddings in `src/store.ts`.

### Cited Findings
- Registrations and annotations from `server.registerTool` in `src/server.ts`:
  - `ctx_execute` — title “Run code in a sandbox (executes the supplied code)”. Annotations: `readOnlyHint: false`, `destructiveHint: true`, `idempotentHint: false`, `openWorldHint: true`. Parameters: `language` enum `javascript|typescript|python|shell|ruby|go|rust|php|perl|r|elixir|csharp` (required); `code` string (required); `timeout` optional number, milliseconds, omitted means no server-side timer; `background` optional boolean, default false; `cwd` optional string (shell only; other languages run from a sandbox temp dir); `intent` optional string.
  - `ctx_execute_file` — title in source comments as executing code over a file. Parameters: `path`, `language` (same enum), `code`, `timeout` optional, `intent` optional. Code sees the file as `FILE_CONTENT` (`file_content` in Elixir).
  - `ctx_index` — title “Index Content”. Parameters: `content` optional string, `path` optional file or directory, `source` optional label; directory-only: `include` string[], `exclude` string[], `maxDepth` int default 5, `maxFiles` int default 200, `extensions` string[], `respectGitignore` boolean default true, `followSymlinks` boolean default false. “Provide this OR path, not both” for content vs path.
  - `ctx_search` — title “Search Indexed Content”. Annotations: `readOnlyHint: true`, `destructiveHint: false`, `idempotentHint: true`, `openWorldHint: false`. Schema is `buildCtxSearchInputSchema`. Always: `queries` string[] (a bare string is coerced to a one-element array); `limit` number default 3; `source` optional partial match; `contentType` enum `code|prose`; `sort` enum `relevance` (default) or `timeline`. Field `project` exists only when `CONTEXT_MODE_PROJECT_DIR` is set at process start (`CTX_SEARCH_SHARED_MODE`). Values: omit = this project, `"global"` = no project filter, any other string = that project directory.
  - `ctx_fetch_and_index` — title “Fetch & Index URL(s)”. `openWorldHint` implied by the annotation comment “fetches external URLs”. Parameters: `url` optional; `source` optional; `requests` optional array of `{url, source?}`; `concurrency` int 1–8 default 1; `force` optional boolean; `ttl` optional int milliseconds, `0` bypasses cache.
  - `ctx_batch_execute` — title “Batch Execute & Search”. Parameters: `commands` array of `{label, command}` min 1; `queries` string[] min 1; `timeout` optional; `concurrency` 1–8 default 1; `cwd` optional; `query_scope` enum `batch` (default) or `global`.
  - `ctx_stats`, `ctx_doctor`, `ctx_upgrade`, `ctx_insight`: `inputSchema: z.object({})`. `ctx_insight` opens `https://context-mode.com/insight` via the local browser.
  - `ctx_purge`: `confirm` boolean required (“MUST be true”); `sessionId` optional; `scope` enum `session|project` optional. `session` requires `sessionId`. `project` wipes FTS5 plus every session plus stats. — [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts); [src/search/ctx-search-schema.ts](https://github.com/mksglu/context-mode/blob/main/src/search/ctx-search-schema.ts)
- `ctx_search` description in source (what it returns): “Per-query ranked sections with window-extracted snippets.” Empty index and `sort !== "timeline"` returns an error text telling the caller to index first, `isError: true`. `sort: "relevance"` is described as current session only; `sort: "timeline"` is chronological across current session, prior sessions, and auto-memory. Source labels named in the description: `decision`, `error`, `error-resolution`, `blocker`, `plan`, `user-prompt`, `rejected-approach`, `compaction`. — [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)
- Search implementation: two FTS5 tables. `chunks` uses `tokenize='porter unicode61'`. `chunks_trigram` uses `tokenize='trigram'`. Queries use `bm25(chunks, 5.0, 1.0)` — title weight 5, content weight 1, matching the README “titles and headings are weighted 5x”. README also describes RRF merge, proximity rerank for multi-term queries, and Levenshtein correction (“kuberntes” → “kubernetes”). `src/store.ts` has no `embed` references. — [src/store.ts](https://github.com/mksglu/context-mode/blob/main/src/store.ts); [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- `SearchResult` fields: `title`, `content`, `source`, `rank`, `contentType` `"code" | "prose"`, optional `matchLayer` `"porter" | "trigram" | "fuzzy" | "rrf" | "rrf-fuzzy"`, optional `highlighted`, `timestamp`, `sessionId`. — [src/types.ts](https://github.com/mksglu/context-mode/blob/main/src/types.ts)
- Throttle constants in `src/server.ts`: `CONTEXT_MODE_SEARCH_WINDOW_MS` default `60_000`; `CONTEXT_MODE_SEARCH_MAX_RESULTS_AFTER` default `3` (comment: “after N calls: 1 result per query”); `CONTEXT_MODE_SEARCH_BLOCK_AFTER` default `8` (comment: “after N calls: refuse, demand batching”). README table says calls 1–3 return 2 results per query, 4–8 return 1, and 9+ block. The schema default `limit` is 3, not 2. Prefer the constants over the README table. — [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts); [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- CLI equivalents documented in the README: `context-mode doctor`, `context-mode index . --source project:my-app`, `context-mode search "authentication middleware" --source project:my-app`, `context-mode upgrade`, `context-mode insight`. Claude Code also has slash commands `/context-mode:ctx-stats` and siblings. Other clients are told to type `ctx stats` so the model calls the MCP tool. — [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- README tool table omits `ctx_insight`. The install section and `registerTool` include it. The table’s “11 MCP tools” count matches the source (6 + 5), not the 10-row table. — [README](https://github.com/mksglu/context-mode/blob/main/README.md)

## Where is data stored, what is the schema, what is retention, and can another app read it?

### Takeaway
State is plain SQLite on disk under a per-client directory. For Cursor that is `~/.cursor/context-mode/sessions/` and `~/.cursor/context-mode/content/<project-hash>.db`, overridable with `CONTEXT_MODE_DIR`. There is no encryption in the schema. Any local process can open the files. Content DBs older than 14 days are deleted on MCP server startup. Session rows have a 7-day cleanup method. A legacy `~/.context-mode/content` directory is wiped immediately if it still exists.

### Cited Findings
- `CONTEXT_MODE_DIR` (`STORAGE_ROOT_ENV` in `src/session/db.ts`): absolute path required; `~` is not expanded; empty values are ignored. When set, sessions and stats use `<root>/sessions` and indexed content uses `<root>/content`. README documents the same variable, “Since v1.0.147”, and says `~` is not expanded. — [src/session/db.ts](https://github.com/mksglu/context-mode/blob/main/src/session/db.ts); [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- Default root is the platform config dir plus `context-mode`. `getSessionDirSegments("cursor")` returns `[".cursor"]`. `resolveDefaultSessionDir` joins that config dir with `"context-mode"/"sessions"`. `getStorePath()` uses `resolveContentStorageDir` and then `resolveContentStorePath`, filename `${hashProjectDirCanonical(projectDir)}.db`. So the Cursor default content DB is `~/.cursor/context-mode/content/<hash>.db` plus `-wal`/`-shm`. Session DB is `~/.cursor/context-mode/sessions/<hash>.db`. — [src/adapters/detect.ts](https://github.com/mksglu/context-mode/blob/main/src/adapters/detect.ts); [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts); [src/session/db.ts](https://github.com/mksglu/context-mode/blob/main/src/session/db.ts)
- Other defaults from the same switch: `.claude`, `.gemini` (also antigravity), `.openclaw`, `.codex`, `.vscode`, `.copilot`, `.kiro`, `.pi`, `.omp`, `.qwen`, `.kimi-code`, `.config/kilo`, `.config/opencode`, `.config/zed`, `.config/JetBrains`. README separately says OMP storage is rooted at `~/.omp/context-mode/` so it does not share with Pi. — [src/adapters/detect.ts](https://github.com/mksglu/context-mode/blob/main/src/adapters/detect.ts); [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- A second override, `CONTEXT_MODE_DATA_DIR`, is documented in `src/adapters/base.ts` (issue #649) as a universal override for `getSessionDir` / `getMemoryDir` only, not for the host’s own config files. — [src/adapters/base.ts](https://github.com/mksglu/context-mode/blob/main/src/adapters/base.ts)
- Startup cleanup in `getStore()`: `cleanupStaleContentDBs(contentDir, 14)` and `_store.cleanupStaleSources(14)`. If `~/.context-mode/content` exists, `cleanupStaleContentDBs(legacyDir, 0)` deletes those legacy DBs immediately. README’s “Indexed content persists in a per-project SQLite database at `~/.context-mode/content/`” describes this legacy path, not the current per-platform path. — [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)
- `SessionDB.cleanupOldSessions(maxAgeDays = 7)` deletes sessions older than that many days. README also says: “If you don't `--continue`, previous session data is deleted immediately — a fresh session means a clean slate.” That immediate-delete behavior was not re-read in the session-start hook in this pass; the 7-day method is what is in `session/db.ts`. — [src/session/db.ts](https://github.com/mksglu/context-mode/blob/main/src/session/db.ts); [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- Content schema (`src/store.ts`):
  - `sources(id INTEGER PRIMARY KEY AUTOINCREMENT, label TEXT NOT NULL, chunk_count INTEGER NOT NULL DEFAULT 0, code_chunk_count INTEGER NOT NULL DEFAULT 0, indexed_at TEXT NOT NULL DEFAULT (datetime('now')), file_path TEXT, content_hash TEXT)` plus index `idx_sources_label`.
  - FTS5 `chunks(title, content, source_id UNINDEXED, content_type UNINDEXED, source_category UNINDEXED, session_id UNINDEXED, event_id UNINDEXED, timestamp UNINDEXED, tokenize='porter unicode61')`.
  - FTS5 `chunks_trigram` with the same columns, `tokenize='trigram'`.
  - `vocabulary(word TEXT PRIMARY KEY)`.
  - Chunk cap `MAX_CHUNK_BYTES = 4096`. File-backed sources store SHA-256 `content_hash` and are refreshed when the file changes. — [src/store.ts](https://github.com/mksglu/context-mode/blob/main/src/store.ts)
- Session schema (`src/session/db.ts`), partial columns captured from the CREATE statements: `session_events(id, session_id, type, category, priority INTEGER DEFAULT 2, data TEXT, project_dir, attribution_source, attribution_confidence REAL, bytes_avoided, bytes_returned, source_hook, …)`; `session_meta(session_id PRIMARY KEY, project_dir, started_at, last_event_at, event_count, compact_count)`; `session_resume(id, session_id UNIQUE, snapshot TEXT, event_count, created_at, …)`; `tool_calls(session_id, tool, calls, bytes_returned, updated_at, PRIMARY KEY (session_id, tool))`. — [src/session/db.ts](https://github.com/mksglu/context-mode/blob/main/src/session/db.ts)
- `ctx_fetch_and_index` cache: README default TTL 24 hours; `ttl` is milliseconds in the schema; `ttl: 0` or `force: true` bypasses. ## What is saved versus what still enters the model context?

### Takeaway
`ctx_execute` returns full stdout whenever it is at most 100 KB and either no `intent` was passed or the output is at most 5,000 bytes. Above 100 KB the stdout is indexed and the model gets a pointer. With `intent` and output over 5,000 bytes, the model gets search snippets, not the raw stdout. Native Read/Grep/external MCP output is not stripped after the tool runs. Compaction snapshots in current source are a table of contents with `ctx_search` calls, and the old `maxBytes` budget is ignored.

### Cited Findings
- Constants: `INTENT_SEARCH_THRESHOLD = 5_000` (“bytes — ~80-100 lines”); `LARGE_OUTPUT_THRESHOLD = 102_400` (“100KB — auto-index into FTS5, return pointer”). — [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)
- Success path of `ctx_execute`: if `intent` is non-empty and stdout is bigger than 5,000 bytes, return `intentSearch(...)` and index the full stdout. Else if stdout is bigger than 102,400 bytes, `indexStdout` and return an “Indexed N sections… Use ctx_search” pointer. Else return `echo + stdout` in full. Non-zero exits: same intent rule; if output exceeds 100 KB, `intentSearch` is called with the fixed query `"errors failures exceptions"`; otherwise the classified output string is returned in full. Timeout returns stderr. — [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)
- `ctx_index` description: “The full content stays in storage — retrieve any section on-demand via ctx_search; nothing is summarized or truncated.” The tool’s own return is the index receipt, not the document. — [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)
- `ctx_fetch_and_index` description: raw page bytes stay in storage; the tool “returns a small preview window per source.” HTML is converted to markdown, JSON is chunked by key paths, plain text is indexed directly. — [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)
- `ctx_search` default `limit` 3 snippets per query, windowed around matches, not full documents. Calls after the block threshold are refused. — [src/search/ctx-search-schema.ts](https://github.com/mksglu/context-mode/blob/main/src/search/ctx-search-schema.ts); [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)
- README compaction story says a “priority-tiered XML snapshot (≤2 KB)” drops low-priority events first. `src/session/snapshot.ts` contradicts that: `maxBytes` is “KEPT for backward compat but IGNORED”, and the file header says “Zero truncation. Zero information loss… the snapshot is a table of contents.” Each section is a short summary plus a literal `ctx_search(queries: [...], source: "session-events")` hint. Caps that do exist: `MAX_ACTIVE_FILES = 10`, `RECENT_MESSAGES_LIMIT = 3`, `RECENT_MESSAGE_MAX_CHARS = 400`, query phrases trimmed to 80 characters. — [src/session/snapshot.ts](https://github.com/mksglu/context-mode/blob/main/src/session/snapshot.ts); [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- README event table (not re-derived from `extract.ts` this pass) lists what hooks persist: file read/edit/write/glob/grep, tasks, plans, rules file paths and content, user prompts, decisions, git operations, errors and error→fix pairs, constraints, blockers, rejected approaches, environment, agent findings “first 500 chars”, iteration loops, latency over 5s, MCP tool counts, subagents, skills, external refs, role, intent, and user-pasted data over 1 KB. Priorities P1–P4. — [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- curl/wget redirect records `bytesAvoided: 8192` as a fixed estimate, not the real body size. WebFetch deny uses a fixed `16384`. Read redirect uses the real `stat` size when the file is over 50,000 bytes. Those numbers are accounting, not a token budget. — [hooks/core/routing.mjs](https://github.com/mksglu/context-mode/blob/main/hooks/core/routing.mjs)
- Benchmarks in the README (Playwright 56.2 KB → 299 B, GitHub issues 58.9 KB → 1.1 KB, session 315 KB → 5.4 KB, “98%”) are the project’s own scenarios. The context-saving page adds “50% drop at 32K tokens, 11 of 12 models, NoLiMa 2025”, “15 min” re-establishing context from “Internal telemetry”, and “$60K per year for a 50-seat team” at “$100/seat/month”. Those three are marketing math, not measurements from the repo. — [README](https://github.com/mksglu/context-mode/blob/main/README.md); [context-saving](https://context-mode.com/context-saving)

### Inferences
- Anything under 100 KB that the model prints from `ctx_execute` without an `intent` still lands in context. The 98% figures assume the model prints a small summary or passes `intent`. A wrapper that wants a hard cap must pass `intent` or keep stdout under 5,000 bytes itself. The 100 KB auto-index is the only unconditional cap.
- Session continuity injected into the prompt is a map, not the events. The events stay in SQLite until the model calls `ctx_search`. On Cursor, if `sessionStart` does not fire, that map is not injected after compaction.

- The “first 500 chars” agent-finding cap and the “>1 KB pasted data” rule are README-only in this pass.
- Did not verify that hooks actually index the 26 event categories into FTS5 (`maybeIndexSessionEvents` was seen called, not read).

## What limits, failure modes, and non-indexed inputs are documented?

### Takeaway
The plugin fails open: if the MCP server is not ready, curl/wget are not rewritten; if a hook throws, Cursor hooks are written with `failClosed: false`. Directory indexing is capped and extension-filtered. Search refuses to run once the rolling window exceeds eight calls. The sandbox is not an OS sandbox.

### Cited Findings
- `mcpRedirect` no-ops when MCP is not ready, so the dangerous curl runs. `failClosed: false` on every Cursor hook entry `generateHookConfig` writes. README Copilot note: “context-mode fails open.” Default security load failure is also fail-open; `CONTEXT_MODE_REQUIRE_SECURITY=1` flips PreToolUse to deny-all until the module loads. — [hooks/core/routing.mjs](https://github.com/mksglu/context-mode/blob/main/hooks/core/routing.mjs); [src/adapters/cursor/index.ts](https://github.com/mksglu/context-mode/blob/main/src/adapters/cursor/index.ts); [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- Directory walk (`src/store-directory.ts`): default max depth 5, max files 200, followSymlinks false. Default extensions `.md .mdx .txt .json .yaml .yml .ts .tsx .js .jsx .py .rs .go .sh`. Default excludes `node_modules`, `.git`, `dist`, `build`, `.next`, `coverage`, `.venv`, `__pycache__`, `.DS_Store`, plus `.gitignore` lines. Negation (`!`) in `.gitignore` is not supported. Symlinks that resolve outside the root are skipped. `ctx_index` of a path used to refuse directories (“not a regular file”); directories are now walked under those caps. — [src/store-directory.ts](https://github.com/mksglu/context-mode/blob/main/src/store-directory.ts)
- `ctx_index` with neither `content` nor `path` throws. Empty-string `content` falls through to `path` (issue #350). — [src/store.ts](https://github.com/mksglu/context-mode/blob/main/src/store.ts)
- `ctx_search` on an empty content index returns an error for relevance sort. Timeline sort skips that guard because session memory may exist. — [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)
- Search block after 8 calls per `CONTEXT_MODE_SEARCH_WINDOW_MS` (default 60s), unless those env vars are changed. The tool description tells the model to use `ctx_batch_execute` instead. — [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)
- `ctx_fetch_and_index` URL policy, README: only `http:` and `https:`; blocks `169.254.0.0/16` including `169.254.169.254`, multicast, and similar; loopback and RFC1918 are allowed unless `CTX_FETCH_STRICT=1`. — [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- `ctx_execute_file` project-boundary refusal: absolute paths, `../`, and symlinks that escape the workspace return `File access blocked` unless `permissions.allow` contains a matching `Read(...)` rule. `ctx_execute` itself is not confined that way. — [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- FTS5 migration drops and recreates the virtual table when `source_category` is missing (old 4-column schema). That drops existing FTS rows on upgrade. — [src/store.ts](https://github.com/mksglu/context-mode/blob/main/src/store.ts)
- Cursor `Task` matcher is marked in source as a “best-guess placeholder” because Cursor has not published the sub-agent tool name. — [src/adapters/cursor/hooks.ts](https://github.com/mksglu/context-mode/blob/main/src/adapters/cursor/hooks.ts)
- Codex cannot rewrite tool input (deny only). Antigravity IDE and Zed have no hooks. Kiro has no session restore (`agentSpawn` unwired). README says OpenCode has no real SessionStart and uses `experimental.chat.system.transform` instead. — [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- Duplicate Cursor configs (plugin plus `.cursor/hooks.json`) fire each event twice. — [README](https://github.com/mksglu/context-mode/blob/main/README.md); [src/adapters/cursor/index.ts](https://github.com/mksglu/context-mode/blob/main/src/adapters/cursor/index.ts)
- `better-sqlite3` native build: prebuilds fail on old glibc (CentOS 7/8, RHEL 8, Debian 10) and need a C++20 compiler. Windows can miss the `.node` binding; a postinstall heal retries the prebuild. — [README](https://github.com/mksglu/context-mode/blob/main/README.md)

### Inferences
- PDFs, images, HTML files, mailboxes, and Office documents are outside the default directory extension list. They are indexable only if the caller passes extracted text as `content`, or fetches HTML through `ctx_fetch_and_index`.
- A Grain integration that shells out should treat hook failure and “MCP not ready” as “full tool output entered context,” not as a blocked call.

### Gaps
- Did not list binary/mime denylist inside the fetch converter. HTML→markdown uses `turndown` (`package.json` dependencies). Behavior on non-HTML bodies beyond the description “JSON chunked by key paths, plain text indexed directly” was not read.
- Did not read issue #485 / #489, only the README’s “awaiting Cursor team review” status.

## Is the design specific to coding-agent tools, or generic for arbitrary tool results?

### Takeaway
The storage and the six data tools are generic over text, files, shell output, and URLs. The automatic interception layer is specific to coding-agent tool names (shell, read, grep, web fetch, and their per-client aliases). Arbitrary MCP results such as calendar, email, or docs are not captured. The hook only periodically tells the model to wrap them in `ctx_execute`, and it does that only when the client actually runs PreToolUse.

### Cited Findings
- `ctx_index` accepts any string as `content`. `ctx_fetch_and_index` accepts any http(s) URL. `ctx_execute` runs user code in 12 languages and indexes stdout. None of those schemas mention a coding-only corpus. — [src/server.ts](https://github.com/mksglu/context-mode/blob/main/src/server.ts)
- `TOOL_ALIASES` maps shell/read/grep/webfetch names from Gemini, Antigravity CLI, Qwen, OpenCode, Codex, OpenClaw, Cursor (`Shell`, `mcp_web_fetch`, `mcp_fetch_tool`), VS Code Copilot, and Kiro. There is no calendar, mail, or docs alias. — [hooks/core/routing.mjs](https://github.com/mksglu/context-mode/blob/main/hooks/core/routing.mjs)
- External MCP branch comment: it fires for `mcp__<server>__<tool>` and Cursor `MCP:` names that are not `ctx_*`, including “slack/telegram/gdrive/notion-style MCPs”, and “We don't deny or modify”. The original payload still returns to the model. — [hooks/core/routing.mjs](https://github.com/mksglu/context-mode/blob/main/hooks/core/routing.mjs)
- Cursor source matcher includes `MCP:(?!ctx_)`, so third-party MCP tools on Cursor are at least eligible for that nudge if the generated hook config is installed. The README Option B sample matcher does not include that pattern, so a hand-copied config will not see them. — [src/adapters/cursor/hooks.ts](https://github.com/mksglu/context-mode/blob/main/src/adapters/cursor/hooks.ts); [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- Platforms without hooks (Antigravity IDE, Zed) have no programmatic interception at all. — [README](https://github.com/mksglu/context-mode/blob/main/README.md)
- Homepage and README examples are coding-shaped (`gh issue list`, grep, file reads, Playwright, access logs) but the fetch/index path is also how they tell users to pull React docs and other web pages. — [context-mode.com](https://context-mode.com/); [README](https://github.com/mksglu/context-mode/blob/main/README.md)

### Inferences
- Wrapping is the fit for Grain: spawn `context-mode` as an MCP server (or call the CLI) and pass calendar/email/doc bodies into `ctx_index` or `ctx_execute` with an `intent`, then `ctx_search`. Reimplementing only the FTS5 store is a smaller slice than reimplementing 17 hook adapters. Vendoring the TypeScript is the ELv2 path above; shelling out keeps Grain from redistributing the code but inherits Node >= 22.5, `better-sqlite3` or `node:sqlite`, and fail-open behavior.
- Do not expect the stock Cursor hooks to keep Grain tool results out of Cursor’s context. They were written for Shell/Read/Grep/WebFetch and for nudging other MCP servers, not for replacing those servers’ outputs.

### Gaps
- Did not check whether `ctx_batch_execute` command strings can call non-shell work (it is shell commands only, per the schema). A calendar API would go through `ctx_execute` code or `ctx_index` text, not through `commands[]`.
- Did not read the Platform “structural events” exporter, so it is unknown whether opting into Insight changes what stays local versus what is forwarded. The homepage says tool name, file path, and error counts, and not source, prompts, or file content. That page is marketing until the exporter is read.
